# 踩过的坑与对应护栏

来源：原文作者亲身踩的三个坑，加上本实现实测撞出来的坑。每条都对应一个可执行护栏，而不是一句建议。

## 一、原文的三个坑

### 坑 1：网页改版按钮挪位，Skill 还在点老位置，生成了一张空表，半天没发现

护栏（四层）：
1. **多策略定位**：每步存 10 种候选，从 `data-testid` 到 `xpath`，逐一降级。
2. **指纹自愈**：全部失效时按元素指纹打分兜底，命中即用并**回写进流程文件**自修复。
3. **非空校验**：`tableNotEmpty` 会剔除 `<td colspan>暂无数据</td>` 这类占位行，占位行不算数据。
4. **空结果守卫**：只要页面呈现空表/空列表/「暂无数据」字样，无论其他断言是否通过，一律判**失败**。

另外：报告里的 `healed` 数组就是「改版预警」。自愈次数上升 = 页面在变，该重新录制了。

### 坑 2：录的时候手滑点错，AI 忠实学会了错误路径

护栏：
1. **可审阅清单**：`record_stop` 返回人类可读的步骤清单，Agent 必须原文呈现给用户确认。
2. **精确修改**：`flow_step_delete` / `flow_step_update` / `flow_step_move` 支持只改那一步，不必整段重录。
3. **重复点击检测**：L061 会在录到手滑双击提交按钮时告警。

### 坑 3：录了要验证码的步骤，AI 卡住干等

护栏：
1. **录制期识别**：密码框、短信/动态码输入、验证码 iframe/组件都会被自动标记，不落明文。
2. **静态拦截**：L020/L021 直接判**阻断**，流程跑不起来，而不是跑到一半卡死。
3. **明确的人工作接管**：`humanHandoff` 步骤带恢复条件（文字出现/消失、URL 变化）与超时。
4. **无头模式早失败**：需要人工接管却在无头模式运行时，立刻报错并说明原因，不会静默等待。

## 二、实测撞出来的坑

### 坑 4：本机自带 Chromium 损坏，所有回放都启动失败

现象：`chromium-1243/chrome-win64/chrome.exe` 启动即退出（`0xC0000142`）。

护栏：**候选浏览器自愈链**——按「自带 Chromium → 系统 Edge → 系统 Chrome」逐个真启动探测，失败的写入 `.work/browser-broken.json`（7 天 TTL），后续自动跳过并改用可用者。实测已自动切换为系统 Edge，headless 与 headed 均正常。

### 坑 5：点击触发下载时冒出一个空白标签页，把「结果页」覆盖了

现象：录制结束时采集页面形态，取到了那个空白页，导致「表格非空」断言没能推断出来。

护栏：**跨页形态合并**——采集所有页面形态，行数取各页最大值，空状态命中取首个，主页面优先用于 URL/标题。

### 坑 6：只校验「文件下载了」，但下载到的是只有表头的空报表

现象：空数据的 CSV 仍有 33 字节（只有表头），`minBytes: 1` 形同虚设。

护栏：**下载数据行校验**——录制时记录真实文件的行数，自动推断出 `download { minBytes: 1, minLines: 2 }`；只有表头（1 行）判失败。

### 坑 7：点击提交后立刻执行下一步，抢跑

现象：点击触发页面跳转，下一步在旧文档上找不到元素。

护栏：**录制期自动标注 `waitForNav`**——点击引发主框架导航时，自动在该点击步骤上挂「等待加载完成」，回放时先等导航再继续。

### 坑 8：重定向链被录成一串多余的 `goto`

护栏：**导航抑制窗口**——点击引发的导航会抑制 1.5 秒内后续 `goto` 记录；录制启动期的重定向用 `booting` 标记屏蔽。

### 坑 9：网页日期每次都变，每次都要手工改

护栏：**日期自动变量化**——录完自动识别「等于今天/昨天/明天」的日期字面量（支持 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`、`YYYY.MM.DD`、`YYYY年MM月DD日`、`MM-DD`、`YYYYMMDDHHmmss` 等），替换成 `${today:...}`。

### 坑 10：单号要从 Excel 取，但环境里没有 Excel 驱动

护栏：**内置零依赖表格解析**——自实现 ZIP（stored + deflate）+ xlsx（sharedStrings/workbook/sheet）解析，支持 `.xlsx/.csv/.tsv/.txt/.json`；列可用名称、A 字母或 1 基序号指定，行支持 `0`/`n`/`*`。

### 坑 11：密码明文躺在流程 JSON 里被提交进 git

护栏：
1. 录制器**不记录敏感输入的值**（`sensitive: true` + 空值）。
2. 凭据走 `secret_set`（AES-256-GCM + 本机密钥文件），步骤里只写 `${名字}`。
3. 报告与日志统一掩码。
4. `.gitignore` 屏蔽 `.work/`、`runs/`、`logs/`、`web-rpa.config.json`（纯净发布包不带 `.` 前缀文件，装机时由 `install.mjs` 生成）。

### 坑 12：失败了自己不知道，等到用的时候才发现

护栏：**失败即告警**——企业微信/钉钉/飞书/Slack/通用 Webhook，消息含流程名、失败步骤、原因、校验明细、自愈提示、报告路径与截图数量。

## 二之二、全面测试阶段又揪出来的坑

### 坑 13：纯 CSS 的 `:hover` 揭层，用"悬停前后可见数量对比"根本测不出来

现象：想通过"悬停后容器里可见元素变多了"来识别菜单，实测 `before=36, after=36` 完全相等。

原因：**`:hover` 生效在 `mouseover` 回调之前**——回调运行时菜单已经展开了，拿到的"前"就是"后"。

另一个更隐蔽的变体：如果"空闲态快照"在悬停期间被重采（实测 35 → 37），已展开的菜单会被当成空闲态，
于是真正需要 hover 的元素被误判为普通元素，hover 步骤被漏掉，回放时点不着。

护栏：**空闲态基线只在文档就绪时采一次，此后再不自动刷新**；
判定需要 hover 的条件是"元素自身与其某个祖先容器都不在基线里"（即一整块被揭开，而不是单个新元素）；
补的 hover 必须落在与被揭容器"近邻"（同级/父子/爷孙）的最近悬停元素上。
并提供 `window.__rpa.hoverDecision()` 诊断钩子与 `rebaselineHover()` 手工重建。

### 坑 14：浏览器内置页混进流程，回放跑到空白页

现象：点击导出后 Edge 弹出一个 `edge://downloads-hub/` 标签页，被当成新标签页记成了第 8 步
`打开网址 edge://downloads-hub/`；回放时这一步把页面从报表页带走，表格断言随之失败。

护栏：**只录真正的网页**（`http(s):` / `file:`），`edge://`、`chrome://`、`about:`、`devtools://` 一律忽略；
另外新增静态检查 **L002**，万一流程里混进这类地址会**阻断执行**而不只是警告。

### 坑 15：iframe 里的元素，主页断言"看不见"

现象：iframe 内按钮点击成功、页面文字确实变成"内层已点击"，
但 `textPresent` 断言报"匹配 0 处"——因为 `page.getByText` 不穿透 iframe。

护栏：`textPresent` / `textAbsent` 默认**扫描主页 + 所有子框架**；
`tableNotEmpty` / `listNotEmpty` 跨框架统计真实数据行；断言可用 `frame` 链限定范围。

### 坑 16：凭据虽然加密存储，却从报告里"漏"出去

现象：参数用 `source: "secret:xxx"` 且带 `secret: true`，但 `${tok}` 被解析进步骤 URL 后，
`report.steps[].label`（"打开网址 ...token=真实凭据..."）和 `report.error` 里都是明文。

护栏：报告落盘前做**整体脱敏**——所有敏感参数的真实值（含 URL 编码形式）在报告任意字符串里替换成 `***`，
且在发送告警之前完成，保证日志、报告、告警三处都不含明文。

### 坑 17：串联时取不到上一步的值

现象：`source: "flow:前一个流程:orderNo"` 报"缺少必填参数"。
原因：写入侧存的是 `chainOut[flowId].extracted.orderNo`，读取侧却按 `chainOut[flowId].orderNo` 取，少了一层。

护栏：读取侧两种结构都支持（有 `extracted` 就取 `extracted[key]`，否则取顶层），
并对 `chain_run` 与流程内 `chain` 步骤都加了端到端测试。

### 坑 18：录复选框时多出一次无意义的点击

现象：点一下复选框会同时产生 `click` 和 `change`，于是录出"点击 agree → 勾选 agree"两步。

护栏：当 `check`/`select` 紧跟在同一元素的 `click` 之后时，**用语义更明确的 change 步骤替换掉那次 click**。

## 二之三、无人值守阶段暴露的坑

### 坑 19：hover 基线"等用户还没交互再采"，在自动化里几乎永远采不到

现象：隔离测试能录到 hover，放进集成测试就偶尔录不到 —— 表现为"有时缺一步 hover，回放点不着"。

原因：空闲态基线的采集条件是"还没有任何 mouseover"。而自动化里第一个动作
（`selectOption`/`check` 都会真的移动鼠标）很快就产生 mouseover，
于是基线一直没采到（`idleSigs` 为 null），**hover 检测被静默关闭**——不报错，只是那一步没了。

护栏：改为**交互开始前持续采样、取最新一次**（交互前 DOM 越完整越好），
**第一次 mouseover 起立即冻结**；这样既不会漏采，也绝不会把悬停揭出来的菜单误当成空闲态。

### 坑 20：留存策略写成"次数与天龄同时满足"，结果只设次数时永不清理

现象：`pruneRuns({ keepCount: 1, keepDays: 0 })` 一条都不删，留存形同虚设。

原因：删除条件写成 `超出次数 && 超过天龄`，而"天龄 0"被当成"不判断天龄"，于是 AND 永远为假。

护栏：把三种组合写成**明确规则**并逐一测试：
只设次数→保留最新 N 次其余全删；只设天龄→保留 N 天内其余全删；
两者都设→保留最新 N 次，超出部分还需超过 N 天才删；都不设→不清理。

### 坑 21：confirm 被静默取消，流程却"跑成功了"

现象：点击提交 → 浏览器 confirm → Playwright 默认自动 dismiss →
页面走了"取消"分支，**业务根本没提交**，但流程一路无错、断言也可能通过。

护栏：录制期把弹窗挂到触发它的那次 click 上（`expectDialog`）并按业务意图接受；
回放期**没有被流程处理的弹窗直接判失败**（`noUnexpectedDialog`），
提醒人"这里出现了没预期的弹窗，操作很可能没生效"；允许 `run.strictDialogs=false` 降级为提示。

### 坑 22：定时任务与手工一键撞车，同一流程跑了两遍

后果：提交类流程会把业务数据提交两次（比"跑失败"严重得多）。

护栏：**带 pid 的并发锁**——同一流程第二次触发直接跳过并说明"正在执行中（pid/开始时间/触发方式）"；
锁随进程结束释放，进程被强杀留下的锁超过 6 小时或进程已不存在时判定过期并自动清理；
另有 `lock_status` / `lock_release` 用于人工排查与恢复。

### 坑 23：被强杀/断电后"什么都没留下"，看起来像"定时根本没到点"

现象：历史里既没有失败记录也没有成功记录，无法区分"没执行"和"执行到一半被打断"。

护栏：每次执行开始先写 `running.json`（含 pid 与触发方式），正常收尾删除；
残留标记会被 `run_history` 与 `status_report` 报成 **interrupted**，并给出"业务可能只做了一半"的提示。

## 二之四、覆盖度自检阶段发现的坑

### 坑 24：L061 是永远触发不了的死代码

现象：写了"连续两次点击同一个提交按钮 → 告警"的规则，但它从来没报过。

原因：规则写在 `if (!hasWait) { ...; return; }` 之后。而"下一次点击"本身不在"等待步骤"名单里，
所以连续双击必然走进 `!hasWait` 分支并 `return`，后面的重复检测永远到不了。

护栏：把重复检测**提到前面**；更根本的是加一个**覆盖度自检**
（`node test/audit.mjs`）——逐条构造触发用例并要求每条规则都至少被触发一次，
任何"没人用过的能力"都会让自检失败。这个自检就是抓出这条死代码的工具。

### 坑 25：配置设过一次就再也改不回去

现象：为了测试把 `browser.channel` 设成 `msedge`，之后想恢复"自动选择"，写 `null` 却发现没生效。

原因：`writeConfig` 用的是 `deepMerge`，而 `deepMerge` 把 `null` 当作"没有提供"从而保留原值。

护栏：`config_set` 的补丁语义改为 **`null` = 删除该键、恢复默认**，
并且测试里用"设置 → `null` → 断言回到默认值"来锁定这个行为。

### 坑 26：逐行文本 / 标量 JSON 被当成"有表头"，第一个值被吃掉

现象：一个每行一个单号的 `.txt`，取第一行拿到的是第二行的值。

原因：`readTable` 对所有格式都默认"第一行是表头并跳过"。

护栏：`.txt` 与标量 JSON 数组按**无表头**处理（所有行都是数据）；
只有 `.xlsx/.csv/.tsv` 与 JSON 对象数组才有表头概念。已补测试覆盖全部 5 种格式。

### 坑 27：支持登录的系统却在"无人值守"时反复失败

原因：登录态在每次执行时都是全新的，第一次跑完就过期。

护栏：`profile_login` 人工登录一次写入持久化 profile，之后所有执行（含定时任务）复用；
profile 同一时间只允许一个执行占用（Playwright 不允许同一 user-data-dir 开两次），
内置全局锁并在冲突时明确报"正在被占用"；`profile_reset` 可随时清空。

## 三、使用侧的三条铁律

1. **录完必须审清单**：手滑一次的代价可能是每天产出错误结果。
2. **没有结果校验就不算做完**：跑成功 ≠ 做对了。
3. **空结果不算成功**：宁可误报，也不能静默产出空表。
