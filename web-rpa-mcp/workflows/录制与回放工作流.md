# 录制与回放工作流

> 适用：用户给出一个「每天都这么点」的网页流程，希望变成一键/定时复跑的技能。
> 核心原则：**路径不稳就不要录；录完必须先审清单；没有结果校验就不算做完。**

## 阶段 0 · 前置确认（必做，不要跳过）

向用户确认四件事，缺一件就先问：

1. **起点**：从哪个网址开始？（登录后的首页，还是登录页？）
2. **路径是否固定**：每次点击的按钮位置、菜单层级是否一致？有随机广告/弹窗吗？
3. **变量在哪**：哪些值每次不一样？日期、单号、金额、环境（TEST/PRE/UAT）？
   - 固定的 → 直接录
   - 每次变的 → 录完改成参数（日期可自动识别）
4. **结果怎么算对**：跑完看到什么才算成功？报表有数据行？出现「提交成功」？文件下载下来？

同时**明确告知用户**（这是硬约束）：

- 验证码、短信码、滑块 → 不要录，会判阻断；改用人工接管步骤
- 登录态 → 不要录（第二次跑就失效）
- 涉及资金、权限、生产库的敏感系统 → 留在人工

## 阶段 0.5 · 需要登录的系统：先建登录态

如果目标系统必须先登录，**不要**把登录过程录进流程（第二次跑就失效）。正确做法是先建登录态：

```
profile_login { url: "https://a.example.com/login", successText: "工作台" }
```

人工在弹出的浏览器里登录（扫码/短信/账密都行），检测到 `successText` 或 `successUrlContains`
就把登录态写进持久化 profile，并自动开启 `browser.persistProfile`。
之后**录制与定时执行都复用这个登录态**，流程从"登录后的页面"开始录即可。

注意：
- profile 等同凭据，不要外传；`.work/profile/` 已被安装器生成的 `.gitignore` 屏蔽
- 换人/换账号时 `profile_reset { confirm: true }` 清空重登
- 同一时间只允许一个执行用它（内置全局锁，冲突会明确报错），所以别让两个流程并行跑

## 阶段 1 · 固定路径

让用户先手工把流程走一遍，清理干扰：关掉弹窗广告、关掉每次跳出来的问卷，确认按钮每次都在同一位置。

路径不稳的处理顺序：
1. 能通过 URL 直达的页面，直接 `goto`，不要靠点菜单
2. 弹窗用「等待元素消失」步骤消化
3. 实在随机的分支，拆成两个流程，不要塞进一个

## 阶段 2 · 演示录制

```
record_start { url: "<起点网址>", name: "<技能名>" }
```

然后把话语权交给用户：

> 请在刚打开的浏览器窗口里，按你平时的流程**慢一点**操作一遍，每一步停顿半秒左右。
> 操作完告诉我，我来生成技能。

注意事项：
- **不要替用户点**（除非用户明确要求代操作）。录制的是人的真实操作路径。
- 录制中可用 `record_status` 观察已记录步骤数，确认事件确实被捕获。
- 录制器**不会**把密码值写进流程文件；会标记 `sensitive`。
- 检测到验证码组件时，会自动在提醒里点名。

## 阶段 3 · 生成技能并审清单

```
record_stop { name: "<技能名>" }
```

返回内容包含：步骤清单（人类可读）、自动变量化结果、推断出的断言、录制提醒、lint 结果。

**必须把步骤清单原文呈现给用户确认**，逐条核对：
- 有没有多点一步（手滑点错菜单）？→ `flow_step_delete`
- 有没有少点一步（录制断了）？→ 补录或 `flow_step_update`
- 顺序对不对？→ `flow_step_move`

> 文章原话：演示时我点成了另一个菜单，AI 忠实学会了错误路径。录完务必自己先看一遍步骤清单。

## 阶段 4 · 变量化

**已自动完成**：录制器会把等于「今天/昨天/明天」的日期字面量替换成 `${today:YYYY-MM-DD}` 这类内置变量（见 `autoVariables` 字段）。

**需要手工补**：业务编号、金额、环境等。

```
flow_param_add {
  flowId: "订单日报导出",
  name: "单号",
  source: "excel:D:/data/orders.xlsx#单号@0",
  required: true
}
```

单号来源写法：

| 写法 | 含义 |
|---|---|
| `excel:文件#单号@0` | 第一行数据 |
| `excel:文件#单号@2` | 第 3 行数据（0 基） |
| `excel:文件#单号@*` | 整列，换行拼接（适合批量粘贴） |
| `excel:文件#2@0` | 按 1 基列序号取第 1 行 |
| `excel:文件#C@0` | 按列字母取第 1 行 |
| `env:变量名` | 环境变量 |
| `secret:凭据名` | 加密凭据（先 `secret_set`） |
| `prompt` | 运行时必填，由人提供 |
| `flow:前一个流程id:提取键` | 串联时取上一流程的 extract 结果 |

支持 `.xlsx .csv .tsv .txt .json`（xlsx 为内置零依赖解析器）。

## 阶段 5 · 补结果校验（不补等于没做完）

`flow_lint` 若报 **L010 缺少结果校验**，必须补：

```
flow_assertion_add { flowId: "订单日报导出", kind: "tableNotEmpty", selector: "table tbody tr", min: 1, message: "报表必须有数据行" }
```

常见组合：

| 场景 | 断言 |
|---|---|
| 有报表/列表 | `tableNotEmpty`（或 `listNotEmpty`） |
| 有导出文件 | 录制时自动加 `download { minBytes: 1, minLines: 2 }` |
| 有提交动作 | `textPresent { text: "提交成功" }` |
| 有跳转 | `url { contains: "/report" }` |
| 有取数 | `extract` 后用 `extracted { as: "单号", notEmpty }` |

> 不用怕漏：回放时「空结果守卫」会兜底——只要页面呈现空表/空列表/「暂无数据」，一律判失败。

## 阶段 6 · 预检与回放

```
flow_preflight { flowId: "订单日报导出" }    # 非破坏性：只验证定位符，不点任何按钮
flow_run { flowId: "订单日报导出" }           # 无头回放
```

回放报告要重点看四件事：
1. `status` 是否 pass
2. `assertions` 是否全部通过
3. `healed` 是否为空（不为空说明页面在变，属于预警）
4. `screenshots` 是否有图（人工复核用）

## 阶段 7 · 上线定时与告警

```
schedule_add { flowId: "订单日报导出", frequency: "daily", at: "09:00" }
schedule_run_now { flowId: "订单日报导出" }
run_history { flowId: "订单日报导出" }
```

```
notify_config { enabled: true, type: "wecom", webhook: "<机器人地址>", on: ["failure", "healed"] }
notify_test
```

## 阶段 8 · 验收

用文章里的验收标准收尾：

1. 第二天早上**不碰它**，让它自己跑一遍
2. 该出的报表在、该提交的交了、没报错
3. 故意把源数据改成空 → 它必须**报失败并告警**，而不是静默成功

第 3 条是分水岭：能做到，才算真的完成。
