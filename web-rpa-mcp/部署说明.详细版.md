## 一、这个包是什么

把重复的网页点击**录成技能**，之后一键或定时复跑。它由两层组成：

| 层 | 文件 | 作用 | 装到哪 |
|---|---|---|---|
| 技能层 | `SKILL.md` + `workflows\` + `references\` | 让客户端/大模型知道「何时用、怎么用、红线是什么」 | 客户端 skills 目录（`install.mjs` 自动复制） |
| 服务层 | `mcp\` | MCP 服务器（stdio / JSON-RPC 2.0，44 工具）+ CLI 运行器 | 原地即可，注册其绝对路径 |

```text
web-rpa-mcp/                  ← 项目/技能目录
├── SKILL.md                  # 技能说明（何时用 / 使用工作流 / 排障与自愈）
├── install.mjs               # 安装器：建目录 + 生成 .gitignore + 装依赖 + 自检 + 注册 + 装技能
├── README.md                 # 安装与使用（含「更新记录」）
├── 部署说明.md               # 简明部署（3 步速览 + 排错）
├── 部署说明.详细版.md        # 本文档
├── demo/                     # 本地演示站点（e2e/集成测试自供给）
├── workflows/ references/    # 技能工作流与 DSL/断言参考文档
├── flows/                    # 流程定义（技能本体；含演示流程 fixture）
└── mcp/                      # ← MCP 服务器本体
    ├── server.mjs            # 入口（stdio JSON-RPC 2.0；--doctor / --tools 自检口）
    ├── runner.mjs            # CLI：run/list/show/history/status/prune（退出码 0/1/2/3）
    ├── selftest.mjs          # 全链路自检聚合器（7 套 387 项，支持按套件/按组过滤）
    ├── lib/                  # 录制器 / 回放器 / 存储 / 浏览器 / 凭据加密 / 定位符自愈等
    ├── test/                 # unit / rules / mcp-protocol / tools / e2e / integration / audit
    ├── package.json / package-lock.json
    └── node_modules/         # ← 纯净包【不含】，装依赖时命令生成
```

### 纯净包（分发包）里没有的东西

本包按「**零预装依赖、不带任何 `.` 前缀文件/目录、不带凭据与生成物**」分发，以下各项由你在安装/使用时生成：

1. **`mcp/node_modules/`** —— `install.mjs` 检测到缺 `playwright` 时自动 `npm install` **命令生成**（或手工 `cd mcp; npm ci`）。
2. **`.gitignore`** —— `install.mjs` 自动生成（纯净包不带任何 `.` 前缀文件；作用是保护 `.work/`、`runs/`、`logs/`、`web-rpa.config.json` 等敏感/生成物不入 git）。
3. **`web-rpa.config.json`** —— `install.mjs` 写默认配置；可能含 Webhook 地址，**不入 git、不外传**。
4. **`runs/` `logs/` `(.work/`)** —— 运行时生成：执行报告与截图 / 运行日志 / **加密密钥与凭据、浏览器登录态 profile（等同登录凭据）、定时包装器、流程备份**。
5. **`mcp-register.example.json`** —— 装机时按当前机器路径重新生成（分发包一律剔除开发机绝对路径）。

> 校验纯净包：根下只有上表列出的源码/文档/fixture，没有 `node_modules`，没有任何 `.` 前缀文件/目录，没有 `runs/`、`logs/`、`.work/`、`web-rpa.config.json`。

## 三、从纯净包开始安装（4 步）

### 总览

| 步骤 | 做什么 | 成功的标志 |
|---|---|---|
| 1 | 放置目录 | `web-rpa-mcp\install.mjs` 可见 |
| 2 | 装依赖（`node install.mjs` 一步到位） | `mcp\node_modules\` 生成，doctor 报 playwright 可用 |
| 3 | 注册 MCP 服务器 | 客户端配置里出现 `mcpServers.webrpa` |
| 4 | 验收 | 自检 `0 failed`，客户端列出 44 个工具 |

### 3.1 第 1 步：放置

放任意目录即可；放进客户端技能根则技能自动发现：

```powershell
Copy-Item -Recurse -Force "D:\path\to\web-rpa-mcp" "$env:USERPROFILE\.agents\skills\web-rpa-mcp"
cd "$env:USERPROFILE\.agents\skills\web-rpa-mcp"
```

### 3.2 第 2 步：安装（装依赖由这步命令生成）

```powershell
node install.mjs
```

按序执行：Node 版本检查 → 建 `flows\ runs\ logs\ .work\` 目录 + 生成 `.gitignore` → 写默认配置 → **解析 playwright（缺失自动 `npm install`）** → 浏览器探测 → 单元自检 → 打印注册 JSON → 复制 SKILL/workflows/references 到技能目录。

若自动装依赖失败（离线/内网），手工安装后重跑 `node install.mjs` 即可：

```powershell
cd mcp
npm ci --no-audit --no-fund                                                   # 严格按 lock 安装（推荐）
npm ci --no-audit --no-fund --registry=https://registry.npmmirror.com         # 国内镜像
```

验证依赖与浏览器：

```powershell
node -e "require('playwright'); console.log('deps ok')"
node mcp\server.mjs --doctor      # browser 字段不应是 none
```

### 3.3 第 3 步：注册 MCP 服务器

安装器步骤 7 会打印注册 JSON（含当前机器绝对路径），复制进客户端配置即可：

```json
{ "mcpServers": { "webrpa": { "command": "node", "args": ["<项目目录>\\web-rpa-mcp\\mcp\\server.mjs"] } } }
```

| 客户端 | 配置文件 / 命令 |
|---|---|
| Claude Code | `claude mcp add webrpa -- node "<项目目录>\web-rpa-mcp\mcp\server.mjs"` 或项目 `.mcp.json` |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` |
| Cursor | `~/.cursor/mcp.json` |

**注册后必须重启客户端。**

### 3.4 第 4 步：验收

```powershell
node mcp\server.mjs --doctor        # 环境自检
cd mcp; node selftest.mjs           # 全链路自检：7 套全绿（387 passed / 0 failed）
```

再让模型调一次 `doctor`，返回环境检查结果即接入成功。首次使用建议走一遍：`record_start`（打开浏览器慢做一遍日常操作）→ `record_stop`（生成技能）→ `flow_lint` → `flow_run`。

## 五、配置管理（`web-rpa.config.json`）

用 `config_get` / `config_set` 读写，不必手改文件。合并式覆盖，不需要的字段可以不写：

| 段 | 关键字段 | 说明 |
|---|---|---|
| `browser` | `mode`（auto/custom）、`channel`、`executablePath`、`headless`、`viewport`、`locale`、`timezoneId`、`persistProfile` | 浏览器选择与环境 |
| `run` | `stepTimeoutMs`、`navTimeoutMs`、`retries`、`maxDurationMs`（运行级总超时，0=不限）、`unattendedMaxDurationMs`（定时运行未配总超时的兜底上限，默认 2 小时，0=关闭）、`saveEvidence`/`evidenceOn`、`saveVideo`/`videoOn`（失败录像证据，敏感输入流程自动跳过）、`humanHandoffTimeoutMs`、`emptyResultGuard`、`healMinScore`、`strictDialogs`、`keepRunsPerFlow`/`keepRunDays`、`keepVideosPerFlow`（每流程录像留存段数，默认 20，0=不限） | 回放行为与留存 |
| `security` | `maskSecrets`、`maskFieldsInScreenshots`、`redactKeys` | 参数/日志/截图脱敏 |
| `notify` | `enabled`、`type`（wecom/dingtalk/feishu/slack/generic）、`webhook`、`on` | 告警 |
| `schedule` | `taskPrefix`（默认 `WebRPA`） | 任务计划前缀 |

- **凭据**：`secret_set` 存入 `.work\secrets.json`（加密落盘），步骤参数用 `source: "secret:<名>"` 引用，报告里自动掩码。
- **登录态**：`profile_login` 人工登录一次后长期复用（`.work\profile\`，**等同登录凭据，不要外传**；换人/换账号用 `profile_reset`）。

## 六、安全机制（简要）

1. **`.work\` 整目录按凭据对待**：加密密钥、加密凭据、浏览器登录态 profile、定时包装器、流程备份。不入 git（装机生成的 `.gitignore` 已屏蔽）、不外传。
2. **脱敏**：`redactKeys` 按键名把命中键（默认 password/token/secret 等）的值替换为 `***` 并全文清除；`maskSecrets` 是参数值/日志脱敏总开关（`false` 仅放开便于调试，secret 凭据值与 webhook 回显永远打码）；`maskFieldsInScreenshots` 截图打码敏感字段；报告与告警文案同口径。
3. **备份与回滚**：任何流程改动/删除前自动备份（`.work\backups\`，每流程留 10 份、30 天）；`flow_restore { flowId }` 回滚，**误删也能找回**（`flow_restore { flowId, list: true }` 列备份）。
4. **执行锁**：同一流程同时只允许一个执行；强杀残留锁用 `lock_status` 确认后 `lock_release`。
5. **空结果守卫**：改版点错位置导致的空表/空列表默认判失败（`emptyResultGuard`），防止「生成空表却当成成功」。

## 七、问题排查

### 7.1 依赖相关

| 现象 | 怎么办 |
|---|---|
| `doctor` 报 playwright 不可用 | `cd mcp; npm install`（内网加 `--registry=https://registry.npmmirror.com`）|
| `npm install` 超时 | 换镜像源重试；或复用同机器其它项目已装的 playwright（本工具会自动搜索兄弟目录） |

### 7.2 浏览器 / 录制回放

| 现象 | 怎么办 |
|---|---|
| 录制时窗口没出现 | `doctor` 看 `browser`；设 `browser.channel="msedge"`；或 `npx playwright install chromium` |
| 步骤找不到元素 | 先 `flow_lint` 看建议；自愈会在改版时自动换定位符（`healMinScore`），自愈不过再人工 `flow_step_update` |
| 回放被空结果拦截 | 页面确实无数据属预期；确认有数据仍被拦时用 `flow_run` 的 `emptyResultOk: true` 豁免并留证据 |
| 只错中间几步 | `record_splice_start { flowId, from, to }` 片段重录，不用整条重来 |

### 7.3 定时 / 执行 / 锁

| 现象 | 怎么办 |
|---|---|
| 定时没跑 | 任务计划里查 `WebRPA*` 任务；`schedule_run_now` 手工触发后 `run_history` 查结果；输出在 `logs\schedule-<flowId>.log` |
| 报「正在执行中」但没在跑 | 进程被强杀锁没释放：`lock_status` 确认后 `lock_release` |
| 上次执行显示 `interrupted` | 被强杀/断电没正常收尾；确认业务是否只做了一半，必要时人工补做 |

### 7.4 客户端注册

| 现象 | 怎么办 |
|---|---|
| 客户端里没有 `webrpa` | 完全退出客户端再启动；核对注册 JSON 绝对路径；`node mcp\server.mjs --tools` 能列 44 个工具说明服务本身没问题 |
| 工具在但调用报错 | 看 `logs\` 下当日日志；报错原文 + `doctor` 输出是最快定位材料（**注意脱敏**） |

> 还有《坑与护栏》（`references\坑与护栏.md`）与 SKILL.md「排障与自愈」工作流（`workflows\排障与自愈.md`）。

## 八、升级、卸载与回滚

**升级**：整体覆盖拷贝即可，但**保留这四样**（它们是你的数据/凭据）：

```powershell
# 覆盖前备份：.work\  runs\  logs\  web-rpa.config.json  flows\
# 覆盖源码后重跑：node install.mjs   （会重新生成依赖并自检）
```

**回滚流程改动**：`flow_restore { flowId }` 从 `.work\backups\` 恢复（任何改动/删除前自动备份）。

**卸载**：删目录前先确认 `.work\` 里的登录态 profile 与密钥是否需要安全处置；客户端配置里删掉 `mcpServers.webrpa` 并重启；任务计划里删掉 `WebRPA*` 任务（或 `schedule_remove`）。

## 九、自然语言使用示例（场景化 · 覆盖全部 44 个工具）

> 用「自然语言」对 AI 助手描述需求，它会映射到下列 MCP 工具调用。示例只列**关键参数**；完整 inputSchema 以客户端工具面板或 `node mcp\server.mjs --tools` 为准（下文参数名均取自真实 inputSchema）。每个场景标注覆盖的工具，文末有**全 44 工具覆盖对照表**。

### A · 把「每天导出订单日报」录成技能
> 你：「A 系统每天要导出订单日报，帮我录下来，以后一键跑。」

1. `doctor` — 先确认 playwright 与浏览器可用。
2. `record_start { "url": "https://a.example.com", "name": "订单日报导出" }` — 打开可见浏览器；**你亲手**慢一点操作一遍（点报表 → 选日期 → 导出），每步停半秒。
3. `record_status` — 中途随时看「已记了哪几步、有没有敏感值 / 验证码 / 下载提醒」。
4. `record_stop { "name": "订单日报导出" }` — 结束并生成技能，返回可审阅步骤清单 + lint 结果（自动把「今天/昨天」字面量换成变量、推断结果校验）。
5. `flow_show { "flowId": "订单日报导出" }` — 把清单给你核对：有没有多点 / 少点某一步。
6. `flow_lint { "flowId": "订单日报导出" }` — 静态检查（26 条规则；缺结果校验会提示）。
7. `flow_run { "flowId": "订单日报导出" }` — 先跑一次确认稳定。

覆盖工具：`doctor` · `record_start` · `record_status` · `record_stop` · `flow_show` · `flow_lint` · `flow_run`

### B · 录错了，只重录「中间那几步」
> 你：「流程第 5 到 7 步点错了，别整条重来，就重录这几步。」

1. `record_splice_start { "flowId": "订单日报导出", "from": 5, "to": 7 }` — 先把第 1~4 步真实重放一遍（页面回到出错前的真实状态），再打开录制让你只重做 5~7 步。
   （`keepSuffix:false` 可丢掉第 7 步之后的旧步骤；`params` 传重放前缀所需变量取值；默认 `headed:true`。重录完成后调 `record_stop` 自动拼接回流程并备份原定义。）
2. `record_cancel` — 中途反悔就取消，原流程一字不动。

覆盖工具：`record_splice_start` · `record_cancel`

### C · 步骤精修（不整条重录）
> 你：「第 3 步删掉；第 6 步标成会下载文件；把第 6 步挪到第 2 步前面。」

1. `flow_step_delete { "flowId": "订单日报导出", "index": 3 }` — 删掉录错的那一步。
2. `flow_step_update { "flowId": "订单日报导出", "index": 6, "patch": { "expectDownload": true } }` — 局部改一步，`patch` 只合并给出的字段：可把写死的值换成 `${变量}`、补上传文件路径、标记 `expectDownload` 等。
3. `flow_step_move { "flowId": "订单日报导出", "from": 6, "to": 2 }` — 调整步骤顺序。

覆盖工具：`flow_step_delete` · `flow_step_update` · `flow_step_move`

### D · 给流程加变量（日期 / 单号 / 凭据）
> 你：「日期和单号每次都变，做成变量；单号从 Excel 取；口令用加密凭据。」

1. `flow_param_add { "flowId": "订单日报导出", "name": "日期", "source": "const", "default": "2026-09-30" }` — 声明变量，步骤里用 `${日期}` 引用。`source` 取值：`const` / `env:NAME` / `secret:NAME` / `excel:<文件>#<列>[@行|*]` / `csv:…` / `flow:<流程id>:<键>` / `prompt`。
2. `flow_param_add { "flowId": "订单日报导出", "name": "单号", "source": "excel:D:/data/orders.xlsx#单号@0" }` — 取 Excel 第一行单号（`@*` 取整列）。
3. `flow_param_add { "flowId": "订单日报导出", "name": "口令", "source": "secret:report_pwd", "secret": true }` — 引用加密凭据并标记敏感（输出掩码）。
4. `flow_param_remove { "flowId": "订单日报导出", "name": "单号" }` — 删掉不再要的变量。

覆盖工具：`flow_param_add` · `flow_param_remove`

### E · 补结果校验（防空报表）
> 你：「导出完帮我确认结果不是空的，空了要报警。」

1. `flow_assertion_add { "flowId": "订单日报导出", "kind": "tableNotEmpty", "selector": "table tbody tr", "min": 1, "message": "订单表为空" }` — 表格至少要有 1 行。`kind` 可选：`tableNotEmpty / listNotEmpty / textPresent / textAbsent / elementVisible / elementAbsent / url / title / download / extracted / noErrorBanner`。
2. `flow_assertion_add { "flowId": "订单日报导出", "kind": "download", "minBytes": 1024 }` — 导出文件至少 1KB（防只有表头）。
3. `flow_assertion_remove { "flowId": "订单日报导出", "index": 1 }` — 删掉第 1 条断言（从 1 开始）。

覆盖工具：`flow_assertion_add` · `flow_assertion_remove`

### F · 流程管理：看 / 改名 / 导出迁移 / 删 / 恢复

**v1.5.10**：真实探针验证 MCP 结果结构化透出——`structuredContent` 纯增量（契约兼容）+ `outputSchema` 标「待确认」按最小化改动延后。① **`structuredContent` 纯增量透出结构化数据**：`ok()` 成功结果新增 `structuredContent` 真字段（=此前只序列化进 `content[0].text` 的同一份结构化 data），客户端（含只认结构化结果的）不必再从文本抠 JSON；`content` 文本回退**原样保留**（老客户端只读 text 零影响），`isError:false` 形状不变。② **`isError:true` 形状逐字节不变**：失败 `fail()` 不带 `structuredContent`，仍恰为 `{content, isError}`——按 `isError` 分流的客户端零影响。③ **`outputSchema`（tools/list 增 per-tool JSON Schema）标「待确认」延后**：客户端跨协议版（2024-11-05 / 2025-03-26 / 2025-06-18）如何消费不可实测确认，且 44 工具逐个精确 schema 有「臆造字段」红线风险，按「最小化改动 + 不臆造」延后，待客户端兼容面确认后再评估。**契约兼容结论：纯增量**（工具名/参数名/返回结构/isError:true 形状全不变，仅成功结果多一真字段）。自检 387 项全绿（107 单元 + 27 规则 + 24 协议 + 65 工具 + 34 端到端 + 130 集成；新增 2 项协议回归 = structuredContent 增量一致 + isError:true 形状不变）。
**v1.5.9**：真实探针修复一处「误报连续失败」缺陷 + statusReport totalRuns 真值优化。① **连续失败不再把未定论/崩溃的运行计为失败**（误报故障类）：`status_report` 的 `consecutiveFailures` 此前把 `running`（进行中、尚未定论）与 `interrupted`（崩溃，已由 item.interrupted 单列）也当一次失败累加——真实探针实锤：上一次已完成是 pass、当前这次还在跑时报 `consecutiveFailures:1`（应 0，会误触发"连续失败 N 次"告警）；2 次真失败 + 1 次崩溃时报 3（应 2，崩溃被重复计数）。现在连续失败只数「已定论的失败」（fail/blocked），pass 即止，`running`/`interrupted` 既不计失败也不打断计数。② **totalRuns 是真实运行总数**：此前用 `listRuns(100).length` 当 totalRuns，运行超 100 次恒报 100（少报）；现在单遍枚举同时给出窗口摘要与真实总数（新增 `listRunsEx`），totalRuns 不再被 100 条摘要窗口封顶。③ `status_report` 工具描述同步更新，明确 totalRuns=真实总数、consecutiveFailures 只数已定论失败，供 agent 调用时正确解读字段。自检 385 项全绿（107 单元 + 27 规则 + 22 协议 + 65 工具 + 34 端到端 + 130 集成；新增 3 项集成 = 2 连续失败语义 + 1 totalRuns 真值）。

## 发版门禁（发版者）

发版 = 跑 `node distribute.mjs --force`，收尾自动「一次性副本验收 + 终态哈希终查」（加固 H19，发版不可能忘）：

1. 纯净打包（逐文件哈希自校验 + 排除项泄漏检查；`.work\`/`runs\`/`logs\` 运行现场目录一并剔除）；
2. **一次性副本验收**：临时目录副本跑 `npm ci` + `selftest.mjs` + `test/tools.mjs`（63 用例）+ `test/integration.mjs`，
   验后整目录删除——交付树自始至终不进套件。套件契约：三套件都从 `mcp\` 目录起跑
   （README 调用姿势 `node test\integration.mjs`，runner CLI 用例按 `process.cwd()` 找 `mcp/runner.mjs`）；
3. **终态哈希终查**：门禁前后交付树哈希逐位一致 + 纯净复扫。

验收退出码契约（统一诚实 SKIP 口径）：`exit 0` 全部通过 / `exit 1` 存在失败 / `exit 3` 诚实 SKIP
（明示记录判过，不冒充全绿）。门禁失败退出码 3、发布包不可交付。`--gate-only` 只跑门禁不打包
（源树口径：源树排除名单内残留——`.git`/`.work` 等——记「已知排除项（不随包）」不判红，交付纯净由
`--force` 打包自校验与纯净复扫保证）；
`--no-gate` 显式跳过（留痕）。**装机生成物不随包**：`web-rpa.config.json`（`install.mjs`「已存在则跳过」
生成的默认配置，可能含 Webhook 地址）、`mcp-register.example.json`、`accounts.json` 在过滤名单机械兜底
——无配置时验收套件照常全绿（无 config 复测门禁四项全过实证）。
