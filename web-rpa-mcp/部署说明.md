```powershell
# 安装 / 修复（自动建目录 + 生成 .gitignore + 装依赖 + 自检 + 打印注册 JSON + 装技能）

node mcp\runner.mjs prune --apply --logs                        # 清理运行记录与过期日志
```

## 自然语言使用示例（场景化 · 覆盖全部 44 个工具）

> 用「自然语言」对 AI 助手描述需求，它会映射到下列 MCP 工具调用。示例只列**关键参数**；完整 inputSchema 以客户端工具面板或 `node mcp\server.mjs --tools` 为准（下文参数名均取自真实 inputSchema）。按**功能模块**分类，44 个工具每个**恰好出现一次**（被多场景用到的只保留最贴切一处），文末有**全 44 工具覆盖对照表**。README 里另有每工具一行的速查表，完整场景展开只在本文一处。

### 录制（`record_start` / `record_status` / `record_stop` / `record_splice_start` / `record_cancel`）

**场景 1 · 把「每天导出订单日报」录成技能**
> 你：「A 系统每天要导出订单日报，帮我录下来，以后一键跑。」

1. `record_start { "url": "https://a.example.com", "name": "订单日报导出" }` — 打开可见浏览器；**你亲手**慢一点操作一遍（点报表 → 选日期 → 导出），每步停半秒。
2. `record_status` — 中途随时看「已记了哪几步、有没有敏感值 / 验证码 / 下载提醒」。
3. `record_stop { "name": "订单日报导出" }` — 结束并生成技能，返回可审阅步骤清单 + lint 结果（自动把「今天/昨天」字面量换成变量、推断结果校验）。

得到：一个可审阅、带结果校验的技能（流程定义）。

**场景 2 · 录错了，只重录「中间那几步」**
> 你：「流程第 5 到 7 步点错了，别整条重来，就重录这几步。」

1. `record_splice_start { "flowId": "订单日报导出", "from": 5, "to": 7 }` — 先把第 1~4 步真实重放一遍（页面回到出错前的真实状态），再打开录制让你只重做 5~7 步；重录完收尾自动拼接回流程并备份原定义（`keepSuffix:false` 可丢掉后面的旧步骤，`params` 传重放前缀所需变量取值，默认 `headed:true`）。
2. `record_cancel` — 中途反悔就取消，原流程一字不动。

得到：只换了出错片段的流程，其余步骤与既有变量/断言原样保留。

覆盖工具：`record_start` · `record_status` · `record_stop` · `record_splice_start` · `record_cancel`

### 流程管理（`flow_list` / `flow_show` / `flow_lint` / `flow_rename` / `flow_delete` / `flow_export` / `flow_import` / `flow_restore`）

**场景 1 · 看清楚有哪些流程、录了什么、有没有要补**
> 你：「列一下我有哪些流程；『订单日报导出』到底录了什么，有没有要补的。」

1. `flow_list` — 列出全部流程（id / 名称 / 步骤数 / 参数数 / 断言数 / 更新时间）。
2. `flow_show { "flowId": "订单日报导出" }` — 完整步骤清单（含变量/断言；`format` 可选 markdown / json）。
3. `flow_lint { "flowId": "订单日报导出" }` — 静态检查（26 条规则）。

得到：一眼看清每个流程录了什么、哪些要补（如缺结果校验会点名）。

**场景 2 · 改名 / 迁移 / 删除 / 找回**
> 你：「把『订单日报导出』改个好认的名字，导出一份进 git；另一台机器上把它导进去；这台机器删掉它——哎删错了，找回来。」

1. `flow_rename { "flowId": "订单日报导出", "name": "订单日报导出（正式）" }` — 只改显示名，id 不变（不打断定时与运行记录）。
2. `flow_export { "flowId": "订单日报导出" }` — 导出流程定义 JSON（备份 / 分享 / 入 git）。
3. `flow_import { "flow": "<流程 JSON>", "overwrite": true }` — 导入流程定义（换机器迁移）。
4. `flow_delete { "flowId": "订单日报导出" }` — 删除流程及其运行记录索引。
5. `flow_restore { "flowId": "订单日报导出" }` — 误删 / 改坏时回滚到最近备份；`flow_restore { "flowId": "…", "list": true }` 列出全部备份（改动 / 删除前自动备份，每流程留 10 份、30 天）。

得到：流程可改名、可迁移、可删除，误删也能从备份找回。

覆盖工具：`flow_list` · `flow_show` · `flow_lint` · `flow_rename` · `flow_delete` · `flow_export` · `flow_import` · `flow_restore`

### 变量与断言（`flow_param_add` / `flow_param_remove` / `flow_assertion_add` / `flow_assertion_remove`）

**场景 1 · 给流程加变量（日期 / 单号 / 凭据）**
> 你：「日期和单号每次都变，做成变量；单号从 Excel 取；口令用加密凭据。」

1. `flow_param_add { "flowId": "订单日报导出", "name": "日期", "source": "const", "default": "2026-09-30" }` — 声明变量，步骤里用 `${日期}` 引用。`source` 取值：`const` / `env:NAME` / `secret:NAME` / `excel:<文件>#<列>[@行|*]` / `csv:…` / `flow:<流程id>:<键>` / `prompt`。
2. `flow_param_add { "name": "单号", "source": "excel:D:/data/orders.xlsx#单号@0" }` — 取 Excel 第一行单号（`@*` 取整列）。
3. `flow_param_add { "name": "口令", "source": "secret:report_pwd", "secret": true }` — 引用加密凭据并标记敏感（输出掩码）。

得到：每次跑传不同值即可复用，敏感值不落明文。

**场景 2 · 补结果校验（防空报表）**
> 你：「导出完帮我确认结果不是空的，空了要报警。」

1. `flow_assertion_add { "flowId": "订单日报导出", "kind": "tableNotEmpty", "selector": "table tbody tr", "min": 1, "message": "订单表为空" }` — 表格至少要有 1 行。`kind` 可选：`tableNotEmpty / listNotEmpty / textPresent / textAbsent / elementVisible / elementAbsent / url / title / download / extracted / noErrorBanner`。
2. `flow_assertion_add { "kind": "download", "minBytes": 1024 }` — 导出文件至少 1KB（防只有表头）。

得到：空表 / 只有表头的导出直接判失败并告警。

**场景 3 · 删掉不要的变量和断言**
> 你：「『单号』这个变量不要了；第 1 条断言也删掉。」

1. `flow_param_remove { "flowId": "订单日报导出", "name": "单号" }` — 删掉不再要的变量。
2. `flow_assertion_remove { "flowId": "订单日报导出", "index": 1 }` — 删掉第 1 条断言（从 1 开始）。

得到：变量与断言清单只剩当前真正在用的。

覆盖工具：`flow_param_add` · `flow_param_remove` · `flow_assertion_add` · `flow_assertion_remove`

### 步骤编辑（`flow_step_delete` / `flow_step_update` / `flow_step_move`）

**场景 · 步骤精修（不整条重录）**
> 你：「第 3 步删掉；第 6 步标成会下载文件；把第 6 步挪到第 2 步前面。」

1. `flow_step_delete { "flowId": "订单日报导出", "index": 3 }` — 删掉录错的那一步。
2. `flow_step_update { "flowId": "订单日报导出", "index": 6, "patch": { "expectDownload": true } }` — 局部改一步，`patch` 只合并给出的字段：可把写死的值换成 `${变量}`、补上传文件路径、标记 `expectDownload` 等。
3. `flow_step_move { "flowId": "订单日报导出", "from": 6, "to": 2 }` — 调整步骤顺序。

得到：三处小修一次完成，不必整条重录。

覆盖工具：`flow_step_delete` · `flow_step_update` · `flow_step_move`

### 执行与报告（`flow_preflight` / `flow_run` / `chain_run` / `run_history` / `run_report` / `status_report` / `runs_prune`）

**场景 1 · 预检后正式跑**
> 你：「先确认定位没坏，再正式跑『订单日报导出』。」

1. `flow_preflight { "flowId": "订单日报导出" }` — 非破坏性定位预检（只探位不执行），报告哪一步降级命中（改版预警）。
2. `flow_run { "flowId": "订单日报导出" }` — 正式回放（自愈 / 断言 / 截图 / 告警；`params` 传变量取值，`headed` 有头跑，`maxDurationMs` 总时限，`saveVideo` 失败录像）。

得到：先知道页面有没有改版，再拿到一次带回放结论与截图证据的执行。

**场景 2 · 多流程串联**
> 你：「把『取数 → 填表 → 发邮件』串成一条线跑完。」

1. `chain_run { "items": [ { "flow": "取数" }, { "flow": "填表", "params": { "日期": "2026-09-30" } }, { "flow": "发邮件", "continueOnError": true } ], "maxDurationMs": 1800000 }` — 前一步 `extract` 出的值用 `${<前一流程id>:<键>}` 引用；`continueOnError` 让某步失败后继续；`maxDurationMs` 是整条串联总时限（到期剩余流程不执行）。

得到：一条线跑完取数→填表→发邮件，前一步提取值自动传给后一步。

**场景 3 · 看昨晚跑成功没**
> 你：「昨晚那单跑成功没？把那一次的完整报告给我。」

1. `run_history { "flowId": "订单日报导出", "limit": 20 }` — 历史执行记录（状态 / 耗时 / 触发方式 / 自愈次数 / 失败步骤）。
2. `run_report { "flowId": "订单日报导出" }` — 读某次完整报告（默认 `latest`；用 `stamp` 指定某次）。

得到：先定位是哪一次，再拿到那次的完整报告与截图证据。

**场景 4 · 全流程健康总览与留存清理**
> 你：「看下全部流程的健康度；历史运行记录太多，只留最近 30 天，先让我看看会删哪些。」

1. `status_report` — 全流程健康总览（最后状态 / 连续失败 / 中断 / 执行中 / 自愈趋势；`onlyProblems:true` 只看有问题的）。
2. `runs_prune { "keepDays": 30 }` — **默认只预演**（列出将删内容，不真删）。语义：只传 `keepCount` 或 `keepDays` 之一＝按该单维度清理（另一维度不限）；两者都传＝AND；都不传＝按配置双约束。`keepVideos` 控每流程录像留存段数。确认后 `runs_prune { "keepDays": 30, "dryRun": false, "logs": true }` 真正删除（含过期日志）。

得到：一眼看清哪些流程有问题；清理先预演、确认后才真删。

覆盖工具：`flow_preflight` · `flow_run` · `chain_run` · `run_history` · `run_report` · `status_report` · `runs_prune`

### 锁 · 定时 · 告警 · 凭据 · 登录态 · 配置（`lock_status` / `lock_release` / `schedule_add` / `schedule_list` / `schedule_remove` / `schedule_run_now` / `notify_config` / `notify_test` / `secret_set` / `secret_list` / `secret_delete` / `profile_login` / `profile_info` / `profile_reset` / `config_get` / `config_set` / `doctor`）

**锁（`lock_status` / `lock_release`）**
> 你：「一直提示『正在执行中』但没在跑是怎么回事？」

1. `lock_status { "flowId": "订单日报导出" }` — 看执行锁：谁在跑、从何时、是否已成过期锁。
2. `lock_release { "flowId": "订单日报导出" }` — 上次被强杀、锁没释放时强制释放（先 `lock_status` 确认确实没在跑）。

得到：确认锁的持有者并释放过期锁，流程立刻能再跑。

**定时（`schedule_add` / `schedule_run_now` / `schedule_list` / `schedule_remove`）**
> 你：「每天早上 9 点自动跑；先让我验证一次链路；看看都定了哪些定时；不合适的删掉。」

1. `schedule_add { "flowId": "订单日报导出", "frequency": "daily", "at": "09:00" }` — 注册 Windows 任务计划。`frequency`：`daily / weekly / hourly / minute / once / logon`；`weekly` 配 `days:["MON","WED"]`；`once` 配 `date:"2026/10/01"`；`hourly`/`minute` 配 `everyHours`/`everyMinutes`。
2. `schedule_run_now { "flowId": "订单日报导出" }` — 立即触发一次（走任务计划，验证定时链路通不通）。
3. `schedule_list` — 列出定时任务及系统实际状态（下次运行 / 上次结果）。
4. `schedule_remove { "flowId": "订单日报导出" }` — 删除定时任务。

得到：定时的注册 / 验证 / 查看 / 删除四件事都在工具里完成。

**告警（`notify_config` / `notify_test`）**
> 你：「跑失败了要发到企业微信群，并 @我；发条测试消息验证一下。」

1. `notify_config { "enabled": true, "type": "wecom", "webhook": "https://qyapi.weixin.qq.com/…", "on": ["failure", "healed"], "mention": "@张三" }` — 配置告警。`type`：`wecom / dingtalk / feishu / slack / generic`；`on`：`failure / success / healed / all`。不传参数＝查看当前配置。
2. `notify_test { "message": "测试告警" }` — 发一条测试告警，验证 Webhook 通不通。

得到：失败即告警到群，且链路先用测试消息验证过。

**凭据（`secret_set` / `secret_list` / `secret_delete`）**
> 你：「把报表系统口令加密存起来，别明文落盘；看看存了哪些；旧的删掉。」

1. `secret_set { "name": "report_pwd", "value": "…" }` — AES-256-GCM 加密保存（密钥在本机 `.work/key`），任何输出不回显明文；步骤里用 `source:"secret:report_pwd"` 引用。
2. `secret_list` — 列出已存凭据名称（不含值）。
3. `secret_delete { "name": "report_pwd" }` — 删除凭据。

得到：口令加密落盘、按名引用，过期凭据随手删。

**登录态（`profile_login` / `profile_info` / `profile_reset`）**
> 你：「这个系统要登录才能用，我不想每次跑都登录。」

1. `profile_login { "url": "https://a.example.com/login", "successText": "工作台" }` — 打开可见浏览器**人工登录一次**（扫码 / 短信 / 账密都行）；检测到 `successText`（或 `successUrlContains:"/dashboard"`）就把登录态写进持久化 profile，并自动开启 `browser.persistProfile`。
2. `profile_info` — 查看登录态目录 / 体积 / 上次使用 / 是否被占用。
3. `profile_reset { "confirm": true }` — 换人换账号或怀疑串号时清空登录态（须显式 `confirm:true`）。

得到：登录一次长期复用，录制与定时都不必含登录步骤。

**配置与环境诊断（`config_get` / `config_set` / `doctor`）**
> 你：「把回放改成有头模式调试；看看现在配置；环境有没有问题。」

1. `config_get` — 读当前配置（浏览器 / 运行 / 安全 / 告警 / 定时各段）。
2. `config_set { "patch": { "browser": { "headless": false } } }` — 合并式改配置；把某项设为 `null` 即「恢复默认」。
3. `doctor` — 环境自检（浏览器 / playwright / 目录 / 录像能力 / 发件箱积压）。

得到：配置随查随改，环境问题一眼看清。

## 一、这个包是什么

把重复的网页点击**录成技能**，之后一键或定时复跑。它由两层组成：

| 层 | 文件 | 作用 | 装到哪 |
|---|---|---|---|
| 技能层 | `SKILL.md` + `workflows\` + `references\` | 让客户端/大模型知道「何时用、怎么用、红线是什么」 | 客户端 skills 目录（`install.mjs` 自动复制） |
| 服务层 | `mcp\` | MCP 服务器（stdio / JSON-RPC 2.0，44 工具）+ CLI 运行器 | 原地即可，注册其绝对路径 |

```text
web-rpa-mcp/                  ← 项目/技能目录
├── SKILL.md                  # 技能说明（何时用 / 使用工作流 / 排障与自愈）
├── install.mjs               # 安装器：建目录 + 生成 .gitignore + 装依赖 + 自检 + 注册 + 装技能
├── README.md                 # 安装与使用（含「更新记录」）
├── 部署说明.md               # 部署完整指引（含全工具使用示例，本文档）
├── demo/                     # 本地演示站点（e2e/集成测试自供给）
├── workflows/ references/    # 技能工作流与 DSL/断言参考文档
├── flows/                    # 流程定义（技能本体；含演示流程 fixture）
└── mcp/                      # ← MCP 服务器本体
    ├── server.mjs            # 入口（stdio JSON-RPC 2.0；--doctor / --tools 自检口）
    ├── runner.mjs            # CLI：run/list/show/history/status/prune（退出码 0/1/2/3）
    ├── selftest.mjs          # 全链路自检聚合器（7 套 427 项，支持按套件/按组过滤）
    ├── lib/                  # 录制器 / 回放器 / 存储 / 浏览器 / 凭据加密 / 定位符自愈等
    ├── test/                 # unit / rules / mcp-protocol / tools / e2e / integration / audit
    ├── package.json / package-lock.json
    └── node_modules/         # ← 纯净包【不含】，装依赖时命令生成
```

### 纯净包（分发包）里没有的东西

本包按「**零预装依赖、不带任何 `.` 前缀文件/目录、不带凭据与生成物**」分发，以下各项由你在安装/使用时生成：

1. **`mcp/node_modules/`** —— `install.mjs` 检测到缺 `playwright` 时自动 `npm install` **命令生成**（或手工 `cd mcp; npm ci`）。
2. **`.gitignore`** —— `install.mjs` 自动生成（纯净包不带任何 `.` 前缀文件；作用是保护 `.work/`、`runs/`、`logs/`、`web-rpa.config.json` 等敏感/生成物不入 git）。
3. **`web-rpa.config.json`** —— `install.mjs` 写默认配置；可能含 Webhook 地址（含 Webhook 时用 `notify_config` 填写），**不入 git、不外传**。
4. **`runs/` `logs/` `(.work/`)** —— 运行时生成：执行报告与截图 / 运行日志 / **加密密钥与凭据、浏览器登录态 profile（等同登录凭据）、定时包装器、流程备份**。
5. **`mcp-register.example.json`** —— 装机时按当前机器路径重新生成（分发包一律剔除开发机绝对路径）。

> 校验纯净包：根下只有上表列出的源码/文档/fixture，没有 `node_modules`，没有任何 `.` 前缀文件/目录，没有 `runs/`、`logs/`、`.work/`、`web-rpa.config.json`。

## 五、配置管理（`web-rpa.config.json`）

用 `config_get` / `config_set` 读写，不必手改文件。合并式覆盖，不需要的字段可以不写：

| 段 | 关键字段 | 说明 |
|---|---|---|
| `browser` | `mode`（auto/custom）、`channel`、`executablePath`、`headless`、`viewport`、`locale`、`timezoneId`、`persistProfile` | 浏览器选择与环境 |
| `run` | `stepTimeoutMs`、`navTimeoutMs`、`retries`、`maxDurationMs`（运行级总超时，0=不限）、`unattendedMaxDurationMs`（定时运行未配总超时的兜底上限，默认 2 小时，0=关闭）、`saveEvidence`/`evidenceOn`、`saveVideo`/`videoOn`（失败录像证据，敏感输入流程自动跳过）、`humanHandoffTimeoutMs`、`emptyResultGuard`、`healMinScore`、`strictDialogs`、`keepRunsPerFlow`/`keepRunDays`、`keepVideosPerFlow`（每流程录像留存段数，默认 20，0=不限） | 回放行为与留存 |
| `security` | `maskSecrets`、`maskFieldsInScreenshots`、`redactKeys` | 参数/日志/截图脱敏 |
| `notify` | `enabled`、`type`（wecom/dingtalk/feishu/slack/generic）、`webhook`、`on` | 告警 |
| `schedule` | `taskPrefix`（默认 `WebRPA`） | 任务计划前缀 |

- **凭据**：`secret_set` 存入 `.work\secrets.json`（加密落盘），步骤参数用 `source: "secret:<名>"` 引用，报告里自动掩码。
- **登录态**：`profile_login` 人工登录一次后长期复用（`.work\profile\`，**等同登录凭据，不要外传**；换人/换账号用 `profile_reset`）。

## 六、安全机制（简要）

1. **`.work\` 整目录按凭据对待**：加密密钥、加密凭据、浏览器登录态 profile、定时包装器、流程备份。不入 git（装机生成的 `.gitignore` 已屏蔽）、不外传。
2. **脱敏**：`redactKeys` 按键名把命中键（默认 password/token/secret 等）的值替换为 `***` 并全文清除；`maskSecrets` 是参数值/日志脱敏总开关（`false` 仅放开便于调试，secret 凭据值与 webhook 回显永远打码）；`maskFieldsInScreenshots` 截图打码敏感字段；报告与告警文案同口径。
3. **备份与回滚**：任何流程改动/删除前自动备份（`.work\backups\`，每流程留 10 份、30 天）；`flow_restore { flowId }` 回滚，**误删也能找回**（`flow_restore { flowId, list: true }` 列备份）。
4. **执行锁**：同一流程同时只允许一个执行；强杀残留锁用 `lock_status` 确认后 `lock_release`。
5. **空结果守卫**：改版点错位置导致的空表/空列表默认判失败（`emptyResultGuard`），防止「生成空表却当成成功」。

## 七、问题排查

### 7.1 依赖相关

| 现象 | 怎么办 |
|---|---|
| `doctor` 报 playwright 不可用 | `cd mcp; npm install`（内网加 `--registry=https://registry.npmmirror.com`）|
| `npm install` 超时 | 换镜像源重试；或复用同机器其它项目已装的 playwright（本工具会自动搜索兄弟目录） |

### 7.2 浏览器 / 录制回放

| 现象 | 怎么办 |
|---|---|
| 录制时窗口没出现 | `doctor` 看 `browser`；设 `browser.channel="msedge"`；或 `npx playwright install chromium` |
| 步骤找不到元素 | 先 `flow_lint` 看建议；自愈会在改版时自动换定位符（`healMinScore`），自愈不过再人工 `flow_step_update` |
| 回放被空结果拦截 | 页面确实无数据属预期；确认有数据仍被拦时用 `flow_run` 的 `emptyResultOk: true` 豁免并留证据 |
| 只错中间几步 | `record_splice_start { flowId, from, to }` 片段重录，不用整条重来 |
| 录错了 / 删错了 | 任何改动/删除前自动有备份：`flow_restore` 回滚，**误删也能找回** |

### 7.3 定时 / 执行 / 锁

| 现象 | 怎么办 |
|---|---|
| 定时没跑 | 先 `node mcp\runner.mjs list` 看流程还在不在；任务计划里查 `WebRPA*` 任务；`schedule_run_now` 手工触发后 `run_history` 查结果；输出在 `logs\schedule-<flowId>.log` |
| 报「正在执行中」但没在跑 | 进程被强杀锁没释放：`lock_status` 确认后 `lock_release` |
| 上次执行显示 `interrupted` | 被强杀/断电没正常收尾；确认业务是否只做了一半，必要时人工补做 |

### 7.4 客户端注册

| 现象 | 怎么办 |
|---|---|
| 客户端里没有 `webrpa` | 完全退出客户端再启动；核对注册 JSON 绝对路径；`node mcp\server.mjs --tools` 能列 44 个工具说明服务本身没问题 |
| 工具在但调用报错 | 看 `logs\` 下当日日志；报错原文 + `doctor` 输出是最快定位材料（**注意脱敏**） |

> 还有《坑与护栏》（`references\坑与护栏.md`）与 SKILL.md「排障与自愈」工作流（`workflows\排障与自愈.md`）。
> 真实卡住时发这三样最快定位：`node install.mjs` 完整输出、`node mcp\server.mjs --doctor` 输出、报错原文（**截图/日志注意脱敏**）。

## 八、升级、卸载与回滚

**升级**：整体覆盖拷贝即可，但**保留这四样**（它们是你的数据/凭据）：

```powershell
# 覆盖前备份：.work\  runs\  logs\  web-rpa.config.json  flows\
# 覆盖源码后重跑：node install.mjs   （会重新生成依赖并自检）
```

**回滚流程改动**：`flow_restore { flowId }` 从 `.work\backups\` 恢复（任何改动/删除前自动备份）。

**卸载**：删目录前先确认 `.work\` 里的登录态 profile 与密钥是否需要安全处置；客户端配置里删掉 `mcpServers.webrpa` 并重启；任务计划里删掉 `WebRPA*` 任务（或 `schedule_remove`）。

## 九、浏览器插件控制台（extension/，可选）

不想敲命令/等 Agent，也可以在浏览器里点点点控制全部 44 个工具：本地起一个零依赖桥接服务把 MCP 暴露成 HTTP，`extension/` 目录的 MV3 插件（六页签：状态 / 录制 / 流程 / 定时 / 系统 / 控制台）通过它实现开始/停止录制、回放与预检、变量断言步骤编辑、定时任务、告警凭据、持久化登录与运行总览；控制台页还能对任意工具做原始调用（含 `flow_import` 等未单独做界面的工具）。桥接同时提供 `/console` 网页版兜底（同一套界面，不装插件也能用）与调用可观测性（`GET /health` 透出调用统计与最近调用清单）。

```bash
node mcp/bridge.mjs      # 第 1 步：启动本地桥接（默认 127.0.0.1:8317；或 npm run bridge）
# 第 2 步：chrome://extensions → 开发者模式 → 加载已解压的扩展程序 → 选 extension/ 目录
```

> **可选 token 鉴权**（公网/跨机转发兜底）：桥接启动时设置 `WEBRPA_BRIDGE_TOKEN=令牌` 后，/health /tools /api/call 必须带 `X-RPA-Token` 头（网页版用 `/console?token=令牌` 打开），不匹配一律 403 并提示配置方法；插件设置页「访问令牌」填同一值即可，悬浮球与控制台自动带头。未设置该环境变量时行为逐字节不变（向后兼容）。

安全口径：桥接只监听 127.0.0.1 并校验 Host/Origin（只放行浏览器插件与本机同源页面），不带 CORS 放行头——跨源网页拿不到任何响应；**不要把 8317 端口转发到公网**（必须跨机时启用上述 token）。安装细节、功能与工具对照表、常见问题见《extension/README.md》。
