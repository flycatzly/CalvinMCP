## 快速命令索引（速查）

```powershell
# 安装 / 修复（自动建目录 + 装依赖 + 自检 + 打印注册 JSON + 装技能）
node install.mjs
# 只装依赖（发布包不含 node_modules，依赖由命令生成）
cd mcp; npm ci --no-audit --no-fund
# 环境自检（浏览器 / playwright / 目录）
node mcp\server.mjs --doctor
# 全链路自检（7 套 387 项；支持按套件过滤：node selftest.mjs unit e2e）
cd mcp; node selftest.mjs
# 命令行跑流程
node mcp\runner.mjs list
node mcp\runner.mjs run 订单日报导出 --params 日期=2026-09-30
node mcp\runner.mjs status --problems    # 总览；有问题时退出码 1（可直接接告警）
```

## 你要做的只有 3 步

```powershell
# 1) 放到任意目录（放技能目录则客户端可自动发现）
Copy-Item -Recurse -Force "D:\path\to\web-rpa-mcp" "$env:USERPROFILE\.agents\skills\web-rpa-mcp"
cd "$env:USERPROFILE\.agents\skills\web-rpa-mcp"

# 2) 跑安装器（依赖缺失会自动 npm install，需联网；内网加 --registry=https://registry.npmmirror.com）
node install.mjs

# 3) 注册并重启 MCP 客户端（安装器会打印注册 JSON，复制进客户端配置即可）
```

```json
{ "mcpServers": { "webrpa": { "command": "node", "args": ["<项目目录>\\web-rpa-mcp\\mcp\\server.mjs"] } } }
```

看到这行就算成功：

```text
=== [6] 运行自检 ===
总计: 107 passed, 0 failed
```

## 纯净包口径

本包按「**零预装依赖、不带任何 `.` 前缀文件/目录、不带凭据与生成物**」分发：

| 不在包里 | 谁来生成 |
|---|---|
| `mcp\node_modules\` | `install.mjs` 自动 `npm install`（或手工 `cd mcp; npm ci`）**命令生成** |
| `.gitignore` | `install.mjs` 自动生成（保护 `.work\`、`runs\` 等敏感路径不入 git） |
| `web-rpa.config.json` | `install.mjs` 生成默认配置（含 Webhook 时用 `notify_config` 填写） |
| `runs\` `logs\` `.work\` | 运行时生成（`.work\` 含密钥/登录态 profile，**等同凭据，绝不外传**） |
| `mcp-register.example.json` | 装机时按当前机器路径重新生成 |

## 出问题先看这几条

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| `doctor` 报 playwright 不可用 | 依赖没装 | `cd mcp; npm install`（内网加 `--registry=https://registry.npmmirror.com`）|
| 录制时浏览器窗口没出现 | 浏览器损坏/没装 | `doctor` 看 `browser` 字段；`npx playwright install chromium` 或设 `browser.channel="msedge"` |
| 客户端里没有 `webrpa` | 没重启或没注册 | 完全退出客户端再启动；核对注册 JSON 里的绝对路径 |
| 定时没跑 | 任务计划被禁/路径变了 | `node mcp\runner.mjs list` 看流程；`schedule_run_now` 手工触发后 `run_history` 查结果 |
| 流程报"正在执行中"但没在跑 | 上次执行被强杀，锁没释放 | `lock_status` 确认后 `lock_release` |
| 录错了 / 删错了 | — | 任何改动/删除前自动有备份：`flow_restore` 回滚，**误删也能找回** |

> 更细的排查见 `workflows\排障与自愈.md` 与同目录《部署说明.详细版.md》第七节。
> 真实卡住时发这三样最快定位：`node install.mjs` 完整输出、`node mcp\server.mjs --doctor` 输出、报错原文（**截图/日志注意脱敏**）。

**v1.5.10**：MCP 结果结构化透出——`structuredContent` 纯增量（契约兼容：成功结果多一真字段，`content` 回退保留、失败 `isError:true` 形状不变）+ `outputSchema` 标「待确认」按最小化改动延后（跨协议版客户端兼容不可实测 + 44 schema 臆造风险）。自检 387 项全绿（24 协议，新增 2）。
**v1.5.9**：真实探针修复「误报连续失败」缺陷 + totalRuns 真值优化。① `status_report` 的连续失败此前把 running（进行中未定论）/interrupted（崩溃另计）也当一次失败累加：上一次 pass + 当前还在跑误报连续失败 1（应 0）、2 失败 + 1 崩溃报 3（应 2）；现只数已定论的失败（fail/blocked），pass 即止，running/interrupted 不计失败也不打断。② totalRuns 此前被 listRuns(100) 封顶、超 100 次恒报 100；现单遍枚举给真实运行总数，不再封顶。③ `status_report` 工具描述同步，明确 totalRuns=真实总数、consecutiveFailures 只数已定论失败。自检 385 项全绿（130 集成，新增 3）。
**v1.5.8**：两轮收口合并——告警链路可信性 + 真实浏览器全流程实测修复。① 告警链路可信性收口（5 处"失败链路最后一环说谎/失踪"）：4xx 拒绝不谎报"已发送"（此前 notify_test 配错 webhook 也报 ✅；现如实 sent:false + permanent，不重试不入箱）；发件箱毒条目（永久拒绝）移出记 alerts.log dead-letter、后续继续补发（此前被当发送成功静默丢弃）；发件箱滞留可见：status_report summary 增 notifyOutbox/最旧时长、最旧 ≥24h 判 error 点名，doctor 带年龄；坏发件箱文件改名 .corrupt-* 备份不灭迹；补发失败不重复入箱（noQueue）。② runs_prune 显式单维度语义修复（真实缺陷）：只传 keepCount 或 keepDays 之一时另一维度此前被配置值（keepRunsPerFlow/keepRunDays）并进 AND 双约束，`{keepCount:1}` 在 keepRunDays=30 下一条不删、静默空跑；现显式单维度独立生效（单传 keepCount=留最新 N 次删其余、单传 keepDays=留 N 天内、双传=AND、都不传=按配置双约束），工具与参数描述同步写明四种组合。③ profile_info 提示语诚实化：persistProfile 已开但登录态目录为空时明确提示"还没有内容：先用 profile_login 登录一次"。自检 382 项全绿（107 单元 + 27 规则 + 22 协议 + 65 工具 + 34 端到端 + 127 集成；新增 6 项集成用例 = 5 告警链路 + 1 prune 单维度，另修正 1 项错误断言）。
