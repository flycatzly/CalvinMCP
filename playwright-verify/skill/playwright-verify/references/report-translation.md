# 结果回译

这个文件回答一个判断题：**这份报告是给机器看的，还是给人看的？同事看完能不能直接决定下一步？**

同事要的是「通过 / 没通过 + 为什么」，不是 `Error: expect(received).toBe(expected)`。对应工具 `summarize_report` 的人读渲染（结论 + 证据 + 下一步），以及 `run_verify` 的落盘日志与截图。

---

## 1. 回译模板 = 结论 + 证据（截图）+ 下一步建议

三段结构，缺一段就不算回译完：

| 段 | 内容 | 反面例子 |
| --- | --- | --- |
| **结论** | 一句话说清通过还是没通过，逐项列出关键步骤的结果 | 「跑完了，有 2 个失败」 |
| **证据** | 附对应步骤的截图 / trace / 报告路径 | 只贴一段 `Error: expect(received)...` |
| **下一步建议** | 主动给出一个可接着跑的对照场景 | 「你看看日志」 |

```bash
# 跑完回归：把 JSON 报告转成归因与派活（机器读）
node scripts/summarize_report.mjs test-results/report.json

# 人读版：结论 + 证据 + 下一步
# summarize_report 的 formatText() 就是按这三段渲染的
```

## 2. 回译范例（可直接照抄的格式）

```
已按你的场景跑完 ✅
· 登录 test / 账号 u1：成功
· 下单 SKU_A、加购、去结算：均成功
· 订单金额校验：通过（实读 ¥99.00，预期 ¥99.00）
四步截图已附，需要我接着跑「用优惠券后金额」的对照吗？
```

这份回译里每一行都在做同一件事：**把断言翻译成业务事实**。

- 「登录 test / 账号 u1：成功」——把「用了哪个环境、哪个账号」写在结论里，读者不用去翻配置（账号口径见 `env-and-accounts.md`）。
- 「订单金额校验：通过（实读 ¥99.00，预期 ¥99.00）」——**把实测值与预期值并列写出**。这是回译的关键动作：只写「通过」读者无法复核，只写 `Expected: ¥89.10 / Received: ¥99.00` 读者看不懂，两值并列才既可读又可核。
- 「四步截图已附」——证据具体到步骤数，截图落在 `.playwright-artifacts/screenshots/`，路径随报告一起给出。
- 失败时的写法遵循同一模板，把最后一句换成归因与建议：「订单金额校验：不通过（实读 ¥109.00，预期 ¥99.00），trace 与截图已附；已判定为断言未成立，需要你确认是页面错了还是预期值该改，见 `flaky-triage.md` 的 `assertion` 类。」**注意：这类失败必须人判，不允许自动放宽断言。**

---

## 3. 最后那句「下一步建议」是对话式入口独有的好处

「需要我接着跑『用优惠券后金额』的对照吗？」——这句话不是客套，它是这套流程与「跑个脚本发个报告」的根本差别。

**验证往往不是一次性的。** 同事看完结论，自然会说「那再跑个优惠券的」；Skill 接着接住，一轮对话就把第二个场景跑完，人不用重新排队找人、不用等下一个迭代窗口。而如果一个工具只输出一份报告，流程就断在这里：同事要做对照实验，得重新提需求、重新等人排期。

具体好在三处：

1. **省一轮沟通。** 对照场景通常是「刚验证过的路径 + 一个变量」，出结论的人最清楚该跑哪个对照，顺手提出来即可。
2. **承接后续成本最低。** 页面已经打开、状态已经就绪（`.playwright-artifacts/state/` 里有登录态），跑第二个场景几乎是连续的——比从零开始一次新验证便宜得多。
3. **把「验证」变成可迭代的对话，而不是一次交付。** 同事可以连续追问「那 SKU_B 呢」「那失败重试呢」，每一轮都拿到「结论 + 证据 + 下一步」。

一句提醒：提出下一步建议时，**不要替同事决定业务判断**。可以建议「跑优惠券的对照」，不可以建议「把预期值改成 ¥109.00」——后者是用例缺陷还是产品回归，必须人判（`flaky-triage.md` 的 `assertion` 类）。

---

## 4. 评审检查点

1. 结论里**有没有说清环境和账号**（如「test / u1」）？没有 → 同事无法复核。
2. 通过项**有没有写出实测值与预期值**？只写「通过」等于没回译。
3. 失败项**有没有附截图/trace 的具体路径**？没有 → 同事看完仍会来找人确认，封装就白做了（这正是 CFG007 要拦的）。
4. 失败项**有没有给出归属方与下一步**，且没有自动放宽断言？
5. 结尾**有没有一个可接着跑的对照建议**？
6. 全文**有没有出现无法翻译的机器语言**（`expect(received)`、堆栈、`strict mode violation`）？出现就必须翻译成业务事实，原始信息放进附录或 artifact 路径里，而不是塞进结论。
