# playwright-verify MCP / Skill 部署说明

> **v1.8.15** · 14 个 MCP 工具 + 1 个 Skill · 13 套件 686 断言（含真实浏览器矩阵）· 版本记录见 README「版本记录」

纯净发布包（剔除开发机残留，**无 `node_modules`、无 `.` 前缀文件/目录**），解压 / 拷贝即可部署。零 npm 依赖——不需要 `npm install`、不需要联网、不需要生成任何依赖。

详细版（DSH 部署、全部客户端注册、CI 集成、配置项与环境变量、升级回滚、完整排障）见 [部署说明.详细版.md](./部署说明.详细版.md)。

## 快速命令索引（速查）

```powershell
# 安装（环境检查 → 装 Skill → 生成 DSH bundle → 注册 MCP 客户端 → 自检）
node skill\playwright-verify\install.mjs
# 只看将要写入的配置，不写任何文件
node skill\playwright-verify\install.mjs --print-config
# 环境自检（必需项必须全过；可选项缺什么逐条说明）
node skill\playwright-verify\scripts\selfcheck.mjs
# 全量回归（13 套件 595 断言；--with-browser 加真实浏览器矩阵）
node mcp\test\verify-all.mjs --with-browser
# 三条门禁命令
node skill\playwright-verify\scripts\check_config.mjs playwright.config.ts
node skill\playwright-verify\scripts\lint_spec.mjs tests/
node skill\playwright-verify\scripts\summarize_report.mjs test-results/report.json
# 观测日志一页摘要（调用量/成功率/延迟分布/错误分布；--json 给机器）
node skill\playwright-verify\scripts\log_summary.mjs $env:PVMCP_LOG
# 卸载（只移除客户端注册项）
node skill\playwright-verify\install.mjs --uninstall
```

## 你要做的只有 3 步

```powershell
# 1) 把 mcp\ 整个目录拷到本机任意路径（解压即部署；无 . 前缀目录、无 node_modules）
Copy-Item -Recurse "D:\path\to\发布版本\mcp" "D:\playwright-verify-mcp"
cd "D:\playwright-verify-mcp"

# 2) 跑安装器（环境检查 + 装 Skill + 生成 DSH bundle + 注册客户端，改配置前自动备份）
node skill\playwright-verify\install.mjs

# 3) 重启 MCP 客户端 / 重新加载 DSH 配置，完成
```

注册片段（安装器输出的同款）：

```json
{ "mcpServers": { "playwright-verify": { "command": "node", "args": ["<项目目录>\\mcp\\server.mjs"] } } }
```

看到这行就算成功：

```text

```

## 纯净包契约

| 不在包里 | 谁来生成 |
|---|---|
| `node_modules\` | 不需要 —— 本包零 npm 依赖，任何环节都不用 `npm install` / `npm ci` |
| `.gitignore` `.gitattributes` `.github\` | 不随包（版本控制基础设施，属开发机残留） |
| `.playwright\cli.config.json` | `install.mjs` 按目标机器生成（Windows→msedge，其余→chromium） |
| `.playwright-artifacts\` `.playwright-cli\` | 运行时生成（快照 / 截图 / 报告证据） |
| `dsh-bundle\` | `install.mjs` 生成 |

## 可选依赖（只有执行层需要，不是部署步骤）

| 依赖 | 谁来提供 | 缺了会怎样 |
|---|---|---|
| `@playwright/test` | 被测项目（`npm i -D @playwright/test`） | 只有 `run_verify` 与真实回归不可用 |
| `@playwright/cli` | 本机（`npm i -g @playwright/cli@latest` + `playwright-cli install`） | `cli_health` / `cli_session` 与智能体线执行层（`nl_test_goal` 真执行、`explore_page`）不可用 |
| 浏览器（Edge / Chrome / Chromium 任一） | 系统已有即可 | 归成 `env` 归因并给出修法 |

**部署本工具不需要以上任何一项** —— 门禁 / 体检 / 归因 / 生成 / 智能体规划照常可用（LLM 也是可选项，默认本地 Ollama、云端显式开）。`selfcheck` 会把可选项缺什么逐条列出来。

## 出问题先看这几条

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 客户端里没有工具 | 没重启 / 路径不是绝对路径 | 完全退出客户端再启动；核对注册 JSON 里的绝对路径 |
| `run_verify` 说找不到 Playwright | 被测项目没装测试依赖 | 在被测项目执行 `npm i -D @playwright/test && npx playwright install chromium` |
| `cli_health` 报浏览器找不到 | 通道配置跟机器不符 | 重跑 `install.mjs`，或 `node skill\playwright-verify\scripts\setup-cli-config.mjs` |
| 智能体线执行报 CLI 缺失 | 没装 `@playwright/cli` | `npm i -g @playwright/cli@latest` + `playwright-cli install` |
| LLM 规划走了降级骨架 | 没配 LLM（正常）或超时 | 配 `OLLAMA_*`（本地）或 `PVMCP_LLM=deepseek` + `DEEPSEEK_API_KEY`（显式开云端） |

> 更细的排查见同目录《部署说明.详细版.md》第 12 节。
> 真实卡住时发这三样最快定位：`install.mjs` 完整输出、`selfcheck.mjs` 输出、报错原文（**截图/日志注意脱敏**）。

部署完成后对 AI 助手说人话即可（完整说法库见 [README「自然语言使用示例」](./README.md#自然语言使用示例)；全工具逐条示例见 [部署说明.详细版 §14](./部署说明.详细版.md#14-部署完成后自然语言使用示例)）：
