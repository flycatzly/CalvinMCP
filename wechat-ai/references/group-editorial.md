# 群聊编辑规则

wai_group_daily 产出的是**机器初筛 + 语义编辑素材包（editorial packet）**，不是最终日报。必须读取同一轮报告目录里的编辑包，做第二遍语义编辑，最终交付两份文件：

- group_daily_topics.md —— 话题日报（跨群，按真实项目/事件组织）
- group_daily_groups.md —— 重点群聊（按群追溯上下文）

group_daily_brief.md 只作旧版兼容入口，不再是群聊交付。两份文件分开写，不用 HTML 的 details/summary 塞进 Markdown。

## 1. 输入：编辑包

- 位置：wai_group_daily 的返回里 files.editorialPacket 指向的 JSON（同一轮报告目录内）。
- 内容：已完成时间过滤、去重与候选筛查的会话与消息；每个群的候选主题、发言人、时间、链接与低价值标记。
- 原则：**第二遍编辑不重新扫描微信**。需要补充上下文时回到编辑包里的证据，必要时才用 wai_chat_history 定向取证。
- 附件在编辑包里只是占位符：**未读取的附件必须标注「附件待核实」**，不得根据上下文补全其内容。

## 2. 输出一：group_daily_topics.md

固定骨架：

1. 标题：# 话题日报
2. 时间窗口、数据截止时间、覆盖群数与缺口。
3. ## 今天最重要的事：最多 5 项，按可行动价值排序。
4. ## 大家主要在聊什么：3–6 个真实项目、事件、问题或争议；同一事件跨群合并。
5. ## 商单、培训与合作：写清项目、联系人/可达路径、阶段、证据等级与下一步。
6. ## 今天可以不看：只总结需要明确排除的噪声类型，不逐群点名凑篇幅。

写作要求：

- **话题标题必须点名真实项目、产品、事件或问题**，例如「某产品新一轮集中投放」「某地水利 AI 项目开始收窄场景」。
- 禁止用规则标签充当话题：「AI 产品/模型」「内容增长/自媒体」「商单信息」「行业动态」都不合格。
- 每个话题写清：发生了什么、涉及哪些群和人、各群分别提供了什么增量信息、为什么值得关注。
- 热议主题是扫读标签，不代表自动提升优先级；只有具体事件、决定、需求、变化或机会才进入正文。

## 3. 输出二：group_daily_groups.md

固定骨架：

1. 标题：# 重点群聊
2. 只收录有明确信息增量、商业/决策价值或与用户目标直接相关的群。
3. 每个群用普通 Markdown `## 群名` 标题，不使用原始 HTML。
4. 群下固定回答四件事：发生了什么、已有结论/分歧、与用户有什么关系、是否需要行动。
5. 代表证据就地保留，格式 [群名｜时间｜发言人]；必要原链接在相关项下只出现一次。

群首句必须是一句可判断的**编辑结论**（这个窗口里主要发生了什么，对用户是行动项、值得关注还是背景动态），不是「本群共 328 条消息」。

## 4. 事实分层与不确定

| 层 | 写法 | 例子 |
| --- | --- | --- |
| 原始发言 | 直接引用短句，注明发言人 | 「[群A｜08-01 15:20｜小李] 预算 3–5k，08-05 前要初稿」 |
| 可验证事实 | 可由原文直接核对的结论 | 「该群本窗口出现 2 次同名产品链接」 |
| 编辑判断 | 明确标「判断」「推测」 | 「判断：这是同一轮投放的第二批名额」 |

- 有不确定性就写「待核实」，不把推断写成已确定。
- 讨论零散、没有结论时明确写「尚未形成结论」，不要硬编一个主题。

## 5. 去重与归因

- 跨群链接按同一标准化 URL 或同一推广轮次合并；在话题或商单雷达区**只展示一次**，并列出出现群。
- 同一主题在多个群出现时合并成一张话题卡，说明各群增量。
- 分别标记原始发布者、转发者、中间人、品牌联系人与纯加热者；不要仅凭昵称推断品牌归属。
- **红包、三连/四连、求加热、已加热、截图结算只进跨群投放雷达**，不作为话题、重点群聊或行动项。只有同条消息同时出现明确品牌/项目、招募、预算、名额、brief 或截止时间时，才保留其实质合作内容。

## 6. 必须分开的两件事

- **低价值娱乐/闲聊**：群名或讨论内容确实以生活、运动、娱乐为主，且没有当前目标信号。
- **本时段无信息**：该群在本窗口内没有可读消息或没有增量信息。

后者只能标为「窗口内信息不足」，**不得据此永久降级整个群**。低价值群也不因消息量大、出现金额或出现「推广」字样就升级为商单。

## 7. 群内已有日报的处理

- 群里已有的文字或图片日报只进入独立的「群内已有日报」索引。
- 不复述它的结论，不用它支撑主题、商机或行动项；需要看原文时把它当作返回原群的索引。
- 文字日报按标题识别；图片日报按用户 Profile 中配置的日报发送人线索识别（本项目不自动识别图片内容）。

## 8. 私聊边界

- 私聊联系人不进入群聊日报；品牌方、中间人与自媒体博主的待回复与回复方向由 wai_contact_daily 单独交付。
- 复合日报的 HTML 可以把两者放在同一阅读器的不同栏目，但不得把私聊逐条塞进群聊栏目。

## 9. 下一步与模板句

- 每个商业机会写清：机会是什么、与用户有什么关系、证据等级、可联系的人、下一步；缺一项就标待核实。
- 不使用「可能和你有关」「建议确认价格排期」这类通用模板；下一步必须来自证据与个人 Profile。
- 每个事实项在句末附紧凑来源 [群名｜时间｜发言人]。

## 10. 验收标准

- [ ] 两份文件都已生成，且各自能独立阅读。
- [ ] 话题标题点名具体项目/事件，没有规则标签式标题。
- [ ] 每个重点群有编辑结论 + 四问回答。
- [ ] 未读附件全部标注「附件待核实」。
- [ ] 红包与接龙只出现在雷达区。
- [ ] 同一链接全篇只出现一次。
- [ ] 「低价值娱乐」与「本时段无信息」分开写。
- [ ] 正文没有 HTML 折叠标签，每份正文约 600–1200 汉字（重大事项多时可适度增加，不靠删证据压缩）。

## 11. 话题卡写法模板

     ## 某产品新一轮集中投放

    - 判断：这是一轮有预算的新品投放，用户在可接名单内。
    - 发生了什么：3 个群在 24 小时内出现同一批物料；其中 1 个群给出预算区间与交付时间。
    - 各群增量：
      - [商单群A｜08-01 10:02｜中间人老周] 给出预算 3–5k 与 08-05 初稿时间。
      - [品牌对接群B｜08-01 11:40｜品牌小李] 确认需要竖版素材，未提金额。
      - [资源群C｜08-01 14:10｜博主阿K] 转发同一条链接，无预算信息（加热者）。
    - 与用户的关系：用户是该品类创作者，去年接过同品牌一次。
    - 下一步：向老周确认名额与发布时间；金额待用户确认。
    - 待核实：群B 提到的素材规格只在附件里，附件未读取。

模板纪律：先判断、再事实、再增量、最后下一步；每一条事实都带来源；不确定的单独列出。

## 12. 价值矩阵与筛选视图

- 价值矩阵（group_selection_matrix）覆盖本时间窗内**全部活跃群**，不只是进入正文的群；维度至少包括活跃度、AI、赚钱、培训、商单、出海、产品、Web3、自媒体运营与增长、合作、B 端 AI 赋能。
- 五种标记：重点 / 雷达观察 / 关注 / 低优先级 / 排除候选。前两种与后两种的差别在于「是否有增量信息」而不是「消息多不多」。
- HTML 的「群聊筛选」视图提供搜索、按维度过滤与标记调整，但**浏览器里的选择只保存在本地**；不得自动写入 Profile 或排除名单，必须由用户确认后才更新个人配置。
- 筛选基准读取最新的人生计划或 Profile；没有个人上下文时用公开默认维度，并在报告里说明这是默认口径。

## 13. 与旗舰 HTML 的衔接

- 两份 Markdown 是交付主体；HTML 是阅读器，不替代正文。
- 渲染顺序：先完成话题日报与重点群聊的语义编辑，再对整轮报告目录执行 wai_render_bundle。
- HTML 的群聊页内切换「话题日报 / 重点群聊 / 群聊筛选」三种视图；Markdown 始终保持干净的分区正文。
- 证据附录、机器初筛与 CSV/JSON 留在本地供审计，不出现在阅读导航里。
- 需要单独把某份 Markdown 变成网页时用 wai_render_html；不要在 Markdown 里内嵌原始 HTML 折叠块来模拟交互。
