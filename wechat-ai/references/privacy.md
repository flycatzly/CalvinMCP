# 隐私、脱敏与发布门禁

微信记录包含联系人身份、商业条款、报价与私人对话。本文件规定哪些数据永远不出本机、报告里怎么写、发布前要跑什么。

## 1. 三条原则

1. **原始数据只留本机**：聊天原文、附件、联系人、索引、报告都保存在用户自己的机器上。
2. **最小必要**：报告里只保留支撑结论的短引与必要字段，不做全文倾倒。
3. **可核查但不可识别**：对外产物保留「何时、何角色、说了什么类型的话」，去掉可直接识别个人的标识。

## 2. 永不外传的内容

- 不得发送给外部搜索、云端研究服务、issue、群聊、第三方接口或模型服务。
- 不得把聊天原文作为调试信息打印或写入日志。
- 不得把附件本体（图片、文件）复制到项目目录之外的共享位置。
- 不得在回答里粘贴大段原始聊天；需要上下文时用 wai_chat_history 定向取证并只引用必要片段。

## 3. 禁止入 git 的清单

以下内容一律不进入版本库（应保持在忽略清单中）：

| 类别 | 例子 |
| --- | --- |
| 个人配置 | Profile（本人昵称、标签、文档路径）、微信流场景与目标中的本地路径 |
| 数据副本 | 数据库快照、导出目录、Inbox 条目与其附件 |
| 索引与缓存 | 本地索引文件、解析缓存、运行日志 |
| 报告产物 | 输出目录下的任何 Markdown/HTML/CSV/JSON |
| 识别信息 | 真实 wxid、群 ID、手机号、邮箱、身份证、地址 |
| 凭据 | 密钥、口令、token、API key、cookie、会话串 |
| 第三方材料 | 未经授权的导出文件、附件、他人聊天记录 |

## 4. wai_privacy_scan 的扫描模式

wai_privacy_scan 是发布门禁，检查目录里是否残留真实微信 ID、群 ID、私钥与口令。

| 模式 | root 取值 | 用途 |
| --- | --- | --- |
| 包目录扫描（默认） | 不传 root | 提交代码或打包前，确认仓库里没有真实数据与凭据 |
| 输出目录扫描 | root: "<输出目录>" | 分享报告前，确认产物里没有可识别信息 |
| 任意目录扫描 | root: "<自定义路径>" | 排查某个可疑目录（例如误放的导出文件） |

使用方式：

1. 生成分享物之后、发送之前调用一次。
2. 返回不通过时，按发现项逐条处理：删除、脱敏或改为角色化表述。
3. 处理完再跑一次，直到通过。
4. wai_doctor 也会跑包目录扫描；它报 privacy_scan_failed 时同样必须先处理。

不要为了让扫描通过而排除整个目录或跳过检查；扫描失败说明确实有问题。

## 5. 脱敏规则

| 场景 | 不写 | 改写为 |
| --- | --- | --- |
| 引用证据 | 真实昵称 + 头像 + 微信号 | 角色 + 时间：「8 月 1 日，中间人在商单群提到预算区间」 |
| 群名 | 包含公司或项目的完整群名（对外时） | 「某品牌对接群」 |
| 金额 | 未经确认的具体数字 | 「预算区间为四位数（待确认）」 |
| 链接 | 带追踪参数的原始链接（对外时） | 归一化后的链接，或只写平台与主题 |
| 附件 | 附件本体与绝对路径 | 「附件未读取，内容待核实」 |
| 索引计数 | 精确到个位的消息量（对外时） | 量级描述 |

对内（只给用户本人看）可以保留会话名与时间，因为用户本来就有这些信息；但只要产物准备发给别人，就按上表重写。

## 6. 分享前检查清单

- [ ] 已运行 wai_privacy_scan 并通过。
- [ ] 产物内没有 wxid、群 ID、手机号、邮箱、密钥、token。
- [ ] 附件没有被一起打包；如必须包含，已确认无隐私内容。
- [ ] 引用已改成「角色 + 时间」，没有第三方昵称。
- [ ] 与本轮问题无关的聊天原文已删除。
- [ ] 报告路径指向的是本机目录，不是共享盘或同步目录。

## 7. 维护类工具

| 工具 | 默认行为 | 说明 |
| --- | --- | --- |
| wai_cleanup | 只预览 | 清理历史报告与原始 JSON/JSONL；rawDays 默认 7、reportDays 默认 30 |
| wai_inbox_maintain | 只预览 | 清理过期 Inbox 条目，days 默认 30 |
| wai_config_get | 只读 | 返回配置，但不含任何凭据 |
| wai_report_list | 只读 | 找回历史报告目录 |

## 8. 谁能看到什么

| 角色 | 能看到 | 不能看到 |
| --- | --- | --- |
| 用户本人 | 全部本机数据与报告 | —— |
| 调用本 MCP 的 Agent | 工具返回的结构化结果（含必要聊天片段） | 微信写权限、凭据、其他机器的数据 |
| 目标 Agent（转发/投递） | 用户选中的内容与提示词 | 索引全量、Profile、其他会话 |
| 报告接收者 | 脱敏后的产物 | 原始聊天、附件、索引 |

默认隐私设置：redactOutputs 为 true（输出脱敏）、blockInsideRepo 为 true（阻止把敏感产物写进仓库目录）。这两项不建议关闭。

## 9. 数据分级

| 级别 | 内容 | 处理要求 |
| --- | --- | --- |
| 公开 | 用户自己公开发布的内容（公众号、公开帖） | 可引用，注明来源链接 |
| 内部 | 用户自己的计划、Profile、报告 | 只留本机，不进版本库 |
| 敏感 | 聊天原文、联系人、群成员、报价与条款 | 只留本机，最小引用，不外发 |
| 机密 | 密钥、口令、token、身份证明、付款信息 | 本项目不采集、不存储、不展示 |

出现机密级内容时（例如聊天里有人发了口令或身份证照片），正确处理是：**不复制、不引用、不索引到报告**，只在报告里写「该会话出现敏感信息，已跳过」。

## 10. 日志与调试

- 日志只记录状态、计数、耗时与错误类型；不记录聊天原文、附件内容、密钥候选。
- 调试时不要打印完整工具返回；需要片段时人工挑选最小必要部分。
- 把问题反馈给他人时，用虚构数据复现，不要把真实会话贴进 issue 或群聊。
- 演示与回归统一使用 mock 数据源（虚构），不要用真实数据截图。

## 11. 凭据处理的明确禁止

- 不读取、不推导、不猜测、不缓存数据库密钥。
- 不保存任何 token、cookie、API key；不把它们写进配置文件或报告。
- 用户主动提供凭据时：拒绝使用并解释原因（本项目只读已解密副本），建议改用 Inbox 或导出目录通道。
- 配置文件（wai_config_get 可见的部分）不应包含任何凭据字段；发现时说明并建议删除。

## 12. 数据生命周期

| 阶段 | 位置 | 保留策略 |
| --- | --- | --- |
| 采集 | Inbox（本机） | 默认 30 天后可清理（wai_inbox_maintain 先预览） |
| 索引 | 本地索引库 | 可随时重建；换机器需要重新建 |
| 报告 | 输出目录 | 默认保留 30 天；原始 JSON/JSONL 保留 7 天 |
| 归档 | 用户自选的 Obsidian vault 或文件夹 | 由用户自行管理，本项目不自动同步 |
| 分享物 | 用户指定的位置 | 生成后应立即跑隐私门禁，确认无残留 |

## 13. 责任边界

- 用户对「是否有权处理这些聊天记录」负责；本项目只提供本机只读工具。
- 涉及第三方（同事、客户、合作方）的信息，未经同意不得对外发布或用在他处。
- 把内容转发给另一个 Agent 时，等于把该内容交给你信任的那台机器与那个模型；请确认这一点后再投递。
- 本文件的规则优先于「用户想快点拿到结果」的临时诉求：宁可少写一条证据，也不要多泄露一个身份。
