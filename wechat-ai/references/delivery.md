# 交付形态与产物

交付形态由请求规模决定，不由「用了技能」决定。默认 delivery=auto；本文件说明怎么选、产物放哪、哪些东西不该给用户看。

## 1. 五种形态

| 形态 | 行为 | 适用 |
| --- | --- | --- |
| text | 只在当前回答里交付，不保存文件 | 单点问答、是否需要回、一条草稿 |
| md | 回答给行动摘要，同时保存最终 Markdown | 中等规模、需要后续复用 |
| html | 先生成各模块最终 Markdown，再从本轮报告目录生成旗舰交互 HTML | 正式日报/周报/月报/指定区间 |
| all | Markdown、HTML、结构化文件与证据附录都保留 | 规则调试、漏报复核、开源回归 |
| auto | 按对象数量、时间跨度、是否需要复用与交互浏览自动选择 | 默认 |

## 2. auto 的判定表

| 请求 | 默认交付 |
| --- | --- |
| 单个联系人最新回复、是否需要回、回复草稿 | text（直接回答） |
| 单一品牌、项目、关键词、事件，对象 ≤ 5 个 | text；需要留档才落 Markdown |
| 6–15 个对象、跨多群归因、需要后续复用 | md |
| 正式多会话日报、周报、月报、指定时间段报告 | html（同时保留分区 Markdown） |
| 跨多会话的联系人/标签/项目/事件调查 | md；明确需要交互浏览时用 html |
| 大范围报告且用户需要搜索、筛选、点击展开 | html |
| 识别规则调试、漏报复核、开源回归 | all |

对象数量只是辅助判断：

- 即使消息很多，只要用户问的是一个明确问题，也优先直接回答。
- 即使对象很少，只要涉及长期决策、持续跟进或需要留档，也可以保存 Markdown。
- 用户明确说「给我个文件」时才落盘；不要用文件代替结论。

## 4. 生成顺序

1. 查新鲜度：wai_db_status；必要时 wai_db_index。
2. 出证据与初筛：wai_group_daily、wai_contact_daily、wai_brief（同一时间窗）。
3. 语义编辑：按 references/group-editorial.md 产出 group_daily_topics.md 与 group_daily_groups.md。
4. 渲染：wai_render_bundle { "reportDir": "...", "out": "...", "title": "..." }。
5. 预览与清理：wai_report_list 确认产物；wai_cleanup 预览后按需清理。

顺序不能颠倒：**没有完成语义编辑就不要渲染 HTML**，否则交付的是机器初筛。

## 5. 旗舰 HTML 的形态

- 四个顶层入口：综合行动报告、群聊日报、重点联系人、商单信号雷达。
- 群聊日报页内切换：话题日报 / 重点群聊 / 群聊筛选。
- 支持全局搜索、分区路由、明暗主题、打印、当前分区 Markdown 下载、原链接跳转。
- 不在 HTML 中单列证据附录与机器审计；只有用户明确要求调试时才把 CSV/JSON 作为主要交付。
- wai_render_html 用于把**单份** Markdown 渲染成安全静态 HTML：白名单净化 + CSP，不依赖 pandoc；不要为了绕过报错而关闭净化或 CSP。

## 6. 不该做的事

- 不为给用户一个文件而扩大扫描范围：交付形式不改变证据边界。
- 不用文件路径代替结论：回答里先给结论，路径放最后一行。
- 不罗列内部 JSON、CSV、appendix 路径。
- 不把机器初筛 HTML 冒充最终日报。
- 不在渲染失败时谎称成功：保留分区 Markdown 并说明 HTML 未生成。

## 7. 验收标准

- [ ] 回答长度与请求规模匹配（一个问题不产出三份报告）。
- [ ] 报告目录里最终产物齐全，中间产物没有被当作交付。
- [ ] 报告路径指向的是当前交付形态对应的文件。
- [ ] HTML（若生成）能被打开、能搜索、能切换分区。
- [ ] 分享前跑过 wai_privacy_scan。

## 8. 报告给谁看

| 读者 | 交付建议 |
| --- | --- |
| 只有用户本人 | 全部产物保留在本机；可以保留证据短引与内部编号 |
| 用户要发给合作方或同事 | 重新生成一份「对外版」：删掉无关会话名、他人隐私、内部候选与推测 |
| 用户要发到公开渠道 | 必须先 wai_privacy_scan；删除真实 wxid、群 ID、手机号、报价细节与他人姓名 |

对外版默认只保留结论、行动与必要的公开信息；证据引用改成角色 + 时间（如「8 月 1 日品牌方在商单群提到预算区间」），不写具体昵称。

## 9. 目录与命名

- 报告目录：输出根目录下的 <kind>-<时间戳>，kind 与工具对应（group-daily、contact-daily、reactivation 等）。
- 时间戳来自运行时刻，不是数据时间；报告正文里写**数据截止时间**。
- 同一窗口重复运行会产生多个目录；用 wai_report_list 找到最新一个，不要手工拼接路径猜测。
- 清理：wai_cleanup 默认保留原始 JSON/JSONL 7 天、报告 30 天，先预览再 apply。

## 10. 部分失败时怎么交付

| 失败 | 交付处理 |
| --- | --- |
| 索引刷新失败 | 用已有索引继续，报告里写数据截止时间与缺口 |
| 某个报告工具 ok:false | 交付其余模块，列出失败模块与 error |
| 附件未读 | 标注「附件待核实」，不阻塞交付 |
| HTML 渲染失败 | 交付分区 Markdown，说明 HTML 未生成 |
| 投递目标未配置 | 交付提示词文件到默认目录，说明目标未启用 |

原则：**部分成功要如实交付**。不要因为一个模块失败就声称整轮失败，也不要隐瞒失败范围。

## 11. 交付与操作记录

- 每次投递都会记录在操作历史里（wai_history_list 可查：动作、目标、标题、字数、成功与否）。
- 同一段内容要发给第二个目标时用 wai_history_rerun，不需要重新抓取或重新推送。
- 批量的投递走 wai_batch_*，逐条状态与失败载荷都可复查。
- 交付记录只在本机：不要把历史记录导出到外部系统。
