# 信号与状态规则

本文件规定 wai_signals / wai_deal_radar / wai_db_links / wai_reactivation / wai_opportunities 背后的判定口径。所有规则的目标只有一个：**把「看起来像机会」和「可以行动的机会」分开**，并让每一条结论都能回到原消息。

## 1. 证据等级

| 等级 | 判定条件 | 是否进今日行动 |
| --- | --- | --- |
| 已确认 | 品牌方/项目方明确邀请；给出 brief、预算、排期；或用户本人已确认真实机会 | 是 |
| 高概率 | 多项强信号互相印证（例如预算 + 名额 + 交付时间），但尚未找到直接对接人或正式需求 | 是（标明还缺什么） |
| 待核实 | 单一转发、模糊口头信息、附件未读取、身份不明确 | 否，进待审核或观察区 |
| 仅供存档 | 普通讨论、行业信息、泛招聘、自然分享，无法转化为下一步 | 否 |

纪律：

- 不得把模型置信度写成事实。每个高概率或待核实项都要写「还缺什么证据」。
- 同一件事的证据等级由最强证据决定，但要在文字里说明依据是哪一条。
- 对话里出现「非商单 / 不是商单 / 纯分享」时是**反证**；只有当同时存在付费加热、预算或结算证据时才可以不采信它。
- 「转发者」不等于「品牌方」。转发是行为，不是身份。

## 2. 商机类型

### 2.1 品牌单（Brand Deal）

强信号：

- 明确寻找 KOL、博主、创作者或账号。
- 出现预算、报价、稿费、佣金、保底、发布时间、brief、审核要求、名额或交付要求。
- 中间人询问谁愿意接某品牌，或要求提交主页、数据与报价。
- 同一推广内容在多个群付费加热、红包互动、三连/四连、截图结算。
- 小型交付群、对接群、初稿/终稿群里的直接商业对话。

反例（不得升级）：

- 只在群里发了一条链接，没有预算/名额/brief/结算。
- 只有红包、点赞、转发、截图等互动协调。
- 别人复盘自己接过的商单。
- 泛泛的「后面有机会联系」。

### 2.2 培训 / 咨询 / 项目合作

强信号：

- 寻找讲师、教练、顾问、课程内容、企业内训、工作坊或项目交付人员。
- 询问主题、大纲、课时、听众、地点、档期、案例、报价或试讲。
- 可信中间人说「有项目」「帮忙提报」「需要某方向老师」，即使没有链接。
- 图片、文件或语音里可能有招募要求，且相邻文本提到合作（附件未读时标待核实）。

反例：普通市场价格讨论、别人复盘培训收入、泛行业闲聊。

**没有链接不是降级理由**：培训、咨询与项目合作常常只出现在自然对话里。

### 2.3 资源引荐（Resource / Referral）

- 能提供品牌联系人、Agency、群入口、项目负责人或转介绍的人属于资源机会。
- 必须写清下一步是「请其引荐」还是「直接联系」。
- 不得把资源提供者写成品牌方；也不得把「认识某人」写成「有预算」。

## 3. 链接与跨群规则

- 同一标准化 URL 在报告中只出现一次，附出现群、最早/最新时间与非加热发布者。
- 纯领红包、点赞、转推、截图的人只算**加热者**，不作为对接候选。
- 首发者、反复组织接龙者、提供 brief/预算者、邀请博主者，才可能是中间人或项目组织者。
- 万粉以上博主参与付费加热，提高「这是推广」的概率，**不提高**「他能直接对接品牌」的概率。
- 不同链接但品牌、产品、发布时间与 brief 高度一致时，可视为同一轮推广；仍需保留各条原始证据。
- 链接参数（追踪参数）要归一化后再判重；同一内容的多条短链视为同一个 URL。

对应工具：wai_db_links（聚合）、wai_signals 的 links（rank > 0 才返回）。

## 4. 角色归属

| 角色 | 特征 | 用法 |
| --- | --- | --- |
| 品牌/项目方 | 代表需求方给出规则、预算或交付要求 | 可以直接确认需求与排期 |
| 中间人 / Agency | 组织招募、收集名单、转交品牌、负责结算 | 主要对接人，问名额与结算口径 |
| 推荐人 | 愿意介绍对接人，但不负责执行 | 请其引荐，不追进度 |
| 自媒体博主 | 参与合作或了解项目 | 可询问来源与报价区间 |
| 加热者 | 只互动或领红包 | 不作为建联对象 |
| 身份待核实 | 只有转发，无法判断角色 | 先核验，不写进对接建议 |

不要仅凭昵称、共同群或一次转发推断品牌归属。涉及交接时用 wai_common_groups 与聊天原文验证。

## 5. 任务状态语义

### 5.1 商机的四层

| 层 | 含义 | 生命周期 |
| --- | --- | --- |
| signal | 单条原始消息或链接证据 | 不直接等于商机 |
| candidate | 由一个或多个信号聚合出的待审核候选 | 默认 14 天无新证据后过期 |
| opportunity | 有明确私聊交付证据，或已经用户人工确认推进 | 唯一持久状态源 |
| stale | 过期候选 | 保留证据，不进入今日行动 |

晋级规则：只有「明确交付证据」或「用户人工确认」才能从 candidate 变成 opportunity；用户说不是商单就写纠正记录并降级，不靠下次扫描自然消失。

### 5.2 任务型状态

| 状态 | 判定 | 关闭条件 |
| --- | --- | --- |
| 待回复 | 对方提出问题、请求确认，或发来需要回应的新信息 | 我方回复后关闭（回复应针对该问题） |
| 待兑现承诺 | 我方已答应发送初稿、报价、大纲、数据、Quote、KOL 名单等 | 只有交付物真正发出才关闭 |
| 等待对方 | 我方已完成当前动作，等预算、brief、审核、排期或结果 | 对方给出结果，或到复查日期 |
| 临近截止 | 已确认的交付或发布时间进入执行窗口 | 交付完成或时间过去 |
| 已发布待数据跟进 | 需要补量、Quote/KOL 扩散、观察数据或在统计窗口回传增量 | 数据回传并确认 |
| 已发布待结算 | 交付与数据义务完成，等待发票、付款或佣金结算 | 款项确认到账 |
| 已收款 | 款项确认到账 | 终态，进入复购保温 |

关键纪律：

- 对方回复「好的 / 嗯嗯 / 收到」只能关闭**待回复**，不能关闭**待兑现承诺**。
- 礼貌性结束语不是任务；泛泛的「后面有机会联系」只生成低优先级复联提醒。
- 「会打款」「已提交结算」不等于「已收款」。
- 等待对方必须带一个建议复查日期，否则不进 wai_today。

## 6. 复联规则

- 后来的发布、结算或新一批邀请，可以覆盖更早的暂停与负面信号。
- 只有品牌方/中间人明确说「下一批、之后联系、后面还有」，才生成下一批窗口。
- 用户自己的期待、第三方猜测、市场传闻都不构成对方承诺。
- 纯佣低优先级是**合作模型**，不是拒绝；不要写成「对方不合作」。
- 我方主动放弃只有在原风险消失后才重新考虑（例如换负责人、换项目类型）。
- 待交接跟进应定位新负责人，而不是继续催离职/转岗的旧负责人。
- 未到跟进日期的对象放入等待区，不挤进立即处理。

对应工具：wai_reactivation 的分档（今天优先看 / 待交接跟进 / 等待区 / 纯佣低优先级 / 我方主动放弃）。上游口径里的「待下一批跟进 / 复购保温」折叠进 今天优先看，「暂缓」即 等待区；带「下一批」信号的会话在返回的 next 字段。

## 7. 日报质量要求

1. 严格使用用户给定的时间窗口；未给出时默认过去 24 小时。
2. 群聊摘要先按会话切分，再按主题归组；不做单条消息的流水式复述。
3. 每个重点讨论段回答：什么时间、主题是什么、围绕什么、为什么值得关注、证据是什么。
4. 商单栏目与培训/咨询/项目栏目分开；活动、招聘/外包与赚钱奖励单独标记，不强行归入商单。
5. 相同内容、链接与同一合作轮次只写一次。
6. 红包加热与重复链接只进入链接聚合区，不在重点讨论区重复。
7. 高活跃不等于高价值；日常闲聊、节日刷屏、互动接龙只统计或省略。
8. 建议必须是针对当前用户的具体下一步（找谁、问什么、何时跟进），不要输出「确认价格、排期、结算方式」这类与证据无关的模板建议。
9. 低价值娱乐与「本时段没有信息」分开写，后者不得用于永久降级某个群。
10. 覆盖范围、数据截止时间与缺口写在最前面。
