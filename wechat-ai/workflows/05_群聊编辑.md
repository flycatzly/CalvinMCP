# 工作流 05：群聊编辑

## 适用场景

- 要出一份「人能读」的微信群聊日报，而不是机器初筛。
- 群多、消息多，需要先跨群归纳话题，再按群追溯。
- 需要判断哪些群值得看、哪些只是噪声。

## 前置条件

- 已完成工作流 01；有近期群聊数据。
- 已读 references/group-editorial.md（编辑规则）。
- 明确时间窗口。

## 步骤

### 1. 生成机器初筛与编辑包

    wai_group_daily { "hours": 24, "groupLimit": 60, "perGroupLimit": 500, "minLinkChats": 2, "exclude": ["闲聊群"] }

返回要点：

- outDir：本轮报告目录。
- files：digest、appendix、CSV/JSON、跨群链接、群聊价值矩阵，以及 **editorialPacket**（编辑素材包）。
- editorial：第二遍编辑相关的产物。
- topGroups：按优先级排序的群与信号摘要。

### 2. 读取编辑包

打开 files.editorialPacket 指向的 JSON（同一轮报告目录内）。里面是已完成时间过滤与去重的会话与消息：候选主题、发言人、时间、链接、低价值标记。

**不要重新扫描微信**；需要补充上下文时回到编辑包里的证据，必要时用 wai_chat_history 定向取证。

### 3. 写话题日报 group_daily_topics.md

固定骨架：

1. # 话题日报
2. 时间窗口、数据截止时间、覆盖群数、缺口
3. ## 今天最重要的事（最多 5 项）
4. ## 大家主要在聊什么（3–6 个真实项目/事件/问题）
5. ## 商单、培训与合作
6. ## 今天可以不看

硬性要求：

- 话题标题必须点名真实项目/事件，禁止「AI 产品/模型」「内容增长」这类规则标签。
- 同一事件跨群合并，说明各群增量。
- 每条事实附 [群名｜时间｜发言人]。

### 4. 写重点群聊 group_daily_groups.md

- 只收录有信息增量、商业/决策价值或与用户目标相关的群。
- 每群用 ## 群名 标题；首句是一句可判断的编辑结论。
- 群下固定回答：发生了什么 / 已有结论或分歧 / 与用户的关系 / 是否需要行动。

### 5. 处理边界情况

| 情况 | 处理 |
| --- | --- |
| 附件未读取 | 标注「附件待核实」，不得补全内容 |
| 红包、三连/四连、求加热、截图结算 | 只进跨群投放雷达，不作话题与行动项 |
| 同一链接出现在多个群 | 合并为一条，只展示一次，列出出现群 |
| 群里有别人写的日报 | 只进「群内已有日报」索引，不复述其结论 |
| 群本窗口没有可读消息 | 写「窗口内信息不足」，不永久降级该群 |

### 6. 交付

需要网页阅读时：

    wai_render_bundle { "reportDir": "<outDir>", "title": "微信群聊日报 2026-08-01" }

HTML 的群聊页内可切换「话题日报 / 重点群聊 / 群聊筛选」。浏览器里的筛选与标记只保存在本机，**不得自动写入 Profile 或排除名单**。

## 验收标准

- [ ] group_daily_topics.md 与 group_daily_groups.md 都已生成，可独立阅读。
- [ ] 话题标题点名具体项目/事件。
- [ ] 每个重点群有编辑结论 + 四问回答。
- [ ] 未读附件全部标注「附件待核实」。
- [ ] 红包与接龙只出现在雷达区。
- [ ] 同一链接全篇只出现一次。
- [ ] 「低价值娱乐」与「本时段无信息」分开写。

## 常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 直接把 digest 当成品交付 | 回到编辑包做第二遍语义编辑；digest 只是初筛 |
| 话题全是宽泛标签 | 回到消息里找具体产品名、项目名、事件名重新命名 |
| 群太多写不完 | 只写有增量的群；其余进价值矩阵的「关注/低优先级」 |
| 商机与话题混在一起 | 商机单独成节，写清证据等级与下一步 |
