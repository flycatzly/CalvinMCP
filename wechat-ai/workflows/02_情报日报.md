# 工作流 02：情报日报

## 适用场景

- 「过去 24 小时发生了什么」「昨天群里都聊了什么」。
- 指定区间复盘：某一天、某一周、某个月、明确起止日期。
- 需要一份可以留档、可以交互浏览的日报。

## 前置条件

- 已完成工作流 01（至少一个真实数据源 + 索引非空）。
- 明确时间窗口；未给时默认过去 24 小时。

## 步骤

### 1. 定窗口

| 用户说法 | 参数 |
| --- | --- |
| 最近 / 今天 | 不传时间参数（默认 24 小时） |
| 过去 48 小时 | hours: 48 |
| 昨天 | since: "2026-08-01", until: "2026-08-01" |
| 这周 | week: true |
| 8 月 1 日到 8 月 3 日 | since: "2026-08-01", until: "2026-08-03" |

同一次运行里，所有报告必须用同一组边界。

### 2. 查新鲜度并刷新

    wai_db_status { }
    wai_db_index { "scope": "sessions", "source": "sqlite:D:/wechat/db_storage", "sessionLimit": 120, "perChatLimit": 800, "days": 2 }

数据超过 48 小时、或用户问的是「最新」时必须刷新；刷新失败就继续用已有索引，并在报告里写数据截止时间与缺口。

### 3. 出三份证据

    wai_group_daily { "hours": 24, "groupLimit": 60, "perGroupLimit": 500, "minLinkChats": 2 }
    wai_contact_daily { "hours": 24, "limit": 80, "scope": "hybrid" }
    wai_brief { "hours": 24, "limitChats": 10 }

- wai_group_daily 的返回里有 outDir、files、editorialPacket 与 topGroups。
- wai_contact_daily 返回重点联系人与每个联系人的回复方向。
- wai_brief 返回跨报告的行动总览，并自动与前一个等长窗口对比。

### 4. 语义编辑群聊日报

读取同一轮报告目录里的编辑素材包，按 references/group-editorial.md 生成两份文件：

- group_daily_topics.md（话题日报：今天最重要的事、主要在聊什么、商单/培训/合作、今天可以不看）
- group_daily_groups.md（重点群聊：每个群的编辑结论 + 发生了什么/结论分歧/与我关系/是否需要行动）

不要把机器初筛当作最终日报；不要用规则标签充当话题标题；未读附件标注「附件待核实」。

### 5. 补充商机与链接视角（需要时）

    wai_deal_radar { "hours": 24 }
    wai_db_links { "days": 7, "minChats": 2, "limit": 50 }
    wai_signals { "hours": 24 }

### 6. 渲染交付物

    wai_render_bundle { "reportDir": "<上一步的 outDir>", "title": "微信情报日报 2026-08-01" }

- 旗舰 HTML 只保留四个顶层入口：综合行动报告、群聊日报、重点联系人、商单信号雷达。
- 群聊页内可切换话题日报 / 重点群聊 / 群聊筛选。
- 单份 Markdown 需要网页时用 wai_render_html。

### 7. 输出行动结论

按 SKILL.md 的 Output Contract 顺序写：覆盖范围 → 立即处理（≤10）→ 商单机会 → 培训/咨询/项目合作 → 等待与复联 → 主要话题与事件 → 按群追溯 → 重点联系人私聊 → 报告路径。

## 验收标准

- [ ] 报告窗口、数据截止时间、覆盖会话数与缺口都写了。
- [ ] 立即处理不超过 10 项，且每项有对象、动作、时间与证据。
- [ ] 候选（待审核）与正式机会分栏。
- [ ] 同一链接/同一轮推广只出现一次。
- [ ] 两份群聊 Markdown 已生成，且话题标题点名真实项目或事件。
- [ ] wai_render_bundle 产出的 HTML 可打开、可搜索、可切换分区。
- [ ] 分享前跑过 wai_privacy_scan。

## 常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 某个群没数据 | 写入缺口说明，不要写成「该群没有讨论」 |
| 只有私聊没有群聊 | 照常交付重点联系人部分，并说明群聊覆盖为空的原因 |
| 商单与培训混在一起 | 拆成两个栏目；培训/项目没有链接也要保留 |
| 报告太长 | 压缩低价值群描述，不删证据与行动项 |
| HTML 未生成 | 保留分区 Markdown 并说明；不要退回交付机器初筛 |
