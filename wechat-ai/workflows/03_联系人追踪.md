# 工作流 03：联系人追踪

## 适用场景

- 「我和某人聊到哪了」「我还欠他什么」。
- 「他刚回复我，我该怎么回」。
- 每天/每周固定看重点联系人的推进情况。

## 前置条件

- 索引里有该联系人的私聊记录（必要时先 wai_db_index）。
- Profile 里配置了本人昵称（ownerAliases），否则无法区分「我」和对方，回复草稿会失真。

## 步骤

### 1. 建立联系人档案

    wai_person { "name": "某某", "refresh": true, "limit": 500 }

得到：聊到哪、我方未完成承诺、对方待回应要求、商业相关时间线、最后发送者。

若名字不确定，先用只读入口核验会话名：

    wai_reader { "command": "resolve-chat", "chat": "某某" }

### 2. 看原文证据（关键节点）

    wai_chat_history { "chat": "某某", "limit": 120, "query": "报价" }

只在需要核对事实时定向取证，不做全文倾倒。

### 3. 判断是否需要回复

按 references/reply-style.md 的顺序：

1. 忽略系统消息，看最后一条**对话**消息是谁发的。
2. 最后一条是本人发的 → 默认不追发（除非对方之后又问了）。
3. 对方只是「好的/收到/哈哈」→ 不需要回复。
4. 有明确问题、请求或情绪 → 需要回复，进入第 4 步。

### 4. 生成一条本地草稿

    wai_reply_draft { "name": "某某", "limit": 120, "styleDays": 30, "minimumChatMessages": 5 }

输出形态：

    建议回：
    > 一条可直接发送的短回复

    判断：<关系语域>；<回应什么>；<哪些事实待确认>。

规则：

- 只给**一条**主草稿，通常 1–2 个微信气泡，默认 ≤50 字（以本人滚动样本为准）。
- 事实闸门：金额、日期、交付范围、授权、付款、完成状态必须来自原消息或用户确认；不确定就写「待你确认」。
- 禁用套话（「老师你好，收到」「我会结合前面的上下文」等）。
- **绝不发送**：草稿只留在本机，由用户自己复制发送。

### 5. 批量看重点联系人

    wai_contact_daily { "hours": 24, "limit": 80, "scope": "hybrid", "contacts": [] }

- scope: hybrid（默认）综合重点标签与商业信号；priority_labels_only 只收录重点标签联系人。
- 返回每个联系人的待兑现、待回复、等待对方、留意与回复方向。
- 需要留档时产物写入报告目录（contact_daily_brief.md 等）。

### 6. 把结论写回持久状态

联系人对话里出现的承诺、待结算与合作阶段，不要只留在回答里：

    wai_opportunities { "chat": "某某", "includeCandidates": true }
    wai_opportunity_update { "id": 12, "nextAction": "发报价档位", "followUp": "2026-08-05" }

## 验收标准

- [ ] 档案里明确写出「谁在等谁」「我方欠什么」「下一步是什么」。
- [ ] 需要回复时给了且只给了一条主草稿，并标注待确认事实。
- [ ] 不需要回复时明确给出「不用再回」的结论与理由。
- [ ] 承诺与跟进日期已写入商机管线（若属于合作类）。
- [ ] 全程没有出现「已发送」「定时发送」等表述。

## 常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 找不到联系人 | 用 wai_reader 的 contacts / resolve-chat 核对准确名称后重试 |
| 分不清「我」和对方 | 让用户补 ownerAliases（wai_profile_init），在此之前不要生成模仿语气的草稿 |
| 样本不足 5 条本人消息 | 保持中性草稿并说明「样本不足，未模仿专属语气」 |
| 对方刚回复但内容只是表情 | 判为不需要回复，给出结论即可 |
| 草稿太长 | 按会话证据压缩到 1–2 个气泡，删掉解释性内容 |
