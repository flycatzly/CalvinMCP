# 工作流 08：批量收集

## 适用场景

- 一次选中了多条微信内容（多群片段、多篇文章），想作为一批统一处理。
- 需要看到每一条的处理进度，而不是「一锅端」。
- 部分条目投递失败，需要只重试失败项。

## 前置条件

- 每条内容已经准备好（文本或消息数组）。
- 明确目标（Agent / Obsidian / 剪贴板 / 文件夹 / 自定义）与场景。

## 状态机

pending → staging → ready → delivering → done，失败进 failed（可重试回 pending）。

| 状态 | 含义 |
| --- | --- |
| pending | 已登记，尚未暂存载荷 |
| staging | 原始载荷已写入 items/<index>.json（**永不丢弃**） |
| ready | 可交付 |
| delivering | 正在投递 |
| done | 该条完成 |
| failed | 投递失败，原始载荷保留，可重试 |

批次整体状态由条目聚合：任一条 delivering 则整体 delivering；有 staging 则 staging；全部 done 则 done。

## 步骤

### 1. 建批次

    wai_batch_create {
      "items": [
        { "title": "商单群X 08-01", "chat": "商单群X", "body": "<片段一>" },
        { "title": "项目群Y 08-01", "chat": "项目群Y", "body": "<片段二>" }
      ],
      "source": "clipboard",
      "scene": "deal",
      "target": "codex"
    }

返回批次 id 与初始状态。条目数上限由 settings.batchMaxItems 控制（默认 100）。

### 2. 查看进度

    wai_batch_status { "id": "b_20260801_1015_ab12" }

不给 id 时返回全部批次列表：

    wai_batch_status { }

### 3. 预览投递

    wai_batch_deliver { "id": "b_20260801_1015_ab12", "target": "codex", "dryRun": true }

确认每条的目标路径与提示词无误后再正式投递：

    wai_batch_deliver { "id": "b_20260801_1015_ab12", "target": "codex" }

### 4. 处理失败项

1. wai_batch_status 找到 failed 的条目与其错误。
2. 修正原因（目标未配置、路径不存在、内容为空等）。
3. 重试：失败条目的状态可以回到 pending 再重新进入 staging → ready → delivering。
4. 只重试失败项，不要整批重投（避免重复笔记与重复提示词文件）。

### 5. 收尾

- 检查每条都有终态（done 或 failed），没有卡在 delivering。
- 失败项保留原始载荷，便于人工查看。
- 需要网页阅读或归档时，按工作流 05 / 07 处理。

## 验收标准

- [ ] 每条内容在批次里都有独立状态与终态。
- [ ] 失败条目的原始载荷仍然存在（未被删除）。
- [ ] 重试只影响失败项，成功的条目不重复投递。
- [ ] 目标路径与场景与用户意图一致。
- [ ] 全程没有对微信的写操作。

## 常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 某条内容为空 | 该条会被判失败；补齐内容后重试 |
| 目标未配置（如 folder 无路径） | 先配置目标，再重试失败项 |
| 批次卡在 delivering | 检查目标是否需人工确认；不要直接删批次，保留载荷 |
| 同一批重复投递 | 会产生 -2、-3 文件；确认后用 wai_history_list 分辨 |
| 条目数超限 | 拆成多个批次，每批不超过 batchMaxItems |
