# 工作流 04：商机雷达

## 适用场景

- 想找「最近有什么赚钱机会」。
- 想维护合作进度（谁在推进、谁在等、谁该跟进）。
- 用户纠正了误报或假商单，需要让系统记住。

## 前置条件

- 已完成工作流 01；索引里有近期聊天。
- 清楚一条原则：**wai_opportunities 是唯一持久状态源**，日报与信号只是证据。

## 步骤

### 1. 抽取原始信号

    wai_signals { "hours": 24 }
    wai_deal_radar { "hours": 24 }

关注：brandDeals（含 qualification 与 confidence）、trainings、projects、resources、settlements、links（rank > 0）。

### 2. 看跨群链接与热度

    wai_db_links { "days": 7, "minChats": 2, "limit": 50 }

每个标准化 URL 只出现一次：出现群、发布者、加热者、商单概率（高概率/疑似/普通）。

### 3. 把信号收敛成候选（先预览）

    wai_opportunity_sync { "hours": 24, "dryRun": true }

- 默认就是 dryRun；先看会新增/加固哪些候选。
- 确认无误后再执行：

    wai_opportunity_sync { "hours": 24, "dryRun": false, "exclude": ["闲聊群"] }

### 4. 查看待审核候选

    wai_new_leads { "minPriority": 4, "limit": 20 }
    wai_opportunities { "includeCandidates": true, "minPriority": 3, "limit": 50 }

候选必须标注「待审核」，不得与推进中/等待对方/暂缓的正式机会混列。

### 5. 人工分流

    wai_triage { "id": 12, "decision": "pursue", "stage": "待报价", "priority": 4, "nextAction": "发报价档位", "followUp": "2026-08-05" }

decision 取值：pursue（推进）/ wait（等待）/ pause（暂缓）/ ignore（忽略）/ won（成交）/ lost（未成交）。

- **wait 必须给 followUp**；没有日期就保留为待确认，不擅自编造。
- pursue / wait / won / ignore 会同时写入针对该机会键的纠正记录，避免下次扫描把同一判断推翻。

### 6. 日常跟进

    wai_opportunities { "dueOnly": true }
    wai_today { "minPriority": 3, "limit": 10 }

- dueOnly 只看到期跟进；未到期的进等待区，不挤进今日动作。
- wai_today 合并待回复、逾期承诺、临近截止、待结算与到期商机。

### 7. 清理过期候选（先预览）

    wai_opportunity_maintain { "staleDays": 14, "apply": false }

确认后再 apply: true。过期只改状态，**不删除原始证据**。

### 8. 持久化用户纠正

    wai_feedback_add { "targetType": "chat", "target": "闲聊群", "verdict": "false_positive", "note": "纯闲聊，无商单" }
    wai_feedback_add { "targetType": "opportunity", "target": "12", "verdict": "confirmed", "note": "已与品牌确认预算" }

verdict 取值：confirmed / false_positive / ignore / low_priority。查历史纠正用 wai_feedback_list。

## 验收标准

- [ ] 候选与正式机会分栏，候选标「待审核」。
- [ ] 每条机会写清项目、联系人/可达路径、角色、证据等级与下一步。
- [ ] wait 类机会都有跟进日期。
- [ ] 用户确认过的状态没有被本轮扫描覆盖。
- [ ] 过期候选只标记不删除证据。
- [ ] 用户的纠正已通过 wai_feedback_add 持久化。

## 常见失败与处理

| 现象 | 处理 |
| --- | --- |
| 候选太多、噪声大 | 先看 evidence 与 qualification；用 feedback 降权噪声来源 |
| 同一机会被拆成多条 | 用 wai_triage / wai_opportunity_update 合并到一条主记录，其余标 ignore |
| 候选长期不动 | wai_opportunity_maintain 预览后 apply 标为 stale |
| 用户说「这个不是商单」 | 立即 wai_feedback_add（false_positive），不要只在对话里记住 |
| 结算状态不清 | 只有款项确认到账才写「已收款」；「会打款」「已提交结算」都不算 |
