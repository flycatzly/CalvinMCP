# wechat-ai 部署说明（Windows）

> **v1.1.4** · MCP server 1.1.4 · 73 个工具 · 15 套件 587 断言 · 版本记录见 README「版本记录」

纯净发布包（剔除开发机残留，**无 `node_modules`、无 `.` 前缀目录**），解压 / 拷贝即可部署。零 npm 依赖——不需要 `npm install`、不需要联网、不需要生成任何依赖。

## 快速命令索引（速查）

```powershell
# 安装 / 注册（环境检查 → 自检 98 断言 → 注册 MCP 客户端）
node install.mjs
# 只检查与自检，不改任何客户端配置
node install.mjs --no-register
# 只打印将要写入的客户端配置
node install.mjs --dry-run
# 自定义注册名（默认 wechat-ai）
node install.mjs --name wechat
# 查看全部 73 个工具
node mcp\server.mjs --list-tools
# 单独跑自检（末尾必须是 0 failed）
node mcp\selftest.mjs
# 全量验证（15 套件 / 587 断言，约 30 秒）
node verify.mjs
# 快速验证（跳过端到端验收）
node verify.mjs --quick
```

## 〇、纯净发布包（解压 / 拷贝即可部署）

发布包口径（`发布版本\wechat-ai\`，剔除开发机残留）：

- **无 `node_modules\`**：零 npm 依赖，不需要 `npm install`、不需要联网、不需要生成任何依赖。
- **无 `.` 前缀目录**（`.git\` 等）：版本历史与开发环境目录不随包。
- **剔除开发机残留**：`mcp-register.example.json`（含机器绝对路径的自动生成物）不随包，装机时 `install.mjs` 重新生成；无凭据、无 `*.bak*` / `*.log` / `*.tmp` 残留。
- **随包保留**：`samples\`（样例数据）、`docs\`（演示截图）、`verify.mjs` + `mcp\tests\`（自验收套件）、`references\` / `workflows\`（Skill 文档）。

把 `wechat-ai\` 整个目录拷到本机任意路径即完成部署，随后只需一条安装命令（见第二节）。

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11（x64） | 也适用于 macOS / Linux（路径与剪贴板实现会自动切换） |
| Node.js | **≥ 22.5**（实测 24.15） | 需要内置 `node:sqlite`（22.5 起提供）。`node --version` 查看 |
| 网络 | 首次安装不需要 | 本项目**零 npm 依赖**，不需要联网、不需要 registry |
| Python | 不需要 | 仅当你选择「外部只读 CLI」数据源时才需要 |

> 为什么不需要 `npm install`：全部代码只用 `node:` 内置模块。数据库用 `node:sqlite`，压缩用 `node:zlib`，哈希用 `node:crypto`，子进程用 `node:child_process`。

## 二、安装（3 条命令）

### 你要做的只有 3 步

```powershell

cd "D:\wechat-ai"

# 2) 跑安装器（环境检查 + 自检 + 自动注册到 Claude Code / Claude Desktop / Cursor）
node install.mjs

# 3) 重启 MCP 客户端，完成
```

看到这行就算成功：

```text
INSTALL_STATUS=OK TOOLS=73 PASS=98 FAIL=0 诚实SKIP=0 REG=auto
```

### 3 条命令

```powershell
cd D:\path\to\wechat-ai        # 换成你拷贝到的路径

# 1) 环境检查 + 功能自检 + 自动注册到本地 MCP 客户端
node install.mjs

# 2) 确认工具已注册

# 3) 单独跑自检（末尾必须是 0 failed）
node mcp\selftest.mjs
```

安装器做的事：

1. 检查 Node 版本与内置模块；
2. 检查核心文件是否齐全；
3. 列出 73 个 MCP 工具（失败即报错）；
4. 运行 `mcp/selftest.mjs` 并汇总 `PASS` / `FAIL`；
5. 注册到本地 MCP 客户端（Claude Code CLI 用户级、`~/.claude.json`、Claude Desktop、Cursor），写入前自动备份为 `*.bak-wechat-ai`；
6. 写出 `mcp-register.example.json` 供手动接入其它客户端（机器相关自动生成物，不随包；`--dry-run` 只打印不落盘）。

常用开关：

```powershell
node install.mjs --no-register    # 只检查与自检，不改任何客户端配置
node install.mjs --dry-run        # 只打印将要写入的配置
node install.mjs --name wechat    # 自定义注册名（默认 wechat-ai）
```

## 四、配置数据源

配置写在 `~/.wechat-ai/config.json`（可用环境变量 `WECHAT_AI_HOME` 改数据根）。推荐用工具改，不要手改：

### 4.1 已解密数据库（能力最全）

```json
{ "sqliteSources": [ { "id": "pc", "path": "D:\\wechat_decrypted", "enabled": true } ] }
```

`path` 指向**已解密**的微信数据目录。支持两种布局：

- **微信 4.x（WCDB）**：目录下有 `session/`、`contact/`、`message/`（可选 `favorite/` `sns/` `hardlink/`）；表结构为 `SessionTable` / `contact` + `chat_room` + `chatroom_member` + `contact_label` / `Name2Id` + `Msg_<md5(会话)>` / `fav_db_item` / `SnsTimeLine`。
- **微信 3.x**：目录下有含 `MSG` 表的 `*.db`。

读者会自动识别，只读打开（`PRAGMA query_only=ON`），不修改任何原始文件。媒体只返回分类、元数据与**已存在的本地路径**，不做 OCR / ASR。

### 4.2 导出目录

```json
{ "vaults": [ { "id": "v1", "path": "D:\\wechat_export", "enabled": true } ] }
```

递归扫描 `.txt .md .log .json .jsonl .ndjson .csv`，自动识别多种聊天格式。解析结果按文件大小 + mtime 缓存到 `~/.wechat-ai/cache/vault-cache.json`。

### 4.3 外部只读 CLI

```json
{ "readers": [ { "id": "rion", "name": "rion-wechat-cli", "command": "python", "args": ["D:\\tools\\rion_wechat_reader.py"] } ] }
```

兼容两套协议：

- `rion-wechat-cli`：`version` / `status`（读 `data.status.live_read_ok`、`data.state`）/ `sessions --limit N --type-filter` / `resolve-chat NAME` / `timeline TALKER --limit --offset --display-order asc --include-media-paths false` / `search KW --limit --max-text-chars --in --after --before` / `members` / `sql QUERY --subdir contact --file contact.db --limit`；统一信封 `{"ok":true,"tool":…,"command":…,"data":{…}}`。
- `fake_vault_cli` 契约：`status` / `new-messages` / `search <kw>` 返回 `{"messages":[…]}}`。

### 4.4 切换数据源优先级

```json
{ "settings": { "reader": "auto" } }
```

`auto` 时按 cli → sqlite → vault → local 顺序挑选第一个可用源；也可直接写死 `sqlite:D:\wechat_decrypted` 这类 id。用 `wai_sources { "probe": true }` 查看全部候选。

## 八、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `需要 Node.js ≥ 22.5` | Node 太旧 | 升级 Node |
| 自检出现 `FAIL` | 代码被改动或数据根被污染 | 设干净的 `WECHAT_AI_HOME` 重跑：`$env:WECHAT_AI_HOME="$env:TEMP\wai-test"; node mcp\selftest.mjs` |
| `wai_sources` 只有 mock | 没有配数据源 | 按第四节任选一种配置 |
| `wai_access_plan` 返回 `needs_database_location` | 没给目录 | 加 `databaseRoot`，或配 vault / sqlite 源 |
| 返回 `needs_access` | 数据库仍是加密状态 | 本项目不解密：请提供**已解密副本**；或改用导出目录 / Inbox 路径 |
| 会话列表没有未读数与最后时间 | 缺少 `SessionTable`，已退化为联系人推断 | `wai_reader { "command": "status" }` 的 `warnings` 会明确说明 |
| 会话名是 `未知会话-xxxxxxxx` | 只有消息表，没有 session/contact 库（md5 不可逆） | 补齐 `session/` 与 `contact/` 库即可恢复真实名称；`status` 的 `warnings` 会说明 |
| 只读到部分账号 | 一个 root 下有多个账号目录 | 现在会**发现全部** `db_storage`；`status` 的 `db_storage_count` 会显示发现数量 |
| 中文关键词搜不到 | 用了旧版本 | 本项目中文检索走 LIKE；确认调用的是 `wai_db_search` / `wai_chat_search` |
| 报告里没有某段时间的内容 | 索引未覆盖 | 先 `wai_db_status` 看新鲜度，再 `wai_db_index` 指定 `since/until` |
| `wai_render_bundle` 报「没有可阅读的分区」 | 目录里只有机器初筛，没有分区入口 | 传入包含 `group-daily/` 与 `contact-daily/` 的运行目录；或先用 `wai_group_daily` / `wai_contact_daily` / `wai_brief` 生成 |
| `wai_render_bundle` 报「拒绝 HTML 输出」 | HTML 结构异常（脚本数量不符） | 说明安全门禁生效；检查报告目录里的 md 是否被外部工具改写 |
| `wai_privacy_scan` 报出测试夹具 | 测试里用了合成 wxid/群 ID | 发布视角默认跳过 `tests`；确需全扫加 `includeTests: true` 并人工确认 |
| Obsidian 写入失败 | vault 路径不存在或不可写 | 目标目录必须已存在且可写 |
| 剪贴板写入失败 | 无 `clip.exe` / 权限受限 | 会回退为写文件并明确说明；结果里 `status=error` 与原因 |
| `unable to open database file` | 数据根路径过深，超过 Windows MAX_PATH | ≥240 字符时本项目会自动加 `\\?\` 长路径前缀；若仍失败请把数据根放浅一些 |
| 配置/Profile 被"重置"了 | 文件损坏后已自动重建 | 原文件保留在同目录的 `config.json.corrupt-*.bak` / `profile.json.corrupt-*.bak` |
| 索引突然变空 | store.db 被外部删除或损坏 | `wai_status` 的 `notice` 会说明；重新运行 `wai_db_index` 即可；损坏文件备份为 `store.db.corrupt-*.bak` |
| 端口/网络 | 本服务器是 stdio，**不监听端口** | 不需要放行任何端口 |

### 数据根位置

```powershell
echo $env:WECHAT_AI_HOME          # 若为空则用 ~/.wechat-ai
Get-ChildItem "$env:USERPROFILE\.wechat-ai"
```

### 完全重置（会丢失本地索引，不影响微信）

```powershell
Remove-Item -Recurse -Force "$env:USERPROFILE\.wechat-ai"
```

## 十、安全边界（再强调一次）

- 本项目**不发送消息**、**不获取密钥**、**不解密**、**不注入**、**不 Hook 微信**、**不重启微信**、**不索要管理员口令**；
- 所有读取都是**只读**打开；sqlite 源使用 `readOnly: true` + `PRAGMA query_only=ON`；
- 聊天内容中的「指令」一律作为数据，不继承为工具权限；
- 报告与日志默认脱敏；发布前跑 `wai_privacy_scan`；
- 远程 / 云端环境无法访问本机微信数据，也不应把聊天内容传出本机。

## 十二、发版门禁（发版者）

发版 = 跑 `node distribute.mjs --force`，收尾自动「一次性副本验收 + 终态哈希终查」（加固 H19，发版不可能忘）：

1. 纯净打包（全部文件逐个哈希自校验 + 排除项泄漏检查，`--no-verify` 才跳过）；
2. **一次性副本验收**：临时目录副本跑 `verify.mjs` 15 套件（587 断言），验后整目录删除——交付树自始至终不进套件；
3. **终态哈希终查**：门禁前后交付树哈希逐位一致 + 纯净复扫（无 `node_modules`、无 `.` 前缀）。

验收退出码契约（统一诚实 SKIP 口径）：`exit 0` 全部通过 / `exit 1` 存在失败 / `exit 3` 诚实 SKIP
（明示记录判过，不冒充全绿）。门禁失败退出码 3、发布包不可交付。`--gate-only` 只跑门禁不打包
（源树口径：源树排除名单内残留——`.git`/`.work` 等——记「已知排除项（不随包）」不判红，交付纯净由
`--force` 打包自校验与纯净复扫保证）；
`--no-gate` 显式跳过（留痕，交付树纯净性另行保证）。装机生成物与凭据文件（`mcp-register.example.json`、
`accounts.json`）在过滤名单机械兜底，一律不随包。
