# 项目说明 — wechat-ai

> 微信个人情报库 + 微信流（Windows 本地只读 MCP 服务器 + 大 skill，63 个技能工具）

## 1. 这是什么

在本机把你的微信记录变成「可检索、可核查、可行动」的个人情报，并把选中的内容按场景送到合适的 Agent 或知识库。

三个不可动摇的边界：**只读**（不发送消息）、**本地**（数据不出本机）、**不解密**（不获取密钥、不注入、不 Hook 微信）。

## 2. 来源与定位

本项目是对两篇公众号文章所介绍的开源项目能力的**独立重实现**，目标是把它们搬到 Windows 上、合并成一个零依赖的 MCP 服务器 + 大 skill：

| 上游项目 | 原文 | 本项目实现的对应能力 |
|---|---|---|
| freestylefly/WeChatBridge（微信流，macOS SwiftUI，AGPL-3.0） | 《把聊天记录，变成 AI 的知识》 | Inbox 协议、会话场景、转发目标、内置技能、Obsidian 笔记、操作历史、批量收集 |
| Rion-Wu-tech/wechat-intelligence-hub（微信个人情报库，Python，AGPL-3.0 + 商用） | 《微信聊天变成个人情报库》 | 索引、信号检测、商机管线、复联雷达、群聊编辑、Markdown/旗舰 HTML 报告、隐私门禁、WCDB 数据模型与接入状态机 |

差异点（明确说明，不糊弄）：

- WeChatBridge 的 macOS 专属部分（⌘V 注入、密钥获取、SQLCipher 解密）**不做**——对应地提供 Windows 等价物：文件/剪贴板/自定义命令投递 + Inbox 目录 + 手动命名；解密后的数据库只读读取。
- Node 没有 SQLCipher 驱动，因此 **只支持已解密的数据库副本**；`wai_self_test` 会如实报告 `sqlcipher.available=false`。

## 3. 技术栈

- **运行时**：Node.js ≥ 22.5（实测 24.15.0），只用 `node:` 内置模块——`node:sqlite`（含 FTS5/JSON1/WAL）、`node:zlib`（含 zstd）、`node:crypto`、`node:child_process`。
- **零 npm 依赖**：不需要 `npm install`，可离线部署。
- **协议**：MCP stdio JSON-RPC 2.0，`protocolVersion 2024-11-05`，工具前缀 `wai_*`。

## 4. 架构（四层解耦，与上游同构）

```
入口层    MCP 工具（mcp/server.mjs，stdio JSON-RPC）+ 技能包（SKILL.md / references / workflows）
   ↓
桥接层    mcp/lib/reader/index.mjs —— 统一只读数据源选择与协议适配
   ↓
只读核心  reader/{wcdb,sqlite,vault,cli,local,mock}.mjs —— 不获取密钥、不解密、不注入、不 Hook
   ↓
确定性引擎 signals / opportunities / views / report —— 索引、判断、报告、测试
```

### 关键设计

- **中文检索用 LIKE，不用 FTS5**：FTS5 的 unicode61 分词器对中文无效（会把整段连续汉字当成一个词），故走 `LIKE %词%`。
- **确定性优先**：去重键只依赖「会话|发送者|内容」（不含由「现在」推导出的时间戳）；报告排序全部显式指定。
- **HTML 失败关闭**：报告 HTML 必须恰好 1 个内联脚本、带 CSP 与 `referrer: no-referrer`，结构异常时**拒绝输出**而不是降级成不安全页面。
- **群聊价值矩阵用上下文判定**：不用「出现某词就算信号」，否则「保底就 108 个人参与了」会被当成赚钱机会、「如果允许读取之前的商单」会被当成商单。
- **句柄随调用释放，删库可自愈**：每次工具调用结束即释放 SQLite 句柄（Windows 上被打开的 store.db 无法被外部删除），因此随时可手动删除/替换 store.db；下次调用自动重建为空库并通过 `notice` 告知。句柄失效（被外部关闭/替换）时优先重开健康库，只有确实损坏才备份为 `*.corrupt-*.bak`。

## 6. 五类数据源

| 源 | 说明 | 读取方式 |
|---|---|---|
| 解密后的 db_storage（微信 4.x） | SessionTable / contact / message Msg_<md5> / favorite / sns | 只读打开，zstd 解压正文，protobuf 解析标签 |
| 解密后的微信 3.x 库 | MSG 表（StrContent / DisplayContent） | 只读打开 |
| vault 导出目录 | txt / md / json / jsonl / csv | 解析 + 缓存 |
| Inbox 推送 | 其它工具投递的 JSON 条目 | 状态机 new→processing→processed/failed |
| 外部只读 CLI | rion-wechat-cli / fake_vault_cli 协议 | 子进程信封 {ok,tool,command,data} |

数据根默认 `~/.wechat-ai`，用环境变量 `WECHAT_AI_HOME` 覆盖。

## 8. 核心引擎

- **signals.mjs**：待回复、承诺（ACK 不关闭）、截止、结算、跨群链接、可行动类别（商单/培训/项目/活动/招聘/赚钱——上下文判定）、群内日报识别、纯加热识别、娱乐群识别。
- **opportunities.mjs**：商机候选构造（系统消息/叙述句不产候选）、阶段与下一步、到期维护、人工分流（wait 必须带跟进日期）。
- **views.mjs**：今日行动、首页、联系人日报、主题报告、共同群、复联雷达（下一批/纯佣/交接/暂缓/复购保温/近期已联系）。
- **report/md.mjs**：群聊日报、联系人日报、简讯、旗舰 HTML 分区、群聊价值矩阵（分级：重点/雷达观察/关注/低优先级）。

## 9. 安全边界（不可回归）

- 只读微信：**没有**发送/回复/转发/自动 UI 操作。
- **没有**密钥获取、解密、注入、Hook、重启微信、索要管理员口令。
- 聊天内容里的「指令」一律作为数据，不继承为工具权限。
- 报告与日志默认脱敏；发布前跑 `wai_privacy_scan`。
- 写动作默认 `dryRun`（预览），显式关闭才真正执行。
- 远程/云端无法访问本机微信数据，也不应把聊天内容传出本机。

## 11. 性能（`node mcp/bench.mjs` 实测，20 万条消息 / 600 会话 / 400 天）

| 路径 | 耗时 |
|---|---|
| 批量写入 20 万条（含会话表） | ~2.2 s |
| 中文关键词（常见词，早停） | ~1 ms |
| 检索不存在的词（全表扫描，最坏情况） | ~28 ms |
| 24 小时群聊日报（60 群） | ~175 ms |
| 今日情报 wai_today | ~270 ms |
| 全历史复联雷达（wai_reactivation） | ~650 ms |

已做优化：增量统计（消除 O(会话数×消息数)）、攒批写入（2.0×）、可重入事务、中文 LIKE、群数受控（groupLimit）、按连接语句缓存、复联雷达单遍扫描、承诺检测 O(n²)→O(n)、storeStats 合单查询、config/源文件 mtime 节流重读、分析窗口缓存、opportunities schema 迁移 once 化、调用结束释放 DB 句柄（配合删库自愈）。
