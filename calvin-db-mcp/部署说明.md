> 一个「文档 + 内置 MCP 服务器」的数据库操作包：为 Claude Code / Claude Desktop / Cursor 等客户端提供
> **MySQL / PostgreSQL / OceanBase(MySQL 模式)** 的查询、核对、建表与受控增删改能力。
>
> | 项 | 值 |
> |---|---|
> | 本包版本 | **V1.6.32** |
> | 内置 MCP 版本 | **1.6.32**（单一真相源 `mcp/package.json`，`server.mjs` 自动读取）|
> | 自检基线 | **349 项断言**（未初始化的包为 335 项；断言数自证常量钉口径）|
> | 运行要求 | `node` ≥ 18.17；`npm`（仅首次装依赖需要）|
> | 工具数 | **16 个**（12 只读 + execute/create_table/import_data 受控写 + export_data 受控落盘）|

## 安装完成后：完整自然语言使用示例（16 工具全覆盖）

> 装好后直接把下面的话说给大模型即可；括号内是该例的主调工具，箭头后是一句话说明得到什么。
> 16 个工具各覆盖一次（同一工具被多场景覆盖时只保留最贴切的一处）。
> 写类操作（`execute` / `create_table` / `import_data`）一律**先确认后执行、写后验证**，红线见 README「安全设计 → 安全红线（Agent 执行纪律）」。

### 场景 A · 定位数据源（`list_sources` / `find_database`）

- 「看看现在有哪些数据源可用，各是什么类型、什么环境」（`list_sources`）→ 得到全部已配置源的清单（类型/主机/库名/环境，不含 url 与口令）。
- 「帮我找一下 TEST 环境里库名带 order 的数据库，顺便探测一下这些主机现在通不通」（`find_database`）→ 得到命中匹配的源，并标注各主机 TCP 可达性（`probe: true`）。

### 场景 B · 摸清结构（`list_tables` / `describe_table` / `find_tables_by_column` / `fk_relationships`）

- 「ele_admin_api 库里有哪些表？带行数估计和表注释」（`list_tables`）→ 得到表/视图清单，含预估行数与表注释（`name_like` 可过滤）。
- 「查一下 t_order 的表结构和索引，order_no 上有没有唯一约束？」（`describe_table`）→ 得到列结构：类型/可空/默认值/主键/索引/注释。
- 「我只记得有个字段叫 order_no——哪些表有这个列？」（`find_tables_by_column`）→ 得到含该列的表清单（列名/类型/是否主键/注释）。
- 「t_order 和 t_order_item 是怎么通过外键关联的？写 JOIN 前先给我看关系」（`fk_relationships`）→ 得到 `表.列 -> 引用表.列` 的外键关系列表，照着写 JOIN。

### 场景 C · 读取数据（`query` / `query_plan` / `sample_data`）

- 「统计 t_order 昨天各状态的数量分布，SQL 先给我确认再执行」（`query`）→ 得到只读 SQL 的查询结果（SELECT/WITH/SHOW/DESC/EXPLAIN，自动 LIMIT，超限标 `truncated`）。
- 「帮我看看这条查询走不走索引：SELECT * FROM t_order WHERE user_id=1001 ORDER BY create_time DESC LIMIT 20」（`query_plan`）→ 得到这条 SELECT 的 EXPLAIN 执行计划（text/json；不执行语句本身）。
- 「抽 10 条 t_order 看看数据长什么样，按创建时间倒序；只看 amount 大于 1000 的取 5 条」（`sample_data`）→ 得到表里的真实数据样本（默认 10 行、最多 50，`where` 过滤 + `order_by` 升/降序）。

### 场景 D · 统计与核对（`distinct_values` / `column_stats` / `count_rows`）

- 「t_order.status 有哪些取值、各多少条？精确去重总数也给我」（`distinct_values`）→ 得到取值分布 Top-N 计数 + 精确去重总数（可带 `where`）。
- 「给 amount 列做个画像：行数/空值/去重数/最值/均值，再看数值分布形态和高频值」（`column_stats`）→ 得到单列画像一条聚合（可选 `histogram` 等宽桶分布、`top_values` 高频值 TopN）。
- 「核对一下 t_order 和 t_order_item 昨天的行数对不对得上」（`count_rows`）→ 得到精确行数（可带 WHERE），用于前后对比、断言总数与数据核对。

### 场景 E · 导出结果（`export_data`）

- 「把这次查询结果导出成文件交给下游——CSV 还是 JSON 都行，长文本和二进制要保真」（`export_data`）→ 得到落盘到 `DBMCP_EXPORT_DIR` 白名单目录的 CSV/JSON 文件（防穿越/20MB 上限/原子落盘）。

### 场景 F · 导入数据（`import_data`）

- 「把 D:/data/new_orders.csv 导入到 t_order——先告诉我目标表、表头和预计行数，我确认后再执行；这次要原子，任何一行失败就整体回滚」（`import_data`）→ 得到 CSV 批量写入目标表的结果与导入行数（`atomic: true` 为全文件单事务，失败整体回滚）。

### 场景 G · 写入与建表（`execute` / `create_table`）

- 「把 t_order 里 order_no='20261005-001' 的状态改成 2——先给影响行数，我确认后执行，写完再核对影响行数」（`execute`）→ 得到单条 INSERT/UPDATE/DELETE 的执行结果与影响行数（同理可用于带 WHERE 的 DELETE；命中行数超 `maxAffectedRows` 预检即被拒）。
- 「在本地测试库建一张 t_demo（id INTEGER PRIMARY KEY, name TEXT），建完给我看一下表结构」（`create_table`）→ 得到单条 CREATE TABLE 建表结果（需 allowCreateTable；禁 DROP/TRUNCATE/数据变更语句）。

**写类操作纪律（先确认后执行、写后验证）**：`execute` / `create_table` / `import_data` 执行前先给出条件、影响行数/表头/建表语句，经确认后再动手；写前用 `count_rows` 按同一 WHERE 数一遍命中行数确认影响范围；写完用 `count_rows`/`query` 核对影响行数与预期一致。

**会被强制拒绝（即使用户明确要求）**：无 WHERE 的全表 UPDATE/DELETE、TRUNCATE、不引用真实列的恒真 WHERE（`WHERE 1=1` / `OR 1=1` 等）、DROP/ALTER——全表需求请走 DBA 人工渠道（DBeaver 等）。

**工具覆盖清单（16/16）**：`list_sources` ✓ `find_database` ✓ `list_tables` ✓ `describe_table` ✓ `find_tables_by_column` ✓ `fk_relationships` ✓ `query` ✓ `query_plan` ✓ `sample_data` ✓ `distinct_values` ✓ `column_stats` ✓ `count_rows` ✓ `export_data` ✓ `import_data` ✓ `execute` ✓ `create_table` ✓

## 一、这个包是什么

它由**两层**组成，安装时两层都要处理：

| 层 | 文件 | 作用 | 装到哪 |
|---|---|---|---|
| 文档层 | `README.md`（能力/工作流/安全红线/排错速查/更新记录）、`部署说明.md` | 让客户端/大模型知道「何时该用这个能力、红线是什么」，并指导部署 | 原地即可 |
| 服务层 | `mcp/` | 真正干活的 MCP 服务器（stdio / JSON-RPC 2.0） | 原地即可，注册其绝对路径 |

```text
calvin-db-mcp/                    ← 部署目录（整个目录即完整部署单元）
├── install.mjs               # 安装器：装依赖 → 初始化 → 自检 → 自动注册到本地 MCP 客户端
├── mcp-register.example.json # 注册片段样例（install.mjs 会刷新它）
├── README.md                 # 项目说明（能力/16 工具/工作流/安全红线/排错速查；「更新记录」唯一落点）
├── 部署说明.md               # 本文（速查命令索引 + 16 工具使用示例 + 完整参考：安装/配置/安全/排查/升级）
└── mcp/                      # ← MCP 服务器本体
    ├── server.mjs            # 入口（stdio / JSON-RPC 2.0；工具实现/协议层）
    ├── guard.mjs             # SQL 安全核心【纯函数零依赖】——词法掩码/守卫/恒真判定/写目标解析，可独立审计
    ├── pool.mjs              # 三库连接层（mysql2/pg 池 + node:sqlite）与 runQuery 读写分流
    ├── observe.mjs           # 观测面打点【零依赖】——DBMCP_ERR_LOG 审计日志（默认关闭，写失败 fail-open，超限滚动总量有界）
    ├── dbeaver-parse.mjs     # 导入器纯函数核心——JDBC URL 解析/环境词元映射/ID 清洗（带 fixture 单测）
    ├── crypt.mjs             # 加密核心【已混淆】——加解密连接串，勿手工编辑
    ├── crypt2.mjs            # enc2 主密钥绑定格式（AES-256-GCM + scrypt，DBMCP_MASTER_KEY）
    ├── crypt-cli.mjs         # 加解密命令行薄层（encrypt/decrypt/rekey）
    ├── import-dbeaver.mjs    # 从 DBeaver 导出文件(.dbp) 导入连接
    ├── selftest.mjs          # 自检（349 项断言）
    ├── sqlite-validate.mjs   # SQLite 真实库验证（83 项断言）
    ├── mysql-validate.mjs    # 真实 MySQL 全链路验证（37 项断言；无配置时 SKIP 退出码 3）
    ├── pg-validate.mjs       # 真实 PostgreSQL 操作矩阵 × 全工具面验证（59 项断言；无配置时 SKIP 退出码 3）
    ├── e2e-validate.mjs      # 全链路 E2E（46 项断言；真 stdio 子进程，fixture 自供给）
    ├── protocol-validate.mjs # 协议边界/对抗（24 项断言；超长行/坏 JSON/id 边界/守卫负例/取消语义）
    ├── realform-validate.mjs # 真实形态验证（43 项断言；中文库/表/列 + 边界值 + 导出导入回环 + 红线/注入负例 + 对抗回归——不可见字符/文件名/表头/CRLF/截断边界/BLOB 序列化）
    ├── bench.mjs             # 导入吞吐基准（万行非事务 × 3 轮取中位；JSON 输出、enc 解密零明文口令、跑完自动清基准表）
    ├── sqlite-add.mjs        # SQLite 一键建库/注册源
    ├── package.json / package-lock.json
    ├── node_modules/         # ← 纯净包**不含**，首次安装时生成
    └── dbmcp.config.json     # ← 纯净包**不含**，导入后生成（enc 加密，勿入 git）
```

### 纯净包（分发包）里没有的东西

本包按「零预装依赖、不预置凭据、不带 `.` 前缀文件」分发，以下各项由你在安装时生成：

1. **`mcp/node_modules/`** —— 由 `install.mjs` 自动执行 `npm ci --omit=dev` **命令生成**（26 个纯生产包；`devDependencies` 里的混淆器不需要）。
2. **`mcp/dbmcp.config.json`** —— 你的数据库连接配置，由导入 `.dbp` 生成，连接串以 `enc` 字段**加密存储**，文件内无明文口令。
3. **`mcp/.gitignore`** —— 导入 `.dbp` 时自动生成（纯净包不带任何 `.` 前缀文件/目录；作用是保护 `dbmcp.config.json` 不入 git）。

> 校验纯净包：`mcp/` 下应只有上表列出的源码文件，没有 `node_modules`，没有 `dbmcp.config.json`，也没有 `node_modules` 之外的任何 `.` 前缀文件/目录。

### 3.3 第 3 步：初始化连接配置

**必须先有配置再注册**，否则客户端连上后所有工具只会回 `init_required`。二选一：

**方式 A（推荐）：从 DBeaver 导出文件导入**

1. 在源机 DBeaver 里确认各连接已勾选「保存密码」；
2. DBeaver → 菜单 **文件 → 导出 → 项目**，勾选所需数据源与「包含连接凭据」，导出得到如 `保险-20260929.dbp`；
3. 导入：

## 四、安装成功的判定标准

**怎么算装好了**：下表判定点全部通过即安装成功——安装器输出 `INSTALL_STATUS=OK` 且 `FAIL=0`，重启后客户端出现 `db` 服务器、能列出 **16 个工具**，实测让模型调 `list_sources` 返回你导入的源数量。自测数字对不上不用慌（都算成功）：

| 判定点 | 通过标准 | 不通过看 |
|---|---|---|
| 依赖 | `mcp/node_modules/` 下存在 `mysql2`、`pg` | §7.1 |
| 配置 | `mcp/dbmcp.config.json` 存在，含 `enc` 字段且**无明文 url** | §7.2 |
| 自测 | `FAIL=0`（已初始化 `PASS=349`；未初始化 `PASS=335`）| §7.5 |
| 注册 | 客户端出现 `db` 服务器且能列出工具 | §7.4 |
| 连通 | 至少一个源可达并能查询 | §7.3 |

### 自测的三种口径（都是「成功」，别被数字吓到）

| 场景 | 汇总行 | 说明 |
|---|---|---|
| 未初始化（纯净包直接跑） | `335 passed, 0 failed` | leak-guard 口令套件整体 SKIP（没配置就没有秘密可测）|
| 已导入配置、所有源可达 | `349 passed, 0 failed` | 正常态 |
| 已导入配置、部分源不可达 | `349 passed, 0 failed` | oceanbase / 特定源用例打印 `SKIP`（计入通过）|

自测是**跨配置可移植**的：若你的配置里没有口令、没有 TEST 环境源、或没有某个特定源，相应用例会打印 `SKIP` 而**不是 FAIL**。

> 打印 `SKIP` 是正常的（未初始化、无口令、缺某个源时都会 SKIP 并计入通过）；只要没有 `FAIL` 就是好的。

## 五、配置管理（`mcp/dbmcp.config.json`）

```json
{
  "maxRows": 200,            // 单次查询返回行数上限（SELECT/WITH 统一外层包 LIMIT）
  "timeoutMs": 30000,        // 连接/语句超时
  "allowWrites": false,      // 是否允许 execute 写操作（默认 false）
  "allowCreateTable": false, // 是否允许 create_table 建表（默认 false）
  "maxAffectedRows": 500,    // execute 前按同一 WHERE 预检命中行数，超过即拒绝；0 = 关闭预检
  "sources": {
    "mysql_xxx": { "type": "mysql", "enc": "<加密串>", "env": "TEST", "description": "可选说明" }
  }
}
```

| 字段 | 说明 |
|---|---|
| `maxRows` | 单次查询上限（默认 200）。客户端还可用 `max_rows` 参数按次调整（上限 5000）|
| `timeoutMs` | 连接与语句超时（默认 30s）。**源主机不可达时会占满这个时间**，属正常等待 |
| `allowWrites` | 放开 `execute`（INSERT/UPDATE/DELETE）。**安全红线仍强制生效，无覆盖开关** |
| `allowCreateTable` | 放开 `create_table`（仅单条 CREATE TABLE）|
| `maxAffectedRows` | 写操作影响行数预检上限（默认 500）。批量变更超限会被拒并回报实际行数 |

**加解密命令**：

```powershell
cd "$env:USERPROFILE\.agents\skills\calvin-db-mcp\mcp"
node crypt-cli.mjs encrypt     # 明文 url → enc
node crypt-cli.mjs decrypt     # enc → 明文 url（临时查看用）
```

**凭据保护三件套**（默认开启，无需配置）：落盘加密（`enc` 字段）、输出清洗（工具响应中的口令一律替换为 `***`）、
git 启动门禁（配置文件被 git 跟踪或未被 ignore 时**拒绝启动**）。

### 5.2 环境变量（MCP 服务进程的环境，非 shell 环境）

环境变量要写在**客户端注册 JSON 的 `"env"` 块**里（由客户端在启动 server 进程时注入），或写进系统环境变量后重启客户端；写在普通终端里对已注册的 MCP 服务**不生效**。

| 变量 | 作用 | 未设置时 |
|---|---|---|
| `DBMCP_CONFIG` | 指向其他配置文件路径 | 用 `mcp/dbmcp.config.json` |
| `DBMCP_EXPORT_DIR` | `export_data` 落盘白名单目录（必须）；`import_data` 的回退读取目录 | export_data 拒绝执行 |
| `DBMCP_IMPORT_DIR` | `import_data` 读取导入文件的白名单目录 | 回退 `DBMCP_EXPORT_DIR`；两者都无则拒绝 |
| `DBMCP_MASTER_KEY` | enc2 主密钥（≥8 字符）：设置后新写入/`crypt-cli rekey` 的密文为 AES-256-GCM 主密钥绑定格式（认证防篡改） | 沿用旧格式（AES-128-CBC 落盘混淆）|
| `DBMCP_PRETTY` | `=1` 时响应恢复缩进 JSON | 紧凑 JSON |
| `DBMCP_MAX_CELL_CHARS` | 超长单元格截断阈值 | 2000 |
| `DBMCP_SLOW_MS` | 慢查询日志阈值（毫秒）：超过即向 stderr 打一行 source/耗时/语句类型/截断预览（SQL 过输出清洗）；`0` 关闭 | 2000 |
| `DBMCP_NO_LISTEN` | `=1` 时不启动 TCP 监听（纯 stdio） | 按默认行为 |

注册 JSON 写法示例（`"env"` 块与 `command`/`args` 平级）：

```json
{
  "mcpServers": {
    "db": {
      "command": "node",
      "args": ["<技能目录>\\mcp\\server.mjs"],
      "env": {
        "DBMCP_EXPORT_DIR": "D:\\exports",
        "DBMCP_IMPORT_DIR": "D:\\imports"
      }
    }
  }
}
```

> Windows 路径在 JSON 里反斜杠要写双份（`\\`），或直接用正斜杠（`D:/exports`）。

### 两个开关（默认都关闭）

| 开关 | 作用 |
|---|---|
| `--allow-writes` | 放开 `execute`（INSERT/UPDATE/DELETE）。安全红线仍强制生效 |
| `--allow-create-table` | 放开 `create_table`（单条 CREATE TABLE）|

也可以导入后直接改 `mcp/dbmcp.config.json`：`allowWrites` / `allowCreateTable` / `maxAffectedRows`（写操作行数预检，默认 500）/ `maxRows`（单次查询上限，默认 200）。

## 六、安全机制（简要）

| 机制 | 行为 |
|---|---|
| 只读守卫 | 仅允许 SELECT/WITH/SHOW/DESC/EXPLAIN；可写 CTE、`INTO OUTFILE`、行锁、`pg_read_file`/`pg_ls_dir`/`dblink` 等全部拦截 |
| 单语句 | 出现第二条语句即拒绝 |
| 自动 LIMIT | SELECT/WITH 统一外层包裹 `LIMIT maxRows+1`，返回 `truncated` 标记 |
| 写入红线 | **无 WHERE 的 UPDATE/DELETE、TRUNCATE、恒真 WHERE（`WHERE 1`、`2>1`、`true=true` 等）一律拒绝**；WHERE 必须引用真实列 |
| 影响行数预检 | 写操作前用同一 WHERE 先 `COUNT(*)`，超 `maxAffectedRows` 即拒绝并回报行数 |
| 输出整形 | 默认紧凑 JSON；超长单元格截断并标注，避免单个 TEXT 列吃满上下文 |

> 详细红线与使用规范见 `README.md`「安全设计」；实现层说明也在 `README.md`。
> 注意：MCP 层不是最终权限边界 —— 请给数据库账号最小权限（只读场景用 SELECT-only 账号）。

## 七、问题排查

### 出问题先看这几条

> 六类高频现象（工具回 `init_required` / 依赖装不上 `ETIMEDOUT` / `ECONNREFUSED`·`ETIMEDOUT` 库不通 / 客户端里没有 `db` / `Access denied for user` / 自测出现 `FAIL`）的对症处理见 7.1–7.6 分类表。
> 更细的排查见 `README.md` 的「排错速查」；配置项与红线细节在 README「配置」与「安全设计」。
> 实在卡住时，把这三样发出来最快定位：`node install.mjs` 的完整输出、`mcp/dbmcp.config.json` 里源的数量（**别发内容**）、以及报错的原文。

### 7.1 依赖相关

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot find package 'mysql2'` | 未安装依赖 | `cd mcp && npm ci --omit=dev`，或重跑 `node install.mjs` |
| npm 报 `ETIMEDOUT` / `ECONNRESET` | 访问不到 npm 源 | 加镜像 `--registry=https://registry.npmmirror.com`，或用企业私服 |
| 依赖装到了别处 | 不在 `mcp/` 下执行 | `package.json` 在 `mcp/`，npm 命令必须在该目录内运行 |
| 想彻底重装 | lock 或缓存异常 | 删除 `mcp/node_modules` 后重新 `npm ci --omit=dev` |

### 7.2 配置与凭据相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 工具返回 `init_required` | 尚未导入配置 | 按 §3.3 导入后重启客户端 |
| `source 'xxx' 的 enc 解密失败` | 密文与密钥不匹配（`crypt.mjs` 被换成了别的版本）| 用本包配套的 `crypt.mjs` 重新 `encrypt` |
| 忘了明文 url | — | `node crypt-cli.mjs decrypt` 临时查看（看完再 `encrypt`）|
| 配置被误提交 git | 保护缺失 | 确认 `mcp/.gitignore` 含 `dbmcp.config.json`；启动门禁会拒绝启动并提示 |

### 7.3 连通性相关

| 现象 | 原因 | 处理 |
|---|---|---|
| `ECONNREFUSED` | 端口不通/服务未监听 | 确认主机端口；检查是否需 VPN |
| `ETIMEDOUT`（恰好等满 `timeoutMs`）| 主机不可达或被防火墙静默丢弃 | 连 VPN / 加 IP 白名单；先用 `find_database` 的 `probe: true` 探测 |
| TCP 能连但一直超时 | 该端口是网关/代理，或 PostgreSQL 握手被挡（部分云库需 TLS 或白名单）| 需人工确认端口/白名单，或从配置移除。注意 `probe` 只测 TCP，**不代表能登录** |
| `Access denied for user` | 账号无权限或口令错误 | 按最小权限调整账号；确认 DBeaver 勾选了「保存密码」后重新导出导入 |

### 7.4 客户端注册相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户端里没有 `db` | 未注册或未重启 | 检查 `mcpServers.db`；完全退出客户端再启动 |
| 客户端报 server 启动失败 | 路径错或 `node` 不在 PATH | 用绝对路径，`args` 指向 `<技能目录>\mcp\server.mjs` |
| 工具列表为空 | 配置未就绪 | 先完成 §3.3 |
| 大模型不知道何时该用 | 技能层没装 | 按 §3.1 放入 skills 目录并重启 |

### 7.5 自测相关

| 现象 | 处理 |
|---|---|
| 出现 `SKIP` | 正常。未初始化、配置无口令、无 TEST 源、特定源不存在时都会 SKIP（计入通过）|
| `FAIL=0` 但带 SKIP | 成功 |
| 出现 `FAIL` | 看 FAIL 行提示：多为配置损坏（`enc` 解不开）或 `crypt.mjs` 被替换 |
| `PASS=335` 而非 349 | 说明当前目录**没有** `dbmcp.config.json`（未初始化口径）|

### 7.6 误改客户端配置后回滚

`install.mjs` 改动任何客户端配置前都会备份为同名 `.bak-calvin-db-mcp`：

```powershell
Copy-Item "$env:USERPROFILE\.claude.json.bak-calvin-db-mcp" "$env:USERPROFILE\.claude.json" -Force
```

## 发版门禁（发版者）

发版 = 跑 `node distribute.mjs --force`，收尾自动「一次性副本验收 + 终态哈希终查」（加固 H19，发版不可能忘）：

1. 纯净打包（逐文件哈希自校验 + 排除项泄漏检查）；
2. **一次性副本验收**：临时目录副本跑 `npm ci --omit=dev` + 六个验证器（`selftest.mjs` / `sqlite-validate.mjs` / `mysql-validate.mjs` / `e2e-validate.mjs` / `protocol-validate.mjs` / `realform-validate.mjs`），
   验后整目录删除——交付树自始至终不进套件；
3. **终态哈希终查**：门禁前后交付树哈希逐位一致 + 纯净复扫（无 `node_modules`、无 `.` 前缀）。

验收退出码契约（统一诚实 SKIP 口径）：`exit 0` 全部通过 / `exit 1` 存在失败 / `exit 3` 诚实 SKIP
（明示记录判过，不冒充全绿）——`mysql-validate` 无凭据 SKIP、e2e/protocol/realform-validate 无 node:sqlite
即退出码 3 的典型形态。门禁失败退出码 3、
发布包不可交付。`--gate-only` 只跑门禁不打包（源树口径：源树排除名单内残留——`.git` 等——记
「已知排除项（不随包）」不判红，交付纯净由 `--force` 打包自校验与纯净复扫保证）；
`--no-gate` 显式跳过（留痕）。连接凭据与装机生成物
（`dbmcp.config.json`、`mcp-register.example.json`、`accounts.json`、`*.dbp`）在过滤名单机械兜底，一律不随包。
