# calvin-db-mcp 部署说明

> 一个「技能（Skill）+ 内置 MCP 服务器」的数据库操作包：为 Claude Code / Claude Desktop / Cursor 等客户端提供
> **MySQL / PostgreSQL / OceanBase(MySQL 模式)** 的查询、核对、建表与受控增删改能力。
>
> | 项 | 值 |
> |---|---|
> | 本包版本 | **V1.6.2** |
> | 内置 MCP 版本 | **1.6.2**（单一真相源 `mcp/package.json`，`server.mjs` 自动读取）|
> | 自检基线 | **277 项断言**（未初始化的包为 263 项）|
> | 运行要求 | `node` ≥ 18.17；`npm`（仅首次装依赖需要）|
> | 工具数 | **16 个**（12 只读 + execute/create_table/import_data 受控写 + export_data 受控落盘）|

## 一、这个包是什么

它由**两层**组成，安装时两层都要处理：

| 层 | 文件 | 作用 | 装到哪 |
|---|---|---|---|
| 技能层 | `SKILL.md` | 让客户端/大模型知道「何时该用这个能力、红线是什么」 | 客户端的 skills 目录 |
| 服务层 | `mcp/` | 真正干活的 MCP 服务器（stdio / JSON-RPC 2.0） | 原地即可，注册其绝对路径 |

```text
calvin-db-mcp/                    ← 技能目录（整个目录作为一个技能）
├── SKILL.md                  # 技能说明（含 name/description front-matter，客户端据此发现技能）
├── install.mjs               # 安装器：装依赖 → 初始化 → 自检 → 自动注册到本地 MCP 客户端
├── mcp-register.example.json # 注册片段样例（install.mjs 会刷新它）
├── README.md                 # 功能与工具说明
├── 部署说明.md               # 简明部署（3 步速览 + 排错）
├── 部署说明.详细版.md        # 本文档（完整参考：安装/配置/安全/排查/升级）
└── mcp/                      # ← MCP 服务器本体
    ├── server.mjs            # 入口（stdio / JSON-RPC 2.0；工具实现/协议层）
    ├── guard.mjs             # SQL 安全核心【纯函数零依赖】——词法掩码/守卫/恒真判定/写目标解析，可独立审计
    ├── pool.mjs              # 三库连接层（mysql2/pg 池 + node:sqlite）与 runQuery 读写分流
    ├── dbeaver-parse.mjs     # 导入器纯函数核心——JDBC URL 解析/环境词元映射/ID 清洗（带 fixture 单测）
    ├── crypt.mjs             # 加密核心【已混淆】——加解密连接串，勿手工编辑
    ├── crypt2.mjs            # enc2 主密钥绑定格式（AES-256-GCM + scrypt，DBMCP_MASTER_KEY）
    ├── crypt-cli.mjs         # 加解密命令行薄层（encrypt/decrypt/rekey）
    ├── import-dbeaver.mjs    # 从 DBeaver 导出文件(.dbp) 导入连接
    ├── selftest.mjs          # 自检（277 项断言）
    ├── sqlite-validate.mjs   # SQLite 真实库验证（76 项断言）
    ├── mysql-validate.mjs    # 真实 MySQL 全链路验证（29 项断言；无配置时 SKIP 退出码 3）
    ├── sqlite-add.mjs        # SQLite 一键建库/注册源
    ├── package.json / package-lock.json
    ├── node_modules/         # ← 纯净包**不含**，首次安装时生成
    └── dbmcp.config.json     # ← 纯净包**不含**，导入后生成（enc 加密，勿入 git）
```

### 纯净包（分发包）里没有的东西

本包按「零预装依赖、不预置凭据、不带 `.` 前缀文件」分发，以下各项由你在安装时生成：

1. **`mcp/node_modules/`** —— 由 `install.mjs` 自动执行 `npm ci --omit=dev` **命令生成**（26 个纯生产包；`devDependencies` 里的混淆器不需要）。
2. **`mcp/dbmcp.config.json`** —— 你的数据库连接配置，由导入 `.dbp` 生成，连接串以 `enc` 字段**加密存储**，文件内无明文口令。
3. **`mcp/.gitignore`** —— 导入 `.dbp` 时自动生成（纯净包不带任何 `.` 前缀文件/目录；作用是保护 `dbmcp.config.json` 不入 git）。

> 校验纯净包：`mcp/` 下应只有上表列出的源码文件，没有 `node_modules`，没有 `dbmcp.config.json`，也没有 `node_modules` 之外的任何 `.` 前缀文件/目录。

### 3.1 第 1 步：放置技能

把整个 `calvin-db-mcp` 目录拷到客户端的技能目录。**目录名即技能名；主文件名与大小写按客户端约定**：

| 客户端 | 技能目录 | 主文件 |
|---|---|---|
| DSH / 通用 agent | `~/.agents/skills/<技能名>/` | `SKILL.md` |
| Claude Code | `~/.claude/skills/<技能名>/` | `skill.md`（小写）|

```powershell
# 例：装到通用 agent 技能根（Windows）
Copy-Item -Recurse -Force "D:\path\to\SKILLS\calvin-db-mcp" "$env:USERPROFILE\.agents\skills\calvin-db-mcp"

# 例：装到 Claude Code 技能根（注意该目录约定主文件名为 skill.md）
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills\calvin-db-mcp" | Out-Null
Copy-Item -Recurse -Force "D:\path\to\SKILLS\calvin-db-mcp\*" "$env:USERPROFILE\.claude\skills\calvin-db-mcp"
Rename-Item "$env:USERPROFILE\.claude\skills\calvin-db-mcp\SKILL.md" "skill.md"
```

验证：

```powershell
Get-ChildItem "$env:USERPROFILE\.agents\skills\calvin-db-mcp" | Select-Object Name
Get-Content   "$env:USERPROFILE\.agents\skills\calvin-db-mcp\SKILL.md" -TotalCount 4   # 应看到 name/description front-matter
```

> 技能是否被识别，取决于客户端重启后能否在技能列表里看到 `calvin-db-mcp`。
> 技能层只是「说明书」；真正连库的是第 4 步注册的 MCP 服务器。

### 3.2 第 2 步：安装依赖

进入技能目录运行安装器（推荐）。它按序执行：Node 版本检查 → 装依赖 → 配置检查 → 自检 → 注册。

```powershell
cd "$env:USERPROFILE\.agents\skills\calvin-db-mcp"
```

```text
== 步骤 2：运行时依赖（缺失时自动 npm ci --omit=dev） ==

added 26 packages in 2s
  ✓ 依赖自动安装完成（26 个纯生产包）
```

若自动安装失败（离线/内网），手工安装：


### 3.3 第 3 步：初始化连接配置

**必须先有配置再注册**，否则客户端连上后所有工具只会回 `init_required`。二选一：

**方式 A（推荐）：从 DBeaver 导出文件导入**

1. 在源机 DBeaver 里确认各连接已勾选「保存密码」；
2. DBeaver → 菜单 **文件 → 导出 → 项目**，勾选所需数据源与「包含连接凭据」，导出得到如 `保险-20260929.dbp`；
3. 导入：

```powershell
cd "$env:USERPROFILE\.agents\skills\calvin-db-mcp"
node install.mjs "C:\Users\<you>\Documents\保险-20260929.dbp"
# 需要写能力时（默认两者都是关闭的）
node install.mjs "C:\Users\<you>\Documents\保险-20260929.dbp" --allow-writes --allow-create-table
```

成功时输出形如：

```text
[import] 发现 DBeaver 项目数据: 1 处
[import] MySQL/PG 连接: 41 个；跳过其他类型: 某连接 (oracle)

== 连通性预检 ==
✓ 可达  10.1.2.3:3306
✗ 不可达(需VPN/白名单)  10.9.9.9:3306

[import] ✅ 已生成 <技能目录>\mcp\dbmcp.config.json
[import] 共 41 个源（url 已加密为 enc 字段）。重启 MCP server 后用 list_sources 查看。
```

导入器还会在 `mcp/` 下写 `.gitignore` 保护该配置，**已存在时只追加条目、不覆盖原有内容**。

**方式 B：手工写配置**（连接很少时）

先写明文 `url`，再用配套工具加密：

```powershell
cd "$env:USERPROFILE\.agents\skills\calvin-db-mcp\mcp"
# 1) 编辑 dbmcp.config.json，sources 里填明文 url
# 2) 加密（把 url 换成 enc，文件内不再有明文）
node crypt-cli.mjs encrypt
node crypt-cli.mjs decrypt    # 需要临时看明文时用，看完记得重新 encrypt
```

### 3.4 第 4 步：注册 MCP 服务器

注册目标是 **`mcp/server.mjs` 的绝对路径**：

```json
{ "mcpServers": { "db": { "command": "node", "args": ["<技能目录>\\mcp\\server.mjs"] } } }
```

| 客户端 | 配置文件 | 备注 |
|---|---|---|
| Claude Code | `~/.claude.json` | 有 `claude` CLI 时优先用命令行：`claude mcp add db -s user -- node "<技能目录>\mcp\server.mjs"` |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | 该目录不存在说明未安装此客户端 |
| Cursor | `~/.cursor/mcp.json` | 同上 |
| 项目级 | 工作区根 `.mcp.json` | 只对该项目生效 |

配置就绪后，`node install.mjs` 会**自动完成注册**（写文件前先备份为 `<原文件>.bak-calvin-db-mcp`），并刷新 `mcp-register.example.json`；也可直接照该文件手工粘贴。

注册后**必须重启客户端**才生效（Claude Desktop / Cursor 需完全退出再启动）。

### 3.5 第 5 步：验收

**① 安装器总判定**：

```text

INSTALL_STATUS=OK INIT=yes REG=auto PASS=277 FAIL=0
```

**② 重跑安装器**（初始化后转为执行完整自检，且不会改动你的配置）：

```powershell

```

**③ 通过客户端实际调用**（重启客户端后）——按顺序让大模型调用：

| 调用 | 期望 |
|---|---|

| `sample_data`（`order_by: "id DESC"`）| 返回真实数据行 |

## 四、安装成功的判定标准

| 判定点 | 通过标准 | 不通过看 |
|---|---|---|
| 依赖 | `mcp/node_modules/` 下存在 `mysql2`、`pg` | §7.1 |
| 配置 | `mcp/dbmcp.config.json` 存在，含 `enc` 字段且**无明文 url** | §7.2 |
| 自测 | `FAIL=0`（已初始化 `PASS=277`；未初始化 `PASS=263`）| §7.5 |
| 注册 | 客户端出现 `db` 服务器且能列出工具 | §7.4 |
| 连通 | 至少一个源可达并能查询 | §7.3 |

### 自测的三种口径（都是「成功」，别被数字吓到）

| 场景 | 汇总行 | 说明 |
|---|---|---|
| 未初始化（纯净包直接跑） | `263 passed, 0 failed` | leak-guard 口令套件整体 SKIP（没配置就没有秘密可测）|
| 已导入配置、所有源可达 | `277 passed, 0 failed` | 正常态 |
| 已导入配置、部分源不可达 | `277 passed, 0 failed` | oceanbase / 特定源用例打印 `SKIP`（计入通过）|

自测是**跨配置可移植**的：若你的配置里没有口令、没有 TEST 环境源、或没有某个特定源，相应用例会打印 `SKIP` 而**不是 FAIL**。

## 五、配置管理（`mcp/dbmcp.config.json`）

```json
{
  "maxRows": 200,            // 单次查询返回行数上限（SELECT/WITH 统一外层包 LIMIT）
  "timeoutMs": 30000,        // 连接/语句超时
  "allowWrites": false,      // 是否允许 execute 写操作（默认 false）
  "allowCreateTable": false, // 是否允许 create_table 建表（默认 false）
  "maxAffectedRows": 500,    // execute 前按同一 WHERE 预检命中行数，超过即拒绝；0 = 关闭预检
  "sources": {
    "mysql_xxx": { "type": "mysql", "enc": "<加密串>", "env": "TEST", "description": "可选说明" }
  }
}
```

| 字段 | 说明 |
|---|---|
| `maxRows` | 单次查询上限（默认 200）。客户端还可用 `max_rows` 参数按次调整（上限 5000）|
| `timeoutMs` | 连接与语句超时（默认 30s）。**源主机不可达时会占满这个时间**，属正常等待 |
| `allowWrites` | 放开 `execute`（INSERT/UPDATE/DELETE）。**安全红线仍强制生效，无覆盖开关** |
| `allowCreateTable` | 放开 `create_table`（仅单条 CREATE TABLE）|
| `maxAffectedRows` | 写操作影响行数预检上限（默认 500）。批量变更超限会被拒并回报实际行数 |

**加解密命令**：

```powershell
cd "$env:USERPROFILE\.agents\skills\calvin-db-mcp\mcp"
node crypt-cli.mjs encrypt     # 明文 url → enc
node crypt-cli.mjs decrypt     # enc → 明文 url（临时查看用）
```

**凭据保护三件套**（默认开启，无需配置）：落盘加密（`enc` 字段）、输出清洗（工具响应中的口令一律替换为 `***`）、
git 启动门禁（配置文件被 git 跟踪或未被 ignore 时**拒绝启动**）。

### 5.2 环境变量（MCP 服务进程的环境，非 shell 环境）

环境变量要写在**客户端注册 JSON 的 `"env"` 块**里（由客户端在启动 server 进程时注入），或写进系统环境变量后重启客户端；写在普通终端里对已注册的 MCP 服务**不生效**。

| 变量 | 作用 | 未设置时 |
|---|---|---|
| `DBMCP_CONFIG` | 指向其他配置文件路径 | 用 `mcp/dbmcp.config.json` |
| `DBMCP_EXPORT_DIR` | `export_data` 落盘白名单目录（必须）；`import_data` 的回退读取目录 | export_data 拒绝执行 |
| `DBMCP_IMPORT_DIR` | `import_data` 读取导入文件的白名单目录 | 回退 `DBMCP_EXPORT_DIR`；两者都无则拒绝 |
| `DBMCP_MASTER_KEY` | enc2 主密钥（≥8 字符）：设置后新写入/`crypt-cli rekey` 的密文为 AES-256-GCM 主密钥绑定格式（认证防篡改） | 沿用旧格式（AES-128-CBC 落盘混淆）|
| `DBMCP_PRETTY` | `=1` 时响应恢复缩进 JSON | 紧凑 JSON |
| `DBMCP_MAX_CELL_CHARS` | 超长单元格截断阈值 | 2000 |
| `DBMCP_SLOW_MS` | 慢查询日志阈值（毫秒）：超过即向 stderr 打一行 source/耗时/语句类型/截断预览（SQL 过输出清洗）；`0` 关闭 | 2000 |
| `DBMCP_NO_LISTEN` | `=1` 时不启动 TCP 监听（纯 stdio） | 按默认行为 |

注册 JSON 写法示例（`"env"` 块与 `command`/`args` 平级）：

```json
{
  "mcpServers": {
    "db": {
      "command": "node",
      "args": ["<技能目录>\\mcp\\server.mjs"],
      "env": {
        "DBMCP_EXPORT_DIR": "D:\\exports",
        "DBMCP_IMPORT_DIR": "D:\\imports"
      }
    }
  }
}
```

> Windows 路径在 JSON 里反斜杠要写双份（`\\`），或直接用正斜杠（`D:/exports`）。

## 六、安全机制（简要）

| 机制 | 行为 |
|---|---|
| 只读守卫 | 仅允许 SELECT/WITH/SHOW/DESC/EXPLAIN；可写 CTE、`INTO OUTFILE`、行锁、`pg_read_file`/`pg_ls_dir`/`dblink` 等全部拦截 |
| 单语句 | 出现第二条语句即拒绝 |
| 自动 LIMIT | SELECT/WITH 统一外层包裹 `LIMIT maxRows+1`，返回 `truncated` 标记 |
| 写入红线 | **无 WHERE 的 UPDATE/DELETE、TRUNCATE、恒真 WHERE（`WHERE 1`、`2>1`、`true=true` 等）一律拒绝**；WHERE 必须引用真实列 |
| 影响行数预检 | 写操作前用同一 WHERE 先 `COUNT(*)`，超 `maxAffectedRows` 即拒绝并回报行数 |
| 输出整形 | 默认紧凑 JSON；超长单元格截断并标注，避免单个 TEXT 列吃满上下文 |

> 详细红线与使用规范见 `SKILL.md`；实现层说明见 `README.md`。
> 注意：MCP 层不是最终权限边界 —— 请给数据库账号最小权限（只读场景用 SELECT-only 账号）。

### 7.1 依赖相关

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot find package 'mysql2'` | 未安装依赖 | `cd mcp && npm ci --omit=dev`，或重跑 `node install.mjs` |

### 7.2 配置与凭据相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 工具返回 `init_required` | 尚未导入配置 | 按 §3.3 导入后重启客户端 |

### 7.3 连通性相关

| 现象 | 原因 | 处理 |
|---|---|---|
| `ECONNREFUSED` | 端口不通/服务未监听 | 确认主机端口；检查是否需 VPN |
| `ETIMEDOUT`（恰好等满 `timeoutMs`）| 主机不可达或被防火墙静默丢弃 | 连 VPN / 加 IP 白名单；先用 `find_database` 的 `probe: true` 探测 |

### V1.0.3（2026-10，守卫方言感知：两族掩码绕过修复）

| 类别 | 变更 |
|---|---|
| 🔴 守卫-注释族 | MySQL 注释语义：`--` 后必须跟 ASCII 空白/控制字符才是注释（`SELECT 1--1 INTO OUTFILE` 中 `1--1` 实为 `1-(-1)`，旧版把 `INTO OUTFILE` 当注释抹掉而放行）；JS `\s` 覆盖 NBSP/全角空格会重新"多抹"，改按 `[\x00-\x20\x7f]` 判定；可执行注释（`/*!`/`/*M!` 开头）是代码，一律拒绝；`#` 仅 MySQL 是注释 |
| 🔴 守卫-字符串族 | PG 反斜杠语义：`standard_conforming_strings=on` 下普通 `'…'` 内反斜杠是字面量，字符串比 MySQL 转义早一个引号结束——`'a\'; DROP TABLE t -- '` 的 `; DROP` 被旧版误判在字符串内而放行。现仅 `E'…'`/`U&'…'` 内反斜杠作转义；`"…"` 标识符不再按反斜杠转义 |
| 🔴 驱动层 | PG 分支强制 `queryMode: "extended"` 扩展协议（单语句）：旧版 `values` 为空数组时 pg 走简单查询协议，多语句可真实执行；MySQL 侧 `multipleStatements: false` 兜底不变 |
| 🔴 count_rows | 拼装后的语句补过只读守卫：`where` 塞 `FOR UPDATE`/`LOCK IN SHARE MODE` 会拿行锁阻塞写事务；COUNT 构造抽成纯函数 `countSql` |
| 🔴 create_table | 拒绝 CTAS（`AS SELECT` 写数据绕开 allowWrites）；执行改用原文（旧版执行脱敏文本，带 COMMENT/DEFAULT/反引号的 DDL 必然语法错误）；表名提取先抹注释 |
