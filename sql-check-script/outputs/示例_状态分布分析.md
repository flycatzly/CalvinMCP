# 示例：状态分布分析（模式 B 合格输出对照）
> 版本 v1.4.3 · sql-check-script · 更新记录见 README.md「更新记录」

演示模式 B「自然语言问题 → 只读 SQL → 先审后执行 → 结果解读」的完整落地。数值为示例，真实值由 calvin-db-mcp 实测填入。

## 用户输入

> 回归测试后，核对 orders 表各订单状态的数量分布，看有没有异常堆积。

## Step 1 确认目标

分析 `orders` 表 `status` 字段的状态分布（各状态数量 + 占比），排查回归后是否有异常堆积。口径：全量订单，不限时间范围。

## Step 2 获取真实 schema

`describe_table(source=mysql_order, table=orders)` 实测：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| order_no | varchar | 订单号 |
| status | varchar | 待支付 / 已支付 / 已发货 / 已完成 / 已取消 |
| created_at | datetime | 创建时间 |

> 字段来源已确认，禁止凭记忆编字段（防幻觉 SQL）。

## Step 3 写 SQL

命中 `references/分析模板库.md` 第 1 节「状态分布」模板：

```sql
-- 统计各订单状态的数量，排查回归后是否有异常堆积
-- 字段取自 describe_table(orders)
SELECT
    status AS 订单状态,
    COUNT(*) AS 订单数,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS 占比_百分比
FROM orders
GROUP BY status
ORDER BY 订单数 DESC;
```

## Step 4 安全自检（五问）

| # | 检查项 | 结果 |
|---|--------|------|
| 1 | 只有 SELECT/WITH，无写关键字 | ✅ 纯 SELECT |
| 2 | 表 / 库在白名单内 | ✅ orders ∈ allowed_tables |
| 3 | 敏感字段已脱敏或排除 | ✅ 本查询未涉及敏感列 |
| 4 | 预计行数 > 5000 先 COUNT | ✅ GROUP BY 聚合，结果仅数行 |
| 5 | 涉及 PRE/UAT 需二次确认 | ✅ 测试库 |

### 2. 这条 SQL 在干什么

### 3. 执行结果

| 订单状态 | 订单数 | 占比_百分比 |
|----------|--------|-------------|
| 已取消 | 5,210 | 42.0 |

### 4. 数据解读与异常提示

- **正常**：`待支付` 占比低（1.0%），符合预期
- **异常**：`已取消` 占比 **42.0%**，高于上版本基线 18%（+24pt）→ 疑似取消/退款流程回归异常，存在资损风险
- **建议**：① 排查取消流程改动与是否有批量误取消 ② 对照 `pay_flow` 做一致性比对（见 `sql_incident_patterns.md`）
- **风险等级**：P0（业务状态异常 + 潜在资损，按 `风险等级定义.md`）

### 5. 安全说明
只读 SELECT ✅ · 白名单表 ✅ · 无敏感字段 ✅
