# 示例：订单列表慢查询（证据版对照模板）
> 版本 v1.4.3 · sql-check-script · 更新记录见 README.md「更新记录」

演示「全链路 + calvin-db-mcp 取证」的合格输出。下表中的 EXPLAIN / count_rows 数值为示例（真实值由 MCP 实测填入）；「无 MCP 时」退化为静态分析的兜底写法见文末。

## 输入契约

```yaml
mode: check
project_path: D:\proj\order-service
datasource: order_db
environment: production
source: mysql_order   # find_database 定位后填

sql: SELECT * FROM order_info WHERE status = 1 ORDER BY create_time DESC LIMIT 100000, 20;
tables: [order_info]
business_scene: 订单列表查询
api_name: GET /api/orders
symptom: 列表加载慢，偶发超时
```

## Step 0 取证（calvin-db-mcp 实测）

- `describe_table(order_info)`：无 `(status, create_time)` 联合索引；仅主键 `id`
- `EXPLAIN`：`type=ALL, key=NULL, rows=5,230,000, Extra=Using where; Using filesort`
- `count_rows`：总行数 5,230,000；`status=1` 占 4,184,000（≈80%，区分度低）
- `sample_data`：create_time 存在 NULL / 异常未来时间 若干样例

## 输出（严格按 8 小节）

### 1. SQL 风险识别
- ✅ `select *`（返回字段过多）
- ✅ 深分页 `limit 100000, 20`
- ⚠️ `status` 区分度低（实测 status=1 占 80%）
- ⚠️ `order by create_time` 触发 filesort（EXPLAIN Extra）

### 2. where 条件分析
- 有 `where status=1`，但实测区分度低（80%），过滤后仍有 418 万行，无法有效缩小扫描范围
- 无函数 / 隐式转换 / or / 前缀模糊

### 3. 索引判断（基于真实索引）
- describe_table 显示无 `(status, create_time)` 联合索引 → **未命中**，导致 where 后仍需 filesort

### 4. 慢查询判断
- EXPLAIN `rows=5,230,000` 全表扫描 + 深分页丢弃前 10 万行，扫描行数风险高
- `select *` 返回字段过多

### 5. join 风险
- 不适用（单表查询）

### 6. order by 风险
- EXPLAIN `Extra=Using filesort`，排序前数据量约 418 万行，排序成本高

### 7. 性能风险输出（附证据）

| 风险类型 | 风险原因 | 影响范围 | 可能表现 | 验证方式（证据） | 等级 |
|---|---|---|---|---|---|
| 全表扫描 | status 区分度低且无联合索引 | GET /api/orders | 响应慢、CPU 升高 | EXPLAIN type=ALL, key=NULL, rows=5,230,000 | P1 |
| filesort | order by 未走索引 | 订单列表模块 | 大结果集排序耗时 | EXPLAIN Extra=Using filesort | P2 |
| 深分页 | limit 100000,20 扫描并丢弃大量行 | GET /api/orders | 翻页越深越慢 | EXPLAIN + 慢查询日志 | P1 |
| 返回字段过多 | select * | 接口带宽/内存 | 传输慢 | 对比精简字段前后耗时 | P2 |

### 8. 优化建议（含 EXPLAIN 验证）
1. **加联合索引** `(status, create_time)`：改后 EXPLAIN 预期 `type=ref, key=idx_status_create_time`，Extra 无 filesort
2. **深分页改游标分页**：`WHERE create_time < ? ORDER BY create_time DESC LIMIT 20` 替代 limit 100000,20
3. **字段精简**：`select *` → 明确字段列表
4. **加时间范围过滤**：查询条件加 create_time 范围，减少排序/扫描数据量

## 无 MCP 时的兜底写法

若 calvin-db-mcp 未初始化 / 表不存在：以上「实测」字段改为「待补充信息」清单（表结构 / EXPLAIN / 区分度统计），所有结论标注「待验证」，禁止写成确定结论。
