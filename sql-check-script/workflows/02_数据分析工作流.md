# 只读数据分析工作流（模式 B）
> 版本 v1.4.2 · sql-check-script · 更新记录见 README.md「更新记录」

自然语言问题 → 只读 SQL → 先审后执行 → 结果解读。六步，禁止跳步。

## 执行前加载

- `references/白名单与脱敏配置.yaml`（库表白名单 + 脱敏规则）
- `references/分析模板库.md`（优先复用现成模板）
- `references/calvin-db-mcp工具映射.md`（MCP 调用规范）

## Step 1 确认目标

复述用户问题：分析哪张表、看什么指标、什么时间范围/口径。含糊不清先追问，不猜。

**追问清单**（缺哪项问哪项）：

1. 目标表 / 库是哪个？
2. 要看的指标（数量 / 占比 / 趋势 / 异常）？
3. 时间范围与口径（含不含取消、是否去重）？
4. 对比基准（上版本 / 上一周期 / 期望值）？
5. 输出形态（表格 / 报告 / 导出）？

## Step 2 获取真实 schema

用 `describe_table` 取目标表真实字段/类型/注释。禁止凭记忆写字段（防幻觉 SQL）。

> 缓存：同一会话内表结构不变时复用已取 schema，不重复查；表结构有变更（用户告知）时重新取。

## Step 3 写 SQL

- 只读 SELECT / WITH
- 带中文注释，说明每段逻辑
- 字段用业务名别名（如 `AS 订单状态`、`AS 订单数`）
- 字段来源写进注释（`-- 字段取自 describe_table(orders)`）
- 先查 `分析模板库.md`，命中模板直接套用

## Step 4 安全自检（五问，全部通过才继续）

1. 只有 SELECT/WITH？无任何写关键字？
2. 表在白名单（allowed_tables）内？库在白名单（allowed_databases）内？
3. 敏感字段已脱敏或排除？
4. 预计行数 > 5000 是否先 COUNT 再抽样？
5. 是否涉及 PRE/UAT 环境（需二次确认）？

任一不过 → 停下说明原因，改完再走。

## Step 5 展示给用户（先审后执行，强制）

输出：SQL + 一句话解释「它在干什么」。**等用户明确确认后才执行。**

- 用户说「执行/可以/跑」→ 进入 Step 6
- 用户改需求 → 回到 Step 1
- 用户不回复 → 不执行，等待

## Step 6 执行与解读

- 用 `query` 执行（只读，自动 LIMIT；大表已按 Step 4 先 COUNT）
- 结果整理成表格
- 点出异常：占比突变、空值、重复、超范围值、环比异常
- 对照业务给结论（如「已取消占比 42%，明显高于上版本 18%，建议排查取消/退款流程」）

## 失败处理

- init_required / 表不存在 / 权限拒绝 → 报告原因，不猜数据
- 输出按 `outputs/分析报告模板.md`
