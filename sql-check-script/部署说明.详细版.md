## 一、这个包是什么

- **双模式 Skill**：模式 A SQL 全链路质量检测 / 模式 B 只读数据分析（`SKILL.md` 为入口，双层写库护栏内置）
- **随包自验收**：`tests\fullchain_test.mjs` 全链路 E2E（核心 46 项）+ `tests\run_all.mjs` 一键合并裁决
- **依赖本地 MCP `calvin-db-mcp` v1.6.2**（16 工具，MySQL/PostgreSQL/OceanBase(MySQL模式)/SQLite）——两个包同级放置时，验收与 E2E 自动发现，无需配置路径

### 纯净包（分发包）里没有的东西

| 剔除项 | 说明 |
|--------|------|
| `node_modules` | 本包零 npm 依赖，本来就不需要；MCP 侧依赖由命令生成（见 3.2） |
| 任何 `.` 前缀文件/目录 | `.git`/`.gitignore`/`.zcode` 等一律不随包；`.gitignore` 等由 `calvin-db-mcp` 装机导入 `.dbp` 时自动生成 |
| 开发机路径/临时产物 | 文档与脚本不含开发机绝对路径；`*.log`/`*.tmp`/`thumbs.db` 不随包 |
| 凭据 | 本包从不持有凭据；连接凭据走 `calvin-db-mcp` 的 `.dbp` 导入（`*.dbp`/`dbmcp.config.json` 按敏感文件对待，绝不随包） |

## 二、环境要求

- **Node.js ≥ 18.17**（跑 MCP、E2E 与验收；SQLite 工具需 Node ≥ 22.5 内置 `node:sqlite`）
- **MCP 客户端**：Claude Code / Claude Desktop / Cursor 等支持 MCP 的客户端
- **目标库账号**：SELECT-only 最小权限账号（红线要求，技能不代管凭据）
- **网络**：仅 `calvin-db-mcp` 首次生成依赖时需可访问 npm 源（内网加 `--registry` 镜像）；本技能包全程免联网
- Windows / Linux / macOS 均可；本文命令以 Windows PowerShell 为例

## 三、从纯净包开始部署（3 步）

### 3.1 第 1 步：放置技能

```powershell
Copy-Item -Recurse -Force "<解压目录>\sql-check-script" "$env:USERPROFILE\.agents\skills\sql-check-script"
```

- 目录名保持 `sql-check-script`，入口文件为 `SKILL.md`（大小写敏感的客户端勿改名）
- **与 `calvin-db-mcp` 的相对布局**：发布目录下两包同级（`<发布版本>\sql-check-script` + `<发布版本>\calvin-db-mcp`）时，`run_all.mjs`/`fullchain_test.mjs`/`install.mjs` 三者互相自动发现；分散部署时用 `DBMCP_MCP_DIR` / `DBMCP_E2E` 显式指路径

### 3.2 第 2 步：部署并初始化 calvin-db-mcp（依赖由命令生成）

```powershell
cd <解压目录>\calvin-db-mcp
node install.mjs "C:\path\to\your.dbp"
```

`install.mjs` 一条命令自动完成六步：

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1 | Node 版本检查 | ≥ 18.17 |
| 2 | **安装依赖**：`npm ci --omit=dev` 生成 `mcp\node_modules`（纯净包不随包依赖，首次需可访问 npm 源） | `mysql2` + `pg` |
| 3 | 配置初始化：导入 `.dbp` 生成加密 `dbmcp.config.json` | 连接源就绪 |
| 4 | `selftest` 自检 | 277 项断言（导入后口径） |
| 5 | **全链路 E2E 验收**：自动发现同级 `sql-check-script\tests\fullchain_test.mjs`（或 `DBMCP_E2E` 指定），剥离 `FULLCHAIN_*` live 门控防部署机误判 | 46 项核心 |
| 6 | 注册到 MCP 客户端 | `db` 服务器生效 |

手动兜底（只有自动失败时才需要）：`calvin-db-mcp\mcp` 下 `npm ci --omit=dev`，再 `node selftest.mjs`。MCP 侧细节（配置管理/加密/故障排查）见 `calvin-db-mcp\部署说明.详细版.md`。

### 3.3 第 3 步：重启 MCP 客户端

使 `db` 服务器与本技能生效。验证入口：客户端技能列表应出现 `sql-check-script`，工具列表出现 `list_sources` 等 16 个 `db` 工具。

## 四、验收（怎么算装好了）

| 检查 | 通过标准 |
|------|----------|
| 技能被发现 | 客户端技能列表出现 `sql-check-script` |
| MCP 已注册 | 工具列表出现 `db` 的 16 个工具 |
| MCP 已初始化 | `list_sources` 返回源列表（非 `init_required`） |
| 依赖自检 | `node mcp\selftest.mjs` → `0 failed` |
| 全链路 E2E | `node tests\fullchain_test.mjs` → `55 passed, 0 failed`（46 核心 + 9 live-MySQL 可选段） |
| 一键验收 | `node tests\run_all.mjs` → 末行 `RUN_ALL selftest=…/0 e2e=…/0 … => OK` |
| 部署即验证 | `install.mjs` 步骤 5 自动跑核心 E2E |

### 自测的三种口径（都是「成功」，别被数字吓到）

| 口径 | selftest | 场景 |
|------|----------|------|
| 未初始化 | 263 passed | 纯净包刚拷贝、未导 `.dbp`（发布包自验收即此口径） |
| 导入后 | 277 passed | `install.mjs` 导入 `.dbp` 之后 |
| live 段 | +9（MySQL）/PG 段 | `FULLCHAIN_MYSQL=1` / `FULLCHAIN_PG=1` 门控，需目标环境配好真实源 |

**验收线是 0 failed，不是 passed 数**（用例数随版本/源连通性增长）。`run_all` 输出解读示例：

```
RUN_ALL selftest=263/0 e2e=46/0 gates=core => OK
        └─未初始化口径    └─核心段      └─合并裁决
```

live 段纪律：严格只读（information_schema/EXPLAIN 取证类语句）；PRE/UAT 取证前**二次确认环境**；建议 FULLCHAIN_MYSQL_SRC / FULLCHAIN_PG_SRC 显式指定 source id，不靠默认猜源。

## 五、护栏配置与安全红线

- 护栏配置：`references\白名单与脱敏配置.yaml`（库表白名单、敏感字段脱敏/排除规则、输出上限）
- 配置生效范围：模式 A/B 均生效；技能层拒写 + MCP 守卫拒写为**双层**，即使用户明确要求写库也拒绝，并输出核对清单/人工 SQL 供 DBA 执行
- 安全红线全文（部署即生效，不可关闭）：

  仅只读（SELECT/WITH/SHOW/DESCRIBE/EXPLAIN）；永不执行 INSERT/UPDATE/DELETE/DROP/TRUNCATE/ALTER（技能与 MCP 双层拒绝，即使用户要求）；`execute`/`create_table`/`import_data` 一律禁用；不碰生产库；仅白名单库表；敏感字段（手机号/身份证/邮箱）脱敏或排除（A/B 模式均生效）；任何 SQL 先展示用户确认再执行；结果预计 >5000 行先 COUNT 再抽样；防幻觉 SQL（先 `describe_table` 取真实 schema）；PRE/UAT 取证前二次确认环境；最小权限 SELECT-only 账号；无证据输出「待补充/待验证」禁止猜根因。

## 七、问题排查

| 现象 | 原因 | 动作 |
|------|------|------|
| 客户端技能列表没有本技能 | 目录放错/入口文件名被改/未重启 | 核对 `SKILL.md` 位置与目录名，重启客户端 |
| 工具列表没有 `db` 工具 | MCP 未注册或未重启 | 重跑 `calvin-db-mcp` 的 `install.mjs`（步骤 6 注册）后重启 |
| `list_sources` 返回 `init_required` | 未导 `.dbp` | `node install.mjs <你的.dbp>` |
| `run_all` → `FAIL` 且 selftest 非 0 failed | 依赖/环境问题 | 先 `calvin-db-mcp\mcp` 下 `npm ci --omit=dev` 再复跑；仍失败看 selftest 输出 |
| `run_all` → `FAIL` 且 e2e 非 0 failed | 链路/fixture 问题 | 确认同级 `calvin-db-mcp\mcp` 存在且 `demo.db` 在 `calvin-db-mcp\` 下（fixture 自供给）；看 E2E FAIL 段 |
| E2E 整段 SKIP（0 passed, 0 failed） | demo fixture 双缺（配置无 demo 源且无 `demo.db`） | 保留同级 `calvin-db-mcp\demo.db` 即可 |
| `node tests\run_all.mjs` 报「未找到 selftest」 | `DBMCP_MCP_DIR`/同级布局未指向真实 `mcp` 目录 | `node tests\run_all.mjs <mcp目录>` 显式传参 |

现象级问题（慢查询/深分页/锁等待等分析场景）见 `references\故障处理.md`；SQL 风险判定见 `references\风险等级定义.md`。

## 八、升级与版本纪律

**升级**：新包覆盖拷贝到技能目录（先删旧目录再拷，避免旧文件残留）→ `calvin-db-mcp` 侧按其部署说明升级 → 重启客户端 → `node tests\run_all.mjs` 全绿即完成。

**版本纪律**（见 README「版本与文档同步规范」）：每次更新版本（含版本说明）必须同步落到全部对应文档——版本标记行全量对齐、版本说明唯一落点 README「更新记录」、`calvin-db-mcp` 依赖版本引用同步、`run_all` 全绿后才可发布/重打发布包，缺一处即视为发版未完成。

## 九、卸载与清理

1. 删除技能目录（`...\skills\sql-check-script`）
2. MCP 侧卸载/回滚见 `calvin-db-mcp\部署说明.详细版.md`「八、升级、卸载与回滚」（含客户端配置回滚 `.bak`）
3. 本包无运行期落盘产物，无需额外清理

## 发版门禁（发版者）

发版 = 跑 `node distribute.mjs --force`，收尾自动「一次性副本验收 + 终态哈希终查」（加固 H19，发版不可能忘）：

1. 纯净打包（逐文件哈希自校验 + 排除项泄漏检查）；
2. **一次性副本验收**：临时目录副本内**同级拷入 `calvin-db-mcp`**（`tests/run_all.mjs` 解析同级包）→
   `calvin-db-mcp\mcp` 下 `npm ci --omit=dev` → 跑 `tests\run_all.mjs`，验后整目录删除——交付树自始至终不进套件；
3. **终态哈希终查**：门禁前后交付树哈希逐位一致 + 纯净复扫。

验收退出码契约（统一诚实 SKIP 口径）：`exit 0` 全部通过 / `exit 1` 存在失败 / `exit 3` 诚实 SKIP
（`run_all` 汇总口径：`OK|SKIP|FAIL`，SKIP 明示记录判过、不冒充全绿）。门禁失败退出码 3、发布包不可交付。
`--gate-only` 只跑门禁不打包（源树口径：源树排除名单内残留——`.git` 等——记「已知排除项（不随包）」
不判红，交付纯净由 `--force` 打包自校验与纯净复扫保证）；`--no-gate` 显式跳过（留痕）。
凭据文件（`accounts.json`）在过滤名单机械兜底，一律不随包。
