# 故障处理手册（现象 → 原因 → 动作）
> 版本 v1.4.28 · sql-check-script · 更新记录见 README.md「更新记录」

遇到问题时先查这里，**不要猜**。

## 一、MCP 侧

| 现象 | 原因 | 动作 |
|------|------|------|
| `list_sources` 返回 `init_required` | 未导入 `.dbp` 配置 | 提示用户执行 `node install.mjs "<.dbp>"`；本次分析标「待补充」 |
| `ECONNREFUSED` / `ETIMEDOUT` | 主机不可达 | 连 VPN / 加 IP 白名单；用 `find_database(probe=true)` 先探测 |
| `Access denied for user` | 账号无该库权限 | 换最小权限账号；**不要**改用高权限账号 |
| 表不存在 | 表名拼错或不在该库 | 用 `list_tables(name_like="...")` 找正确表名 |
| EXPLAIN 语法错误 | 方言不符（PG / MySQL） | 按 `calvin-db-mcp工具映射.md` §方言适配 改写 |
| 查询超时 | 大表无过滤 | 先 `count_rows` 估量，再加时间范围/条件 |
| 结果被截断 | 单元格过长 / 行数超 `maxRows` | 设计行为；确需更多行调 `max_rows` 参数 |

## 二、业务侧

| 现象 | 动作 |
|------|------|
| 表不在白名单 | 拒绝执行，请用户确认是否加入 `allowed_tables` |
| 命中敏感字段 | 按 `分析模板库.md` §7 写脱敏 SQL；无法脱敏则排除该列 |
| 用户要求写操作 | 一律拒绝，说明本 Skill 只读；引导由 DBA 通过其他渠道执行 |
| 用户要求全表 UPDATE/DELETE | 拒绝（安全红线），引导 DBA 人工执行 |
| 用户未确认就催执行 | 不执行，等待明确确认 |
| 用户描述含糊 | 按 `02_数据分析工作流.md` Step 1 追问清单逐项确认 |

## 三、统一兜底（证据拿不到时）

输出「待补充信息」清单 + 结论标「待验证」，**禁止猜根因、禁止编造数据**。

## 四、calvin-db-mcp 安全红线（不可绕过）

- 无 WHERE 的 UPDATE / DELETE → 一律拒绝，即使用户明确要求
- TRUNCATE TABLE → 一律拒绝
- 不引用真实列的 WHERE（`1=1` / `true` / `2>1`）→ 拒绝
- DDL（DROP / ALTER / TRUNCATE）→ 拒绝；仅 `create_table` 在显式开启时可用（本 Skill 仍不使用）
- 写操作默认关闭；本 Skill **永不调用** `execute` / `create_table`

## 五、错误类矩阵实测表（按报错码反查）

> v1.4.11–v1.4.15 探针口径归档，v1.4.17 补 retry 全码实证（源码 + 真实 MCP 链路双确证），v1.4.21 真实库方言实证（MySQL 8.4.11 / PG 17.4 live 探针，报文引文见下方方言行）。工具返回报错完整形态为 `Error: [E_CODE:retry] 消息`（`isError: true`），正则捕获全码用 `/\[(E_[A-Z_]+):([a-z-]+)\]/`（只抓 `E_XXX` 会漏 retry 标记）。retry 三值域：`retryable`（同参重试可能成功）| `conditional`（改参数/范围后重试）| `no-retry`（同参重试必然失败）。下表「实测报文形态」为实测引文（可直接 pattern match）。数字上限语义注意：`limit`/`max_rows` 低于下限或非整数报 `E_PARAM` 拒绝，但**超 `maximum` 不报错、静默夹取**（如 51→50），比对行数以实际 `rows.length` 为准。

### 工具级错误码

| 错误码 | 触发条件 | 实测报文形态 | 重试语义 | 排障方向 |
|---|---|---|---|---|
| `E_PARAM` | 整数参数低于下限/非整数（0、1.5） | `[E_PARAM:no-retry] Invalid 'limit': must be >= 1, got 0.` / `[E_PARAM:no-retry] Invalid 'limit': expected an integer, got 1.5.`——超 `maximum` 则**静默夹取**不报错（实测 `sample_data limit=51` → `sql_executed: … LIMIT 50`） | 不重试，改参数 | 别把「没报错」当取到请求条数 |
| `E_PARAM` | 只读工具（query 等）首词非 SELECT/WITH/SHOW/DESCRIBE/EXPLAIN——**词法层先于驱动**，`SELEC 1` 拼错首词也走此处（v1.4.21：MySQL/PG live 实测同走词法层，方言无关） | `[E_PARAM:no-retry] Read-only tool: statement must start with SELECT / WITH / SHOW / DESCRIBE / EXPLAIN. Use the 'execute' tool for writes (only when enabled in config).` | 不重试 | 语法残缺若首词不合法先撞词法层；首词合法的残缺才落驱动（见 E_DB） |
| `E_PARAM` | 表名非法标识符——`import_data.table` 与 `create_table` DDL 表名**同口径**（v1.4.15 起） | `[E_PARAM:no-retry] Invalid identifier '<p>'. Pass plain names; use the schema parameter instead of qualified names.` | 不重试 | 表名改纯标识符（`_`/字母开头，Unicode 文字可）；限定名改传 `schema` 参数 |
| `E_PARAM` | export filename 清洗后为空（`..`、`.` 等） | `[E_PARAM:no-retry] Invalid export filename '<name>'（清洗后为空）。` | 不重试 | 换正常文件名 |
| `E_CONFIG` | 写操作在**关门**（`allowWrites` 未开）——先于安全红线报出 | `[E_CONFIG:no-retry] Writes are disabled. Set allowWrites=true in dbmcp.config.json (globally or on this source), then restart the MCP server. Prefer a least-privilege account.` | 不重试（开门属运维动作） | 关门写与红线拒是两层：关门=E_CONFIG；开门后红线拒=E_SAFETY |
| `E_SAFETY` | **开门后**无 WHERE 的 UPDATE/DELETE | `[E_SAFETY:no-retry] 安全红线：拒绝执行无 WHERE 条件的 UPDATE/DELETE（会导致全表数据被覆盖/清空）。…请补充 WHERE 条件后重试。` | 永不重试 | 即使用户要求也拒（双层拒绝）；引导 DBA 人工 |
| `E_SAFETY` | **开门后**恒真 WHERE（`1=1`/`true`/`2>1`） | `[E_SAFETY:no-retry] 安全红线：WHERE 子句为恒真条件（如 WHERE 1=1 / WHERE true），等同无条件的全表操作，拒绝执行。` | 永不重试 | 写真实业务条件 |
| `E_SAFETY` | CTAS 各变体——**安全检查先于表名校验**，`allowCreateTable` 开门也拒 | `[E_SAFETY:no-retry] Blocked: CREATE TABLE ... AS SELECT writes data; use the 'execute' tool (with allowWrites) instead.` | 永不重试 | 参数语义不越过安全语义；带危险关键字的非法表名也走此处 |
| `E_SAFETY` | 引号标识符**调用形态**撞黑名单（v1.4.28 收口，修复前为守卫旁路直达库）：`` `sleep`(5) ``、`"pg_sleep"(5)`、`U&"pg_sleep"(5)`、`pg_catalog."pg_sleep"(5)`、`` `mysql`.`sleep`(1) ``、注释隔开 `` `sleep`/*c*/(5) ``、复合 `("pg_sleep")(30)` 与裸名同拦；引号**列名引用**（闭引号后无左括号，如 `` `delete` ``）不误伤 | `[E_SAFETY:no-retry] Blocked by read-only guard: administrative/destructive function call 'pg_sleep(' is not allowed in reads.` / `[E_SAFETY:no-retry] Blocked by read-only guard: found 'LOAD_FILE' (quoted function name) outside string literals.`（where 片段通道同语义：`Blocked in WHERE: …`） | 永不重试 | 掩码曾把引号抹空致黑名单不可见（`sleep`/`benchmark` 真实执行、文件读/外联函数触达驱动层）；现按「闭引号后接左括号」判调用形态、按名复核黑名单；报文 `(quoted function name)` 标记可与裸名拦截形态区分 |
| `E_DB` | 语句级数据库错误——首词合法的语法残缺/未定义函数/列名错，驱动错误码透传 | `[E_DB:no-retry] no such column: FRM (ERR_SQLITE_ERROR)`（如 `SELECT FRM x`） | 不重试 | **这是 SQL/参数问题不是数据库故障**；按驱动报文改写 |
| `E_DB` | 表不存在——SQLite 驱动消息透传（`no such table` 不含 exists 类词，不走 E_NOT_FOUND；MySQL/PG 见下一行） | `[E_DB:no-retry] no such table: <t> (ERR_SQLITE_ERROR)` | 不重试 | **查表名拼写**（`list_tables(name_like)`），勿当数据库故障 |
| `E_NOT_FOUND` | 表不存在——**MySQL/PG 方言**（报文含 `doesn't/does not exist` 命中归类正则；v1.4.21 真实库探针实测收口） | `[E_NOT_FOUND:no-retry] Table 'sqlchk_test.no_such_table_xyz' doesn't exist (ER_NO_SUCH_TABLE)`（MySQL 8.4.11）/ `[E_NOT_FOUND:no-retry] relation "no_such_table_xyz" does not exist (42P01)`（PG 17.4） | 不重试 | **查表名拼写**（`list_tables(name_like)`），勿当数据库故障 |
| `E_DB` | 驱动码命中连接类瞬时错误：`ECONNREFUSED`/`ECONNRESET`/`ETIMEDOUT`/`EHOSTUNREACH`/`ENOTFOUND`/`PROTOCOL_CONNECTION_LOST`/`PROTOCOL_ENQUEUE_AFTER_FATAL_ERROR`/`57P03` | `[E_DB:retryable] connect ECONNREFUSED 127.0.0.1:1 (ECONNREFUSED)`（实测引文，驱动码括号后缀透传） | **retryable**：同参重试可能成功 | 网络/连接层瞬时故障；退避重试或查连通性 |
| `E_DB` | 批写入结果未知（超时/连接中断，安全中止、不自动回退） | `[E_DB:conditional] 批写入结果未知（超时/连接中断，安全中止、不自动回退）：…请用 count_rows 核对后人工决定…` | conditional | 可能**部分写入**：count_rows 核对后人工补插/回退 |
| `E_DB` | **查询/执行超时**（`timeoutMs` 上限，真实库 8s 门实测）——pg `query_timeout` 报文无驱动码、pg `statement_timeout` 码 `57014`、mysql2 码 `PROTOCOL_SEQUENCE_TIMEOUT`；此前按报文形态散落 `E_INTERNAL`/`E_DB:no-retry` 三口径，v1.4.25 起统一 conditional | `[E_DB:conditional] Query read timeout`（pg query_timeout 原文）/ `[E_DB:conditional] canceling statement due to statement timeout (57014)` | conditional | 读=查询太重，**缩小范围**（加 WHERE/时间窗，先 `count_rows` 估量——见「症状速查」查询超时行）；写=结果可能未知（mysql2 超时不撤服务端语句），`count_rows` 核对后再决定。**连接建立超时 `ETIMEDOUT` 不在此行**（瞬时连接错误，走上一行 `E_DB:retryable`） |
| `E_DB` | import 默认档中途失败（如 UNIQUE 冲突——import 纯 INSERT 不预清表） | `[E_DB:no-retry] 第 N 行导入失败，整批中止（此前 X 行已写入——如需清场请用 execute 按条件删除）` | 不重试 | **中止不回滚**：残留行按文案指引清场，勿假设「失败=没写入」 |
| `E_DB` | import `atomic: true` 档失败 | `[E_DB:no-retry] 原子导入失败，已全部回滚（未写入任何行）` | 不重试 | 已回滚（count 不变实证）；修数据后整体重导 |
| `E_LIMIT` | import 文件 >20MB（20971520 字节） | `[E_LIMIT:conditional] 文件 … 字节超过上限 20971520` | **conditional**：改小后重试 | 字节检查**先于**行数检查；拆文件 |
| `E_LIMIT` | import 数据行 >10000 | `[E_LIMIT:conditional]` 行数超限 | conditional | 拆批导入 |
| `E_LIMIT` | export 内容 >20MB | `[E_LIMIT:conditional] 组装期早停，未写盘` | conditional | **不落残片**（landed=false 实证）；缩小导出范围 |
| `E_NOT_FOUND` | 源不存在（Unknown source）/ import 文件不存在（或 filename 含路径成分被清洗拒绝） | `[E_NOT_FOUND:no-retry] Unknown source '<id>'. Available sources: …` / `[E_NOT_FOUND:no-retry] 导入文件不存在（或文件名被清洗拒绝）` | 不重试 | 核对源 id / 文件须在 `DBMCP_IMPORT_DIR` 内；`../` 一律拒。注意**表不存在分方言**：SQLite 走 E_DB（驱动透传）、MySQL/PG 走 E_NOT_FOUND（见上方方言行） |
| `E_CONFIG` | `allowCreateTable` 关闭时调 `create_table` | `[E_CONFIG:no-retry] 建表未启用：在 dbmcp.config.json 设置 "allowCreateTable": true（全局或该源）后重启 MCP。安全红线（无 WHERE 的 UPDATE/DELETE、TRUNCATE）不受此开关影响，始终生效。` | 不重试 | **gate-first**：先于表名校验与安全检查报出；开门需显式配置 |
| `E_INTERNAL` | 未归类兜底（fail-closed） | `[E_INTERNAL:no-retry]` + 原始消息 | 不重试 | 反馈报文原文，禁止猜根因 |

### 启动期拒启（加密配置面，非工具级报错）

配置 url 存密文字段 `enc`（`enc2:` = AES-256-GCM + scrypt，需 `DBMCP_MASTER_KEY` ≥8 字符）时，解密失败是**启动期 fail-fast 拒启**——工具侧无任何响应（不是工具返回报错），排障看服务端 stderr `source '<id>' 的 enc 解密失败: …`：

| 形态 | stderr 文案要点 | 说明 |
|---|---|---|
| 错主密钥 / 篡改密文 | 「DBMCP_MASTER_KEY 不匹配或密文被篡改」 | 两者**合并报**（GCM 认证不区分） |
| 无主密钥 | 「DBMCP_MASTER_KEY 未设置（或少于 8 字符）…」 | enc2 专属 |
| 密文长度不足/非法 | 「密文长度不足或非法（enc2）」 | 截断/非法密文 |
| 旧 `enc:` 格式 | （不拒启） | 向后兼容，无需主密钥 |

均 fail-closed 不落半解密数据。表现为「工具无响应/连不上」时先查服务端日志，不是查工具返回。

> 补充口径：① export filename 含 `../` 的另一形态是**清洗改名**（`../x.csv` → `.._x.csv`，不报错、仍落导出目录内），与 import 的拒绝不同，无错误码。② `init_required` / `ECONNREFUSED` / `Access denied` 等非 `E_` 码形态见「一、MCP 侧」现象表。
